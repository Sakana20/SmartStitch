# 通用项目素材匹配与成片命名方案（讨论稿）

## 1. 要解决的问题

现在的“命名设置”要求每换一个产品，填写产品、利益点，再确认素材文件名是否能被同一条正则解析。这个流程没有真正解决**素材与产品是否匹配**：即使文件名生成成功，成片也可能抽到另一个产品的画面。

本稿的目标是：优先从素材文件名提取一次可复用的业务信息，之后选择产品和利益点时，系统自动筛出可用素材，并从**本条成片实际使用的素材**生成文件名和飞书字段。更换产品时只需检查新命名格式和少数无法识别的条目，不必重新调整整套命名规则。简单模式用可拖拽卡片设置输出字段顺序。

本文只提出方案，不改变现有代码、NAS 素材或配置。

## 2. 当前实现与实测事实

| 环节 | 当前行为 | 造成的问题 |
| --- | --- | --- |
| 抽取素材 | `planner.py` 按素材库独立抽取所有启用且权重大于 0 的素材，没有产品或利益点过滤。 | 手填产品名不会限制镜头，可能“瑞幸”命名配“霸王茶姬”画面。 |
| 元数据提取 | `naming.py` 用一条 `fullmatch` 正则从命名范围内的视频文件名同时提取达人和限制日期。默认范围是全部视频库 `pool_*`。 | 数字名、普通描述名、不同切片来源都容易失败；图片库不参与提取。 |
| 预检 | 启用业务命名后，范围内任一可选视频不匹配即报错，整个生成任务受阻。 | 添加一个新产品素材，可能使旧产品任务也无法生成。 |
| 页面预览 | `app.js` 取每库第一条可用素材尝试解析，解析异常会被忽略，空值显示“达人名”“限制日期”。 | 预览不是计划中实际抽到的组合，也不能证明批次可生成。 |
| 输出与飞书 | 产品、利益点来自配置；达人、日期来自抽中的素材。飞书“文本/利益点/达人/限制日期”使用同一份计划命名结果。 | 配置字段和画面不一致时，文件名与飞书会一起写错。 |

对当前通用验证项目的只读抽样：`pool_1` 有 21 条，文件名包含瑞幸、霸王茶姬、蜜雪冰城等多个品牌；`pool_2/3/4` 分别有 38/37/30 条，其中纯数字文件名分别有 21/17/20 条。这些名字缺少稳定的产品、达人和日期字段。当前业务命名还处于关闭状态。单纯换一条更宽松的正则无法可靠识别这些素材。

## 3. 方案比较

| 方案 | 换产品的操作 | 正确性 | 代价 | 结论 |
| --- | --- | --- | --- | --- |
| 每个产品维护文件名正则 | 每次调整正则、重新预检 | 依赖命名习惯，无法识别 `1.mp4` | 开发少，长期维护高 | 不建议作为主方案 |
| 只靠文件名关键词猜产品 | 几乎不用设置 | 数字名无信息；品牌简称和别名易误判 | 初期低，误配处理高 | 不能直接当作已确认结果 |
| 素材显式标注业务元数据 | 新素材逐条标注 | 可追溯，可做严格过滤 | 一次性迁移和界面开发 | 适合作为例外处理 |
| **文件名解析模板 + 可视化卡片 + 例外确认 + 批次预检** | 新命名格式确认一次；换产品直接选产品 | 兼顾自动化与可控性 | 中等 | **推荐** |

“通用”应理解为统一的解析模板和匹配规则，而不是从任何随意命名的视频中凭空猜出产品、达人与日期。规则应按**文件名格式或素材库**维护一次，不按每个产品维护一套。文件名无信息或同时命中多个产品时，系统必须明确标为待处理。

## 4. 简单模式：解析文件名，再拖拽字段卡片

建议把现在的“产品/利益点输入框 + 文件名预览”改为两个相连的区域：

1. **从哪里取值**：选一个素材库和几条真实文件名样本。页面展示“原文件名 → 产品 / 利益点 / 达人 / 限制日期”的解析结果。用户可点选文件名中的一段并指定它代表哪个字段；系统由此形成可复用的解析模板，而不是要求用户手写正则。一个库有多种文件名格式时，可添加多张解析模板卡片并按优先级尝试。
2. **怎么组成成片名**：下方显示“产品”“利益点”“达人”“限制日期”“序号”卡片。拖动卡片决定输出顺序；每张卡片可选“显示/省略”和取值来源，例如“当前选择的产品”或“抽中素材的已解析字段”。分隔符在卡片之间统一设置，空值时自动移除多余分隔符。
3. **立即验证**：右侧不是固定示例，而是从当前素材中选出若干真实组合，展示解析覆盖率、每条成片的抽中素材、最终文件名及失败原因。拖动卡片后即时更新；保存前对所有可能入选的素材做预检。

卡片只决定**命名字段的顺序和来源**；素材是否能用于当前产品，仍由解析出的产品信息参与筛选，不能因为卡片被隐藏就放过产品错配。

示意：

```text
素材文件名：瑞幸咖啡-第二件半价-小王-2026-10-31.mp4
解析结果：  [产品:瑞幸咖啡] [利益点:第二件半价] [达人:小王] [日期:2026-10-31]
拖拽顺序：  [产品] → [利益点] → [达人] → [日期] → [序号]
输出预览：  瑞幸咖啡-第二件半价-小王-20261031-1.mp4
```

若素材叫 `1.mp4`，页面显示“文件名无法提供产品/利益点/达人/日期”，允许用户对这条或整批素材补充信息，或明确标为通用素材。系统不能把当前选择的产品反填进未识别素材，造成看似匹配的假象。

## 5. 解析规则与素材元数据

### 5.1 产品目录

为每个产品建立稳定 ID、显示名和别名。例如 `luckin` 对应“瑞幸咖啡”，别名可有“瑞幸”。输出文件名使用显示名，匹配使用稳定 ID。这样改显示名或文件名写法时不用重标素材。

利益点也使用稳定 ID 与显示名，例如 `second_half_price`、`one_cent`；不同产品可共用利益点定义。不能从 `0.1` 这类片段盲目推定利益点，需经确认。

### 5.2 解析模板与例外覆盖

解析模板至少记录：适用素材库、文件名样本、字段提取规则、优先级和版本。系统可根据分隔符、日期形态、产品别名等生成候选模板，但必须用库内全部可选素材验证覆盖率，并让用户确认。切片文件先还原源文件名前缀，再应用模板。

解析结果应写入可追溯的素材元数据缓存，记录来源为“文件名规则 / 人工覆盖 / 源视频继承”，并用文件指纹或路径加修改时间判断是否需要重新解析。规则变更后只重算受影响的素材和计划预览；输出计划一旦确定，应固定当时解析结果，不被后续重命名改变。

文件名没有信息、模板冲突或别名冲突时允许人工覆盖；覆盖优先级高于解析模板。在现有 `AssetItemConfig` 的 `tags` 之外新增结构化字段，避免用自由标签承载必须准确的业务信息。下面的结构仅是示例，实际字段需在实现时与现有配置兼容：

```yaml
items:
  - path: "瑞幸咖啡杨枝甘露.mp4"
    match:
      products: [luckin]
      benefits: []
      scope: specific        # specific / shared
      talent: null
      restriction_date: null
      status: confirmed      # 文件名规则通过预检，或人工确认
```

- `products`：允许使用该素材的产品 ID。一个素材可属于多个产品。
- `benefits`：该素材明确表达的利益点；空列表表示**不限定利益点**，不表示自动识别成功。
- `scope: shared`：人工确认对所有产品通用的镜头，例如确实没有品牌信息的转场。不能因文件名是数字就自动当成通用素材。
- `talent`、`restriction_date`：仅在业务需要时填写，日期存 ISO 格式；原视频切片继承原视频的已确认信息。
- `status`：记录解析结果是否通过规则预检或人工确认；有冲突的猜测不能直接参与严格匹配。

素材路径和已有 ID 可能随重命名变化，落地时需定义稳定的素材身份、重命名迁移与重复文件处理。人工覆盖应随配置备份、跨机器共享，不只放在本机缓存。现有 `tags` 和权重保持原义。

### 5.3 素材库规则

每个库声明角色和匹配要求，例如前贴可要求产品匹配，引子可允许共享素材，利益点库可同时要求产品与利益点匹配。规则设置在库上，素材例外设置在条目上，避免每个产品复制一套库。

不同内容风险不同：包含可辨认品牌、商品或价格的库，默认禁止“未标注素材”进入候选；已确认通用镜头可进入任何产品。图片库采用同一套匹配规则。

## 6. 一次选择产品后的完整流程

1. 用户在项目中选择产品和利益点，系统读取对应稳定 ID。产品显示名只是输出名称，不直接用于模糊匹配。
2. 扫描素材时先按已确认的模板解析文件名，再应用人工覆盖和切片源文件继承结果。新格式、冲突项和纯数字文件名标为“未识别”，集中提示用户处理。
3. 每个启用素材库按规则过滤候选：`confirmed` 且产品匹配，或人工确认的 `shared`；利益点受限的库还需利益点匹配。禁用、零权重、媒体无效的素材继续排除。
4. **过滤后**再运行现有配额、洗牌、去重和随机抽取算法。先随机后过滤会破坏权重与配额。
5. 必需库无候选时阻止计划生成，并指出库名、产品、利益点及被排除原因；可选库无候选则在计划中跳过并提示。
6. 对已选素材汇总达人和限制日期，生成文件名和飞书字段；文件名、计划预览、落盘名称和飞书必须使用同一份计划结果。

例如选择“瑞幸咖啡 + 第二件半价”时，“霸王茶姬”前贴应在抽取前排除；`1.mp4` 若没有已确认解析或覆盖，不能凭当前产品字段自动纳入。换成“霸王茶姬”时，不需要重新测试瑞幸素材，只需保证该产品所需库有足够的已确认候选。

## 7. 命名规则的调整

将“匹配产品”和“输出文件名”拆开。推荐文件名仍可保持现有顺序：

```text
产品-利益点-达人-限制日期-序号.mp4
```

但字段来源应改变：

| 字段 | 建议来源 | 无值时 |
| --- | --- | --- |
| 产品 | 当前选择的产品目录项，且计划通过素材匹配预检 | 阻止生成 |
| 利益点 | 当前选择的利益点目录项，且受限库通过匹配预检 | 业务要求时阻止生成 |
| 达人 | 本条成片实际选中素材的已确认元数据，按时间线去重 | 按项目命名策略决定：必填则阻止；可选则省略整段及分隔符 |
| 限制日期 | 本条成片实际选中素材的已确认有效日期，取最早日期 | 必填则阻止；可选则省略整段及分隔符，不用当天日期伪装 |
| 序号 | 批次计划，延续现有序号起点与冲突处理 | 必填 |

现有正则可作为一张解析模板的底层实现，但普通用户只编辑“选取字段 + 样本验证”的可视化卡片。多种文件名格式可对应多张模板；成功且无歧义的解析结果才进入匹配。旧配置继续走旧规则，启用新匹配模式时执行明确迁移，不静默改变既有项目输出。

## 8. 页面与预检

简单模式建议显示“当前产品”“当前利益点”和一个真实的“可生成检查”结果。检查至少列出每个库的已确认可用数、未识别数、被产品或利益点排除数、必需库缺口。点开可看到具体素材和原因，并支持批量确认或标为通用。

文件名预览应来自**真实计划样本**，展示抽中的素材和最终文件名；若还没有可生成计划，直接显示阻止原因，不显示“达人名”“限制日期”这类看似可用的占位文件名。生成前的完整预检要覆盖所有可能参与抽取的候选，不能只看第一条样本。

素材列表增加产品、利益点、通用、达人、日期及“已解析/待处理”筛选。批量操作必须展示将修改多少条，方便处理 `1.mp4` 这类批量遗留素材。详情应说明命中的模板、源文件名和人工修改记录。

## 9. 迁移步骤与验收

### 第一阶段：可见性

新增只读诊断报告：按库统计当前素材可识别程度、品牌关键词冲突和数字名比例；将现有命名预览标明为示意。用真实文件名试做“字段选取 + 卡片拖拽”原型。此阶段不改生成行为。

### 第二阶段：结构化标注与筛选

加入产品目录、按库保存的解析模板、例外覆盖、库规则和计划前候选筛选。先在通用验证项目启用；原淘宝闪购项目和旧通用配置保持原行为。对当前混合库，先用文件名模板识别明显的品牌素材，再人工处理数字名。

### 第三阶段：统一命名和飞书

由同一份计划元数据生成真实预览、输出文件名与飞书字段；加入可拖拽命名卡片；补充切片继承和跨机器共享验证。

验收至少覆盖：两个产品混放、同一素材适配多个产品、已确认通用素材、数字名未识别、文件名与标注冲突、利益点错配、必需库候选为空、可选库为空、图片尾帧、多人和多个限制日期、素材重命名、不同机器使用同一 NAS 配置、批次预览与成片及飞书一致。最关键的断言是：**任何计划项都不能出现产品名与已选素材确认标注冲突**。

## 10. 工作量与风险

主要改动在解析模板与可拖拽卡片、配置模型与迁移、素材扫描/管理界面、计划候选筛选、真实预览和飞书字段一致性；渲染器本身通常无需改动。一次性开发量明显高于“多写几条正则”，但能把逐产品重复调试转为逐命名格式确认。当前项目最大的人工成本仍是纯数字素材的初次归类，代码无法可靠补出它们缺失的业务信息。

实施前需要确定两条业务规则：

1. 哪些库允许已确认的通用素材，哪些库必须严格匹配产品与利益点。
2. 达人与限制日期是所有项目必填，还是由每个项目分别设置为必填/可选。

在这两条确定前，建议先做只读诊断和数据标注设计，不让自动猜测结果直接进入生产抽取。
