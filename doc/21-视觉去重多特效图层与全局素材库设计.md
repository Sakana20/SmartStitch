# 视觉去重多特效图层与全局素材库设计

## 1. 文档状态

- 状态：已实现，待业务验收。
- 范围：扩展现有“视觉去重”，将透明边框与烟花、光效、粒子等覆盖素材统一为可排序的特效图层。
- 前置设计：[18-视觉去重边框与模糊背景设计](./18-视觉去重边框与模糊背景设计.md)。
- 本文同时作为当前实现与验收基线。

## 2. 需求摘要

1. 新特效归属于“视觉去重”，受现有 `visual_dedup.enabled` 总开关统一控制。
2. 特效与边框一样，作为透明图片或透明视频覆盖到成片，例如烟花、光斑、粒子或动态贴纸。
3. 同一配置可使用多个特效库卡片，每张卡片可单独启停、上移、下移和调节透明度；卡片本身就是全局素材库在项目中的编排项，不再先建图层再选择库。
4. 风险提示语仍是锁定的最高视觉图层；任何去重特效都不得移到它上方。
5. 特效素材和素材分组保存在 SmartStitch 全局素材库，由所有项目复用。
6. 用户可直接在编排列表新增和删除“烟花、边框”等全局特效素材库（分组），也可从对应卡片向库内新增素材；不再提供第二套库管理区。
7. “模糊背景＋缩小清晰主画面”定义为内置的“模糊边框”特效层，它和烟花、透明边框一样参与排序。
8. 每个视觉去重特效层单独使用 `0%～100%` 透明度；风险提示语不属于本次透明度改造范围，保持现有逻辑。

## 3. 概念和边界

### 3.1 全局特效库

“库”是全局素材库下的一个业务分组，例如：

- 透明边框
- 烟花
- 光斑
- 金粉粒子

在产品界面中，一张特效卡片就是一个库，也是项目中的一个可排序编排项。新增卡片即新增全局库，删除素材型卡片即删除对应全局库；项目通过卡片上的“参与去重”开关决定该库是否参与当前项目。生成时与视频库逻辑一致，从库内启用素材中自动抽取一项。

全局存储层仍用稳定的 `library_id` 保存库和素材，项目配置仍保存该库的顺序、参与状态与透明度。上述内部拆分只用于持久化和渲染，前端不暴露“库”和“图层”两套对象。

### 3.2 特效图层

特效编排卡片分为两种：

- `overlay`：从全局特效库选出透明图片或视频叠加，例如边框、烟花、光斑。
- `blur_frame`：内置处理层，将进入该层的当前画面拆为模糊满幅背景和缩小清晰前景，再合成为模糊边框效果。

两种图层都至少包含：

- 稳定的 `layer_id`，排序或改名后不变。
- 显示名称、类型、启用状态和透明度百分比。

`overlay` 图层额外包含引用的全局库、允许素材集合、项目级权重、缩放方式、循环方式和 Alpha 模式。旧版随机/固定字段仅作配置兼容，不在新界面提供选项。`blur_frame` 图层额外包含前景缩放、模糊强度、模糊步数和背景亮度。

每个素材型全局库在同一项目中只对应一张卡片，避免出现“卡片”和“库管理项”重复。要使用另一组素材，应直接新增另一张库卡片。

### 3.3 顺序语义

图层不是一次性平铺到原视频上，而是从下到上顺序处理“当前画面”：

- `overlay` 将自己的透明素材覆盖到当前画面。
- `blur_frame` 将当前画面整体转换为“模糊背景＋缩小清晰前景”。

因此顺序会产生实际差异：烟花在模糊边框层之下时，烟花与原视频一起被缩小，并进入周围的模糊背景；烟花在它之上时，则保持全画幅清晰覆盖。

## 4. 总开关和运行规则

- `visual_dedup.enabled=false`：全部特效图层（包括模糊边框）都不执行，但保留完整配置。
- `visual_dedup.enabled=true`：按各子功能和图层自身开关执行。
- 关闭某个特效图层只改它自身的 `enabled`，不清空选择方式、素材或透明度。
- 总开关不会联动修改子开关，再次开启时恢复上次设置。
- 每条成片在计划阶段固定每个图层的具体素材，渲染阶段不临时随机。

## 5. 图层协议

### 5.1 排序表示

界面中图层列表按视觉顺序“从上到下”显示：

```text
风险提示语（锁定顶层，不可移动）
烟花特效
透明边框
模糊边框（模糊背景＋缩小清晰主画面）
原始主画面（固定输入）
```

配置中 `effect_layers` 的数组顺序与前端完全一致，都定义为“从上到下”。这样可直接复用上方视频库的数组拖拽和上移/下移逻辑；渲染器构建 FFmpeg 链时从数组末尾向前处理。

### 5.2 上移与下移

- 每个特效图层提供“上移”和“下移”，也可复用项目内已有的拖拽排序交互。
- 最上方的特效层不能继续上移，其上方永远是风险提示语。
- 模糊边框层可与烟花、透明边框等层互相换位，不再固定在覆盖素材之下。
- 最下方的特效层不能继续下移，其下方是原始主画面输入。
- 排序只改变项目的图层列表，不修改全局库，也不影响其他项目。
- 风险提示语不在视觉去重卡片中重复展示；最高层约束由卡片说明和后端渲染顺序保证。

### 5.3 渲染顺序

```text
各片段归一化并拼接 [basev]
  → effect_layers[最后一项]
  → ...
  → effect_layers[0]
  → 风险提示语 [outv]
```

渲染器必须最后才叠加风险提示语。后端不得仅依赖前端禁用按钮，而应在配置校验和过滤图构建中都强制该不变量。

## 6. 透明度

### 6.1 产品口径

- 每个视觉去重特效图层都有独立的“透明度”，取值为 `0%～100%`，包括内置模糊边框层。
- 对 `overlay` 层，`0%` 表示完全不可见，`100%` 表示保留素材原始 Alpha，不等价于将透明区域变成不透明。
- 对 `blur_frame` 层，`0%` 表示完全保留进入该层前的画面，`100%` 表示完全使用模糊边框结果，中间值在两者之间按百分比混合。
- 风险提示语不属于视觉去重特效层，本次不改它的透明度字段、单位或界面。
- 每个图层的透明度作用于本图层选中的素材，不回写到全局素材库，因此同一素材在不同项目可使用不同透明度。

### 6.2 存储和迁移

新字段建议直接存储整数百分比，避免前端、YAML 和 API 在 `0.65` 与 `65` 之间反复换算：

```yaml
opacity_percent: 65
```

渲染时统一转换为：

```text
ffmpeg_alpha = opacity_percent / 100
```

旧边框字段迁移：

```text
opacity_percent = round(opacity * 100)
```

过渡期优先读取 `opacity_percent`；仅当新字段缺失时才读取旧 `opacity`。只有用户主动保存配置时才写回新字段。

## 7. 配置设计

```yaml
visual_dedup:
  enabled: false

  # 数组从上到下与前端图层列表一致。
  effect_layers:
    - layer_id: fireworks-main
      name: 烟花
      type: overlay
      enabled: true
      library_id: effect_2
      enabled_asset_ids: []
      weights: {}
      opacity_percent: 70
      scale_mode: exact
      playback: loop
      alpha_mode: auto

    - layer_id: border-main
      name: 透明边框
      type: overlay
      enabled: true
      library_id: effect_1
      enabled_asset_ids: []
      weights: {}
      opacity_percent: 100
      scale_mode: exact
      playback: loop
      alpha_mode: auto

    - layer_id: blur-frame-main
      name: 模糊边框
      type: blur_frame
      enabled: true
      opacity_percent: 100
      foreground_scale: 0.90
      sigma: 20.0
      steps: 2
      brightness: 0.0

```

### 7.1 校验规则

- 新配置默认包含一个启用的“模糊边框”层；显式保存后也允许为空列表。最大图层数按 10 层限制，防止过多同时解码拖垮机器。
- `layer_id` 在同一配置内唯一；`name` 非空；`type` 只能是 `overlay/blur_frame`；`opacity_percent` 为 `0～100` 的整数。
- 一个配置首版最多存在一个 `blur_frame` 层，但它可启停、删除、重新添加和排序。
- 已启用的 `overlay` 图层引用的库必须存在且启用。
- 素材型图层必须至少有一个已启用、兼容当前画布且权重大于 0 的素材。
- 允许 `opacity_percent=0`，但界面显示“当前不可见”提示。

## 8. 全局素材库设计

### 8.1 目录

```text
<SmartStitch 共享根>/
├── 全局素材库/
│   └── 视觉特效/
│       ├── effect_1/     # 显示名称可为“透明边框”
│       ├── effect_2/     # 显示名称可为“视觉特效”或用户改名
│       └── effect_N/
└── .smartstitch/
    └── visual-effect-libraries.json
```

注册表记录库元数据、素材元数据、内容哈希、当前版本和删除状态。素材仍使用内容哈希 ID 去重，不依赖文件名作为身份。

### 8.2 新增库

- 用户填写库名称，系统按创建顺序生成不变的 `effect_N` 编号和同名目录。
- 库名可修改，`library_id` 不随之改变。
- 新库默认启用、素材为空，可在之后批量上传。
- “透明边框”作为内置迁移库，不允许产生第二个相同 ID。

### 8.3 删除库和素材

全局删除会影响多个项目，因此界面提供“删除”，底层首先执行可恢复的软删除：

- 删除前显示库内素材数量，并提示引用该库的项目会在预检时报错。
- 空库可直接软删除；非空库必须二次确认。
- 已被项目引用的库删除后，该项目预检失败并明确提示“特效库已删除”，不得静默换用其他库。
- 已创建任务冻结的计划和素材文件在任务结束前保持可读，避免排队中的任务突然失败。
- 单个素材删除遵循同样规则；删除后不会静默替换项目图层的素材库引用。
- 物理清理由后续垃圾回收机制执行，不在删除按钮的当次请求中立即移除大文件。

库和素材的写操作继续使用全局库版本号、内容哈希与跨进程锁，避免 NAS 多机并发覆盖。

### 8.4 格式和预检

首版复用现有透明边框的视频/图片格式和 Alpha 检查能力，不在本功能中顺便扩大编码范围。上传后必须由后端用 ffprobe/FFmpeg 校验：

- 有效视频流或可解码图片。
- 实际存在 Alpha 通道和透明像素。
- 尺寸与当前项目的 `exact/stretch` 规则兼容。
- 动态素材时长大于 0，并可循环到成片结束。
- 素材中的音轨始终忽略。

## 9. 计划、渲染与追溯

### 9.1 计划阶段

对每个已启用的 `overlay` 图层，计划器按其库、允许集合、权重和随机种子选出唯一素材。`blur_frame` 不需要选择外部素材，但其顺序和参数必须同样冻结到计划快照。`PlanItem` 从单个 `visual_border` 扩展为有序 `visual_effects` 列表，列表顺序与前端“从上到下”的图层顺序一致，渲染时反向遍历。

任意已启用的必需图层无兼容素材时，整批任务不可启动。错误需指出图层名、库名和没有候选的原因。

### 9.2 渲染阶段

渲染器按 `effect_layers` 从最后一项到第一项依次处理，每一层的输出成为下一层的输入：

```text
[basev] -> effect_layers[最后一项] -> ... -> effect_layers[0] -> [effectv]
[effectv][risk_overlay]overlay[outv]
```

- `overlay` 层独立执行尺寸、帧率、PTS、Alpha 模式和透明度处理，再叠加到当前画面。
- `blur_frame` 层对当前画面执行 `split → 背景模糊 → 前景缩小 → overlay`，再按 `opacity_percent` 将处理结果与该层处理前的画面混合。
- 任何特效素材都不提供成片音轨。
- 风险提示语仍在全部视觉去重图层完成后最后叠加。

### 9.3 清单

`manifest.json` 每条成片至少记录：

- 视觉去重总开关。
- 有序图层列表，包含 `layer_id`、图层名、类型、顺序和透明度百分比；`overlay` 层还记录库 ID/名称。
- 每个 `overlay` 层最终选中的素材 ID、路径、内容哈希、媒体探测信息、权重和随机种子；`blur_frame` 层记录其处理参数。
- 风险提示语的素材、时段、位置和现有配置快照，但不将它记为视觉去重特效层。
- 最终图层顺序，并明确风险提示语为锁定顶层。

## 10. 界面设计

### 10.1 视觉去重卡片

在现有“视觉去重”卡片内增量扩展，不新建独立页面。图层列表直接参考配置页上方已有的“视频库编排”实现，保持相同的卡片密度、拖拽方式和操作反馈：

- 卡片头部保留总开关。
- “模糊背景与缩小主画面”不再作为列表之外的固定子功能，而是列表中一张名为“模糊边框”的卡片。
- 图层列表与上方视频库一样，显示拖拽手柄、当前顺序号、名称、状态和行内操作。
- 每层显示开关、透明度百分比、上移、下移和删除；`overlay` 层只显示关联素材库及可用素材数量，不显示随机/固定或具体素材选择控件。
- 风险提示语已在上方独立设置，不在视觉去重列表中重复显示。
- 只能从拖拽手柄开始排序，避免调节开关、透明度或素材时误触拖拽。
- 放下卡片后更新同一份 `state.configDraft.visual_dedup.effect_layers`，不单独建立图层 store。
- 鼠标拖拽与键盘“上移/下移”必须产生相同的配置结果。
- “＋添加特效库”按钮与上方“＋添加视频库”的位置和样式一致。输入名称后同时创建全局库和列表卡片，生成时从该库自动抽取启用素材。
- 与上方视频库一样，新库默认添加到可见列表末尾，添加后可立即上传素材并拖到任意位置。
- 素材型卡片上的改名、添加素材和删除直接作用于对应全局库；参与开关、顺序和透明度属于当前项目。
- 删除素材型卡片前显示库名、素材数量以及对其他引用项目的影响；底层执行可恢复的全局软删除。内置“模糊边框”只从当前项目移除。
- 删除最后一张卡片后允许保持空列表。

透明度控件同时提供滑块和数字输入，两者双向同步：

```text
透明度  [━━━●━━━] 70 %
```

键盘输入限制为整数 `0～100`，超界时不允许保存并给出字段级提示。

### 10.2 单列表原则

视觉去重区域只保留一套卡片列表，不在列表下方再放“管理全局特效库”：

- 卡片名称就是库名称，可直接编辑。
- 卡片中显示 `effect_N ↗` 文件夹入口；素材数量和可用状态显示在名称下方，向该目录放入素材后系统自动登记。
- “参与去重”、上移、下移、删除和透明度均位于同一张卡片。
- 新增、改名、上传和删除继续使用全局库版本号处理并发冲突；发生冲突时刷新卡片列表，不覆盖其他电脑的修改。

## 12. 兼容和迁移

1. 旧 `visual_dedup.border_overlay` 迁移为 `effect_layers` 中名为“透明边框”的一层。
2. 旧 `foreground + background` 迁移为名为“模糊边框”的 `blur_frame` 层，并保留缩放、模糊、步数和亮度参数。
3. 为保持旧输出，迁移后前端从上到下显示“透明边框、模糊边框”，实际渲染仍是“模糊边框 → 透明边框”；两层的 `opacity_percent` 默认均为 `100`。
4. 旧边框的启停、随机/固定、素材范围、权重、缩放、循环和 Alpha 设置在后端兼容保留，但新界面不再展示随机/固定选项。
5. 旧边框 `opacity` 按 `round(opacity * 100)` 迁移。
6. 现有 `全局素材库/视觉去重边框` 迁移为编号库 `视觉特效/effect_1`，保留显示名“透明边框”、原素材显示名和内容哈希；旧配置中的 `visual-border` 引用继续兼容。
7. 现有 `全局素材库/视觉特效` 根目录中的素材迁移并登记为 `effect_2`，默认显示名“视觉特效”；之后改显示名不会改变 `effect_2` 目录。
8. 风险提示语 `benefit_overlays` 完全保持现有字段和行为，不迁移为特效层，也不改为百分比字段。
9. 没有视觉去重配置的旧项目仍默认关闭，输出不变。
10. 素材库目录迁移在首次读取全局特效库时执行；项目配置仍只在用户主动保存时写回。

## 13. 测试与验收

### 13.1 配置和界面

1. 总开关关闭时，所有特效不渲染，但图层顺序、素材和透明度均保留。
2. 新增透明边框和烟花两个素材库卡片，与内置模糊边框一起上下移动，重新打开配置后顺序不变。
3. 最高特效层的“上移”不可用，风险提示语不出现在视觉去重图层列表中。
4. 每个视觉去重层的透明度可单独修改为 `0%、50%、100%`，不影响其他层，风险提示语不出现在该百分比操作中。
5. 视觉去重列表下方不出现独立的全局特效库管理区；库的新增、改名、上传和删除均从卡片完成。
6. 删除素材型卡片会软删除对应全局库，并提示对其他项目的影响；删除内置模糊边框只影响当前项目。
7. 新增/删除全局库时有版本冲突保护和影响范围提示。

### 13.2 渲染

构造主画面、红色边框、蓝色烟花、黄色光效和绿色风险提示语的可重叠样例，通过像素取样验证：

1. 调整特效层顺序后，重叠区域颜色按新顺序变化；将烟花放在模糊边框下方时，烟花随当前画面一起缩小和模糊，放在上方时则保持全幅清晰。
2. 不论特效如何排序，风险提示语重叠区域始终保持最上层结果。
3. `overlay` 层的 `50%` 输出与预期 Alpha 混合值在容差内一致；`blur_frame` 层的 `0%` 与处理前画面一致，`100%` 与完整模糊边框结果一致，`50%` 为两者混合。
4. 同一条成片中的所有动态特效从第 0 帧开始，独立循环，成片时长仍由主时间线决定。
5. 特效音轨不进入成片，风险提示语的时段规则不变。
6. 任务清单可完整复现图层顺序、素材选择和透明度。

### 13.3 回归

- 旧项目在迁移前后生成结果一致。
- 只使用原边框时，过滤链与现有语义一致。
- 不启用视觉去重时，不新增特效输入和过滤器。
- 取消、重试、VideoToolbox 回退、中文路径和 NAS 多机编辑不回归。

## 14. 已确认业务规则

1. “新增库/删除库”指新建或删除“烟花、边框”等全局素材分组，不是只增删项目内图层。
2. 模糊背景和缩小清晰主画面组成一个“模糊边框”特效层，它必须能和透明边框、烟花等图层自由调整顺序。
3. 所有视觉去重特效层都不得高于风险提示语。
4. 百分比透明度只属于视觉去重特效层，不包含风险提示语。
5. 前端图层编排参考配置页上方的视频库列表，复用其卡片、拖拽、上移/下移、新增、删除和草稿保存逻辑。
6. 素材型图层不提供随机/固定和具体素材选择控件，生成时与视频库一致，从关联库内自动抽取启用素材。
7. 风险提示语只在上方独立设置区域出现，不在视觉去重卡片内重复占位。
8. 一张素材型卡片就是一个全局特效库；不再提供独立库选择器或列表下方的“管理全局特效库”。
