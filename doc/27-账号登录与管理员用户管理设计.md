# 账号登录与管理员用户管理设计

状态：账号登录与管理员用户管理首版已实现；任务提交者归属字段待补。本文记录用户名加密码登录、管理员专属入口，以及管理员对账号的创建、暂停、恢复和删除规则。

## 1. 目标与现状

SmartStitch 在每台 Mac 上运行独立 App，多个实例共用 NAS 配置和素材。当前顶部的“用户”只是本机无密码显示名称，不能证明操作者身份；工具台“SmartStitch 集群控制”另用一套临时共享密码；“用户管理”仍是占位卡片。新方案用同一套账号登录替代这两个入口的身份判断。

目标：

1. 打开 App 后先以用户名和密码登录，未登录不能调用业务接口。
2. 账号分为 `admin`（管理员）和 `user`（普通用户）。工具台中的“SmartStitch 集群控制”和“用户管理”只对管理员展示和开放。
3. 管理员可添加、暂停（停用）、恢复（启用）和删除用户；可指定或撤销其他管理员，但始终保留至少一个可登录管理员。
4. 同一账号可在不同 Mac 登录；显示名称和配置编辑锁能关联到稳定账号 ID。
5. 停用、删除、改密和降权后，相关旧会话及时失效。

本期只定义账号和角色，不增加按配置、素材库或任务细分的权限。普通用户登录后继续使用现有创建任务、时间线切片、素材权重、任务记录和非管理员工具。

## 2. 页面与操作

### 登录与个人账号

- 首次进入及会话过期时显示登录页：用户名、密码、登录按钮和明确的错误提示；不提供自行注册。
- 顶部显示当前账号的显示名称与角色，提供退出登录、修改本人密码。用户名是唯一登录名，显示名称允许重名且可由管理员修改。
- 错误提示不区分“用户名不存在”和“密码错误”；连续失败要有节流。密码输入框不可回显，前端不保存密码。
- 退出登录立即撤销当前会话并清理前端状态；重新登录后才恢复业务页面。正在运行的后台任务按任务自身规则继续，账号退出不自动取消任务。

### 工具台可见性

| 能力 | 普通用户 | 管理员 |
| --- | --- | --- |
| 工具台及一般工具 | 可见、可用 | 可见、可用 |
| SmartStitch 集群控制卡片、面板、操作接口 | 不显示、拒绝访问 | 可见、可用 |
| 用户管理卡片、面板、操作接口 | 不显示、拒绝访问 | 可见、可用 |
| 管理本人密码、退出登录 | 可用 | 可用 |

工具清单可保留稳定 ID `cluster-control` 和 `user-management`，渲染时按当前角色过滤。隐藏卡片只是界面规则；后端必须在每个管理接口校验登录状态和当前 `admin` 角色。用户手动请求 URL、修改前端代码或复用旧令牌均不能绕过权限。

### 用户管理面板

管理员可查看账号列表：用户名、显示名称、角色、状态、创建时间、最后登录时间。列表不返回密码、密码哈希或会话令牌。提供以下操作：

| 操作 | 规则 |
| --- | --- |
| 添加用户 | 填写唯一用户名、显示名称、初始密码和角色；默认普通用户。账号创建后即可登录，首次登录强制修改初始密码。 |
| 暂停用户（停用） | 保留账号和历史关联，立即撤销其所有会话，不允许新登录。 |
| 恢复用户（启用） | 恢复登录资格；原会话不恢复，必须重新登录。 |
| 删除用户 | 二次确认后标记删除，立即撤销会话；用户名保留不可复用，以免历史归属混淆。历史任务、锁记录和审计记录保留账号 ID 与当时显示名称。 |
| 调整角色 | 管理员可授予或撤销管理员角色；变更后撤销目标账号全部会话，要求重新登录。 |
| 重置密码 | 管理员设置临时密码，目标账号所有会话立即失效，下一次登录强制改密；不显示原密码。 |

管理员不能停用、删除或降权最后一个处于启用状态的管理员；不能删除当前登录账号，需先由其他管理员处理。停用或删除正在编辑的用户时，其配置锁应释放；即使释放失败，也不得允许其继续续租或保存，锁仍可按现有租约超时恢复。已提交的后台任务不因用户状态变化自动取消，记录保留提交者 ID。

所有账号新增、暂停、恢复、删除、角色变更和密码重置都记录操作者账号 ID、目标账号 ID、操作类型、时间和结果；审计记录不包含密码或会话令牌。

## 3. 账号数据与多机一致性

多台 App 必须看到同一份账号和角色。账号注册表放在 NAS 上独立于业务 YAML 的受限目录；本机 `data/user-profile.json` 不再是登录凭据，也不能决定角色。账号采用不可变 `account_id`，用户名唯一、规范化后比较，显示名称仅用于界面和锁提示。记录至少包含：`account_id`、`username`、`display_name`、`role`、`status`、`password_hash`、`must_change_password`、`auth_version`、创建/修改/最后登录时间。删除采用墓碑状态，不物理抹去历史身份。

注册表写入要使用跨机互斥、版本校验、唯一临时文件和原子替换；账号创建与用户名唯一性校验、最后管理员保护必须处于同一次受保护提交中。NAS 读写失败或注册表损坏时拒绝登录、管理修改及需要核验身份的业务请求，不能回退到本机显示名称或临时集群密码。保留可恢复备份；恢复步骤需由管理员在可信机器上操作。NAS 目录权限应只赋予运行 SmartStitch 所需的服务身份；若使用者直接拥有该目录写权限，应用层账号无法防止其离线篡改，部署时必须明确这一安全边界。

密码只保存使用随机盐的成熟密码哈希（当前采用 scrypt），不保存明文或可逆密文。初始密码由管理员安全交付给用户，不能写入日志或返回列表。密码策略：新设密码至少 6 个字符；禁止空密码；登录和改密接口限制尝试频率。此前按用户指定创建的短密码管理员账号仍可登录，修改时按新规则校验。账号注册表与会话数据不提交到 Git。

本方案沿用“多台独立 App + NAS”的部署方式。若未来需要在不可信终端或不可信 NAS 写入者之间建立强安全边界，应改为独立的认证服务与受控存储；不能仅靠前端隐藏入口或 NAS 文件权限声称已实现该边界。

## 4. 会话与接口权限

- 登录后由后端生成不可预测的会话令牌，绑定 `account_id` 与 `auth_version`。推荐通过仅本机 `127.0.0.1` 的 `HttpOnly`、`SameSite=Strict` Cookie 传递，并对修改请求做同源/CSRF 校验；不得持久化在 `localStorage`。会话应有空闲超时和最长有效期，退出时服务端撤销。
- 每个业务请求由后端解析会话并核对共享账号的状态和 `auth_version`。停用、删除、改密、重置密码和角色变更递增版本，使各台 Mac 上的旧会话失效；不得只信任登录时写入令牌的旧角色。NAS 无法核验时拒绝请求。
- 登录、登出、本人资料与改密接口允许相应的未登录/已登录状态；用户列表及增删停启、角色、重置密码接口要求管理员。现有配置、素材、切片、任务、工具操作等 `/api/v1` 业务接口要求已登录。健康检查、静态登录页和工作机专用接口按各自用途单独列白名单，不把完整管理 API 暴露到局域网。
- 集群控制原有 `/unlock`、`SMARTSTITCH_CLUSTER_PASSWORD` 和 15 分钟临时访问令牌在迁移完成后移除；集群控制本机接口改为管理员会话鉴权。工作机之间的局域网节点令牌是机器通信凭据，仍与用户登录分离，不能当作管理员身份。
- 权限变更和拒绝访问应有可读错误码：未登录/会话失效返回 401，无管理员权限返回 403，目标账号不存在返回 404，用户名冲突或最后管理员保护返回 409。

## 5. 从现状迁移

1. 在受控的首台 Mac 上运行一次性初始化流程，创建首个管理员，现场设置用户名和密码。初始化要用 NAS 原子互斥确保只能成功一次；不得内置默认管理员密码，也不得让任意打开 App 的人抢先注册管理员。
2. 所有 Mac 升级到强制登录版本后再开放新账号系统。旧版本没有全局登录鉴权，继续运行会绕过新权限；升级前暂停旧版本访问共享数据。
3. 旧 `user-profile.json` 的显示名称只用于提示管理员认领或新建账号，不自动赋予身份和权限。新登录账号的 `account_id` 已取代旧随机 `user_id` 进入配置锁持有者字段；任务记录的提交者归属字段尚未迁移，旧记录保留原有历史信息。
4. 活跃的旧配置编辑锁按当前租约到期或由持有者释放；迁移时不把旧无密码身份转换为可续租的新登录会话。新账号登录后重新获取锁。
5. 集群控制临时密码入口及其文档、环境变量说明随代码切换一并移除；工作机间通信配置独立保留。

## 6. 验收要点

1. 未登录打开 App 只能进入登录流程；直接调用任一业务接口被拒绝。普通用户看不到两张管理员卡片，直接请求管理接口得到 403。
2. 管理员能添加用户、授予管理员、停用/启用/删除用户、重置密码；同名用户名创建失败，重名显示名称允许。
3. 两台 Mac 登录同一账号后，在一台停用、删除、改密或降权，另一台下一次受保护请求立即失效；NAS 不可用时不能继续使用缓存的管理员权限。
4. 最后一名启用管理员无法被停用、删除或降权；并发管理操作也不能留下零管理员。
5. 被停用或删除者不能继续保存配置、续租编辑锁或发起新任务；历史任务和已完成结果仍可追溯。
6. 密码和哈希不出现在前端资源、业务 YAML、API 列表或日志；旧集群解锁密码不再提供管理权限。
