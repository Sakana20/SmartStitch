# SmartStitch 时间线审核交互规范

## 1. 目标与术语

时间线审核台用于“机器粗分析、人工确认断点、片段分类”的工作流。编辑体验参考 Adobe Premiere Pro 的时间线，但只实现单条素材、断点和片段范围，不扩展为多轨剪辑器。断点下方的列表应以片段为对象，并允许在每行直接选择入库类型；详见[《片段审核与分类切片设计》](./09-片段审核与分类切片设计.md)。

- **播放器进度条**：视频播放器自带的进度控件，是辅助定位入口，不属于编辑时间线的上下两层。
- **时间标尺栏**：编辑时间线的上层，显示刻度、时间码标签和播放头手柄。
- **片段轨道**：编辑时间线的下层，即当前显示片段、机器点和人工断点的轨道。
- **播放头**：由标尺栏上的手柄和贯穿轨道的竖线组成，表示当前预览帧。
- **断点**：切片边界，最终以整数 `frame_index` 保存。
- **机器点**：粗分析生成、尚未人工确认的候选断点。
- **人工点**：人工新增、调整或确认的断点。
- **片段类型**：切割后的入库目标，由片段行右侧的类型按钮选择。

## 2. PR 式时间线结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 时间标尺栏   00:00:00:00   00:00:05:00   00:00:10:00       │
│              |  |  |  |  |  ▼  |  |  |  |  |  |  |         │
├─────────────────────────────┼────────────────────────────────┤
│ 片段轨道     [ 片段 1       │ ][ 片段 2 ][ 片段 3 ]         │
│ 机器/人工点        M         │       H                        │
└─────────────────────────────┼────────────────────────────────┘
                              播放头竖线
```

时间标尺栏与片段轨道必须：

- 共享同一时间线内容宽度、缩放比例和水平滚动位置。
- 共享同一 `playhead_frame`，播放头手柄与竖线不得分离。
- 在缩放和滚动后继续保持刻度、断点和片段边界对齐。
- 根据缩放级别自适应主次刻度；标签间距不足时减少标签，而不是重叠显示。

## 3. 播放与同步

视频、播放器进度条、时间标尺播放头、帧号和时间码由同一个 `playhead_frame` 驱动；片段与断点使用各自的边界帧，不得在拖动断点时反向改写 `playhead_frame`：

1. 视频播放时，以实际呈现帧更新播放头。
2. 操作播放器进度条后，时间线播放头同步到实际 seek 后呈现的帧。
3. 操作时间标尺时，先由鼠标坐标得到目标帧，再驱动视频跳转；片段轨道空白区域不参与播放定位。
4. 浏览器只提供连续 `currentTime` 时，帧号按当前显示区间向下取整并加入微小浮点误差补偿；不得四舍五入到尚未呈现的下一帧。
5. 断点的权威时间保持 `frame_index / fps`；播放器定位预览使用 `(frame_index + 0.5) / fps` 进入目标帧内部，避免浏览器在帧边界保留前一段最后一帧。
4. 暂停、播放结束、切换视频和重新加载审核记录后，所有显示仍须一致。
5. 同步实现必须区分更新来源，避免视频与时间线互相回写形成循环。

## 4. 跟手拖动

时间线拖动采用与 PR 类似的绝对坐标定位。鼠标移动到时间线哪个横坐标，播放头就移动到同一横坐标；不得使用 `4px/帧`、`12px/帧` 等人为减速映射。

```text
timeline_x = pointer_viewport_x - timeline_left + scroll_left
raw_time_seconds = timeline_x / pixels_per_second
target_frame = round(raw_time_seconds * fps)
```

交互规则：

| 手势 | 行为 |
|---|---|
| 单击时间标尺 | 播放头定位到该横坐标对应的最近整数帧 |
| 拖动时间标尺 | 播放头持续跟随鼠标，并同步预览视频画面 |
| 单击、双击或拖动轨道空白处 | 不改变播放头，也不新增断点 |
| 单击断点 | 选中断点并定位播放头 |
| 拖动断点 | 仅调整断点边界；播放头竖线、视频画面和当前播放帧保持不变 |
| `←` / `→` | 播放头或选中断点前后移动 1 帧 |
| `Shift` + 拖动 | 临时启用吸附；断点可吸附到播放头竖线 |
| 时间线悬停 + `Space` | 切换视频播放/暂停，并阻止页面滚动；忽略按键自动重复 |
| 时间线悬停 + `Option` + 滚轮 | 以鼠标所在时间点为锚点放大或缩小时间线 |
| 普通滚轮 | 不缩放，保留时间线视口原有滚动行为 |

跟手标准：

- 除整数帧取整导致的亚像素差异外，指针与被拖对象之间不应出现持续可见间距。
- 使用每帧一次的合并刷新处理高频指针事件，始终消费最新位置，不排队回放旧位置。
- 松开鼠标时直接提交当前显示位置，不得再次套用不同公式造成跳变。
- 帧级精调由时间线缩放实现；放大到单帧宽度至少 4 CSS px 时，应能稳定选择相邻帧。
- 拖动时间标尺期间暂停视频并连续更新预览，松开后必须保持暂停，即使拖动前正在播放也不恢复。拖动断点期间播放头和画面不随断点移动，松开后可恢复断点拖动前的播放状态。

快捷键只在鼠标位于时间线视口内时生效。`Option` + 滚轮缩放前后，鼠标所指的时间值必须保持稳定，不得跳到播放头或视口中心。

## 5. 按住 Shift 吸附

吸附默认关闭。只有 `Shift` 持续按下且用户正在拖动时间标尺或断点时才启用；拖动时间标尺可吸附到已有断点，拖动断点还可吸附到当前播放头竖线。

```text
普通拖动：始终跟手，不吸附

按住 Shift：
  自由拖动 ── 距目标 ≤ 8 px ──> 已吸附
              已吸附且距目标 ≤ 12 px：保持吸附
              松开 Shift 或距目标 > 12 px：立即解除
```

要求：

- 吸附目标包括机器候选断点和人工确认断点；拖动断点时，当前播放头所在帧也是吸附目标。
- 断点吸附到播放头后只更新断点帧，播放头竖线、视频画面和当前播放帧必须保持不变。
- 吸附阈值按当前视口中的 CSS 像素计算，缩放或滚动后重新计算目标横坐标。
- 吸附生效时显示目标引导线、目标类型、帧号和时间码；播放头作为目标时显示“播放头吸附”。
- 多目标同时命中时依次比较：屏幕距离、人工点优先级、机器点优先级、帧序号。
- 拖动中松开 `Shift`，必须在下一次可见刷新内解除吸附，并回到当前鼠标横坐标对应的帧。
- 新增点吸附到已有点时选中已有点，不创建重复断点。
- 拖动已有点吸附到另一已有点时不得覆盖或隐式删除任何断点。

## 6. 拖动生命周期

1. `pointerdown`：记录拖动对象、视频播放状态并捕获指针。
2. `pointermove`：保存最新指针坐标；在下一帧刷新中换算目标帧，按 Shift 状态决定是否吸附，然后更新播放头、画面和时间码。
3. `pointerup` 或 `pointercancel`：提交当前内存位置并释放指针；移动播放头后保持暂停，只有断点拖动可以恢复操作前的播放状态。
4. 用户点击“保存人工审核”后，才将最终断点写入审核 JSON。

即使鼠标在窗口外松开、页面失去焦点或触发取消事件，也必须执行统一清理，不能遗留拖动、吸附或暂停状态。

## 7. 数据与可审计性

- 原始机器候选点不可因人工调整而被覆盖，应作为分析证据保留。
- 人工最终断点按升序、去重后保存。
- 秒数、像素位置和时间码均是显示派生值；审核重载必须以 `frame_index` 恢复。
- 缩放、滚动和是否按住 Shift 只影响交互，不改变最终断点含义。
- 再次机器分析同一视频应产生新的分析记录，不覆盖已经保存的人工审核。

## 8. 精度边界

当前帧级交互首先保证恒定帧率（CFR）素材。对可变帧率（VFR）视频，平均 FPS 不能严格代表每帧时间；界面应提示精度限制。若业务需要对 VFR 达到同等精度，后续应建立每帧 PTS 索引，使用真实时间戳完成 `frame_index ↔ pts` 映射。

## 9. 完成标准

- 时间标尺栏位于现有轨道上方，主次刻度、标签和播放头手柄清晰可用。
- 标尺、轨道、断点、片段边界及贯穿式播放头在缩放和滚动后保持对齐。
- 播放头和断点拖动始终跟手，无人为减速、累计延迟或松手跳变。
- 默认拖动不吸附；只有按住 `Shift` 时吸附，松开后立即解除。
- 保存、关闭、重载后断点帧序号完全一致。
- 机器候选证据和人工最终决策均可追溯。
