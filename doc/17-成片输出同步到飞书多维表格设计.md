# SmartStitch 成片输出同步到飞书多维表格设计

## 1. 结论

SmartStitch 的同步目标是飞书多维表格（Base/bitable），不是飞书电子表格（Sheets）。两者接口和数据模型不同：电子表格按单元格区域写入，多维表格按 `Table → Field → Record` 写入。

用户需要配置三类信息：

| 信息 | 作用 | 保存位置 |
| --- | --- | --- |
| App ID | 标识飞书企业自建应用 | 本机全局配置 |
| App Secret | 换取应用访问令牌 | 本机秘密配置 |
| 多维表格链接 + 数据表 | 确定记录写入目标 | 项目配置 |

因此，**多维表格链接仍然需要填写**。App ID 和 App Secret 只能确定调用身份，不能确定写入哪个 Base、哪张数据表。

## 2. 链接与目标解析

支持两种常见链接：

```text
https://example.feishu.cn/base/bascxxxxxxxx?table=tblxxxxxxxx&view=vewxxxxxxxx
https://example.feishu.cn/wiki/wikcnxxxxxxxx?table=tblxxxxxxxx&view=vewxxxxxxxx
```

- `/base/` 后的值解析为 `base_token`。
- `/wiki/` 表示多维表格位于知识库中；后端先通过 Wiki 节点接口解析出底层 `base_token`。
- `table` 查询参数解析为 `table_id` 并自动预选数据表。
- `view` 只控制飞书页面展示，不影响记录写入，因此不保存。
- 如果链接没有 `table` 参数，连接测试会列出 Base 内的数据表，用户从下拉框选择。
- `/app/` 应用模式链接不是普通 Base 链接，首版暂不作为同步目标。

## 3. 配置拆分

App Secret 不能放入项目 YAML。项目配置会进入浏览器状态、任务快照和 NAS 备份，放在其中会扩大秘密暴露范围。

本机秘密配置：

```yaml
# data/integrations.yaml，权限 0600，不纳入 Git
schema_version: 1
feishu:
  app_id: "cli_xxxxxxxxxxxxx"
  app_secret: "真实密钥"
```

项目配置只保存非秘密目标：

```yaml
output:
  feishu_base_sync:
    enabled: false
    base_url: "https://example.feishu.cn/base/bascxxxxxxxx?table=tblxxxxxxxx"
    table_id: "tblxxxxxxxx"
    trigger: job_terminal
    row_scope: all_items
    write_mode: upsert
```

App Secret 可以在前端更换，但读取接口只返回 `app_secret_configured`，不返回真实值。Secret 输入框留空表示保留原值。

## 4. 前端交互

“配置管理”新增独立的“飞书多维表格同步”卡片：

1. 启用开关。
2. App ID。
3. App Secret（只允许更换，不读回）。
4. 多维表格链接，支持 `/wiki/` 和 `/base/`。
5. 数据表下拉框，保存稳定的 `table_id`。
6. “测试连接”按钮：验证凭证和 Base 可访问性，读取数据表列表，但不写测试记录。

通用项目中该卡片编号为 06，淘宝闪购项目中编号为 05。高级模式额外提供同步条目范围设置。

## 5. 字段与记录结构

同步器按项目的 `workflow_type` 选择字段模板，红果/通用项目与淘宝闪购互不覆盖。

### 5.1 红果/通用项目

每条成片任务条目对应一条 Base Record。目标数据表需要预先存在 6 个业务字段；同步器只会自动补齐 4 个 SmartStitch 文本字段，不再为同一含义创建重复列：

| 字段 | 类型 | 来源 | 内容 |
| --- | --- | --- | --- |
| 日期 | 日期 | 用户预建 | 成片任务完成时间 |
| 单选 | 单选 | 用户预建 | 新成片写为“待审核” |
| 文本 | 文本 | 用户预建 | 产品名 |
| 文件 | 附件 | 用户预建 | 实际成片文件 |
| 命名 | 文本 | 用户预建 | 成片文件名 |
| 当日文件夹路径 | 文本 | 用户预建 | 成片所在目录 |
| 利益点 | 文本 | 自动补齐 | 命名元数据中的利益点 |
| 达人 | 文本 | 自动补齐 | 命名元数据中的达人，多人用 `+` 连接 |
| 限制日期 | 文本 | 自动补齐 | 命名元数据中的限制日期 |
| `_smartstitch_key` | 文本 | 自动补齐 | `<job_id>:<item_index>`，用于幂等 upsert |

视频先以 `bitable_file` 素材上传到目标 Base，再将返回的 `file_token` 写入“文件”附件字段。20 MB 以内直接上传，超过 20 MB 时按飞书返回的分片策略串行上传。已有记录已经包含附件时，重试只更新其他字段，不重复上传文件。

### 5.2 淘宝闪购项目

淘宝闪购使用目标素材表的现有字段，不创建或复用红果字段：

| 字段 | 类型 | 首次写入内容 |
| --- | --- | --- |
| 出片日期 | 日期 | 成片任务完成时间 |
| 剪辑 | 文本 | 留空，供后续人工填写 |
| 视频 | 附件 | 实际成片文件 |
| 素材（命名：利益点-形式-日期-剪辑-特殊标识-序列） | 文本 | `一口价二剪-MMDD-当日序号` |
| 审核 | 单选 | `待审核` |
| `_smartstitch_key` | 文本 | `<job_id>:<item_index>` |

“序号”为飞书自动编号，“任务id”由后续素材上传流程回填，SmartStitch 不写入。文案、投稿日期、投稿标题、达人号和备注也保留给后续流程。当日序号读取同一出片日期的已有记录后续排；重试使用 `_smartstitch_key` 更新原记录，并保留已人工填写的剪辑、审核状态和素材命名。

## 6. 同步流程

```text
成片任务进入终态
  → 写入本地 manifest.json / manifest.csv
  → 创建 SQLite output_sync_jobs 记录
  → 后台读取任务快照中的 feishu_base_sync
  → 获取 tenant_access_token
  → 解析 base_url 并确认 table_id
  → 根据项目类型校验红果/通用或淘宝闪购字段模板
  → 拉取现有 Record 的 _smartstitch_key
  → 上传缺失的成片附件
  → 已存在的批量更新，不存在的批量创建
  → 再次读取并校验本批业务键
  → 独立记录同步成功或失败
```

同步状态与成片状态分开。飞书断网、限流、权限不足或字段创建失败，不会把已完成的成片任务改成失败。

## 7. 幂等、批量与恢复

- 唯一业务键为 `<job_id>:<item_index>`。
- 每次重试先读取远端记录，再决定创建或更新，避免超时后重复记录。
- 创建和更新按每批最多 200 条串行提交，降低多维表格并发冲突风险。
- 网络错误、HTTP 429、服务端错误和明确的限流响应采用 5 秒、30 秒、2 分钟、10 分钟退避重试。
- 进程重启时，将中断的同步记录恢复入队。
- 达到重试上限或遇到权限、凭证等确定性错误后，任务详情保留错误并提供手动重试。

## 8. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/integrations/feishu/settings` | 返回 App ID 和 Secret 是否已配置 |
| `PUT` | `/api/v1/integrations/feishu/settings` | 更新全局凭证 |
| `POST` | `/api/v1/integrations/feishu/test` | 解析 Base 并返回数据表列表，不写记录 |
| `GET` | `/api/v1/jobs/{job_id}/sync/feishu` | 查询同步状态 |
| `POST` | `/api/v1/jobs/{job_id}/sync/feishu` | 手动发起或重试同步 |

## 9. 飞书侧前置条件

1. 创建或使用企业自建应用。
2. 为应用申请并发布多维表格读取、字段创建、记录读取、记录创建和记录更新权限。
3. 附件上传还需要满足飞书素材上传接口的任一权限（例如 `docs:document.media:upload` 或 `bitable:app`）。
4. 确保应用身份能访问目标多维表格；仅申请 API scope 不等于自动获得某份 Base 的访问权限。
5. 使用 `/wiki/` 或 `/base/` 链接测试连接并选择数据表；使用 Wiki 链接时还需 Wiki 节点只读权限。

`base:field:delete` 与 `base:record:delete` 只用于本次旧结构迁移清理，不是日常自动同步的必需权限；日常同步不会删除用户字段或记录。

连接测试若返回 `base:table:read` 等缺失 scope，配置卡片会显示可读的权限名称，并提供错误响应中飞书开放平台的权限配置链接。应用身份缺少 scope 时需要在开发者后台开通并发布权限，不使用用户登录授权代替。

## 10. 验收标准

1. 前端可配置 App ID、更换 App Secret、粘贴 `/wiki/` 或 `/base/` 链接并选择数据表。
2. GET 接口、项目配置、任务快照、日志和清单不包含 App Secret 或 access token。
3. 连接测试不会写入数据。
4. 完成、部分失败和失败任务均可按配置同步为记录。
5. 同一任务重复同步不会产生重复 `_smartstitch_key`。
6. 目标数据表已有其他字段和记录时，不删除、不清空、不覆盖无关数据。
7. 飞书同步失败不影响成片任务终态，任务详情可查看错误并重试。
