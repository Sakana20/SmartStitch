# 工具台横改竖设计

状态：首版已实现（2026-09-28）；已完成本机 FFmpeg 样片、浏览器完整流程与交互回归，正式桌面包人工验收待做。

## 1. 需求与默认方案

用户选择一个文件夹，批量读取其中的视频。每条视频生成一条竖屏成片：底层使用同一视频的模糊版本补满竖屏画布，上层放清晰的正常视频。前景保持原始比例、完整画面和正常播放速度，背景与前景使用同一时刻的内容，保留原视频声音。

用户已明确文件夹输入、背景模糊、前景正常和先落文档。以下未指定细节作为首版默认方案：输出 9:16，默认 720×1280，可选 1080×1920；清晰前景等比居中；扫描文件夹第一层；结果默认保存到源目录下的“横改竖”子文件夹；本机批量处理。

工具保持稳定 ID `landscape-to-portrait`，位于超分之后。普通用户和管理员均可使用，不依赖创建任务页当前配置。

## 2. 画面规则

图层从下到上：

```text
┌────────────────────┐
│ 同帧视频的模糊背景 │
│                    │
├────────────────────┤
│ 清晰完整的横屏视频 │ ← 等比缩放、水平与垂直居中
├────────────────────┤
│                    │
│ 同帧视频的模糊背景 │
└────────────────────┘
       720×1280
```

- **背景**：将原视频等比放大至覆盖整个竖屏画布，居中裁掉超出的部分，再做高斯模糊。只有背景允许裁切；不得拉伸变形、使用固定截图或单色背景替代。
- **前景**：将原视频等比缩放至完整装入画布的最大尺寸，不额外缩小，不裁切，不模糊，不加边框。缩放尺寸按编码要求取偶数，并使比例误差最小。
- **示例**：1920×1080 横屏输入，前景约为 720×405（实际尺寸按偶数取整），居中放在 720×1280 的竖屏画布上；上下空余部分显示模糊背景。
- **同步**：前景、背景从一次解码的画面分成两路，共享时间戳，避免运动时错位。视频长度、播放速度及原始音画相对偏移保持不变。
- **方向**：开始任务后，逐文件按旋转元数据和像素宽高比确定显示比例。渲染统一处理显示方向与方形像素，再分路；输出清除已经应用的旋转标记，避免播放器再次旋转。
- **横屏判断**：按显示宽度大于显示高度判断。正方形、竖屏素材显示“跳过：不是横屏视频”，不阻止同批横屏素材处理。

模糊默认值以 720×1280 为基准：`sigma=20`、`steps=2`；1080×1920 使用 `sigma=30`，保持相近的相对模糊效果。前景不经过模糊滤镜。暂不增加模糊强度、前景位置、画布比例、边框和视觉去重配置项。

现有[视觉去重模糊背景设计](./18-视觉去重边框与模糊背景设计.md)处理的是已归一化画面的缩小前景。本工具直接处理源横屏视频，必须先按源显示比例分别计算背景覆盖尺寸与前景完整尺寸，不能直接套用其前景缩放参数。

## 3. 操作流程

1. 点击工具台“横改竖”卡片，进入工具台内操作面板，顶部保留“← 返回工具台”。
2. 在源视频文件夹上方，通过两个按钮选择输出分辨率：**720p · 720×1280** 或 **1080p · 1080×1920**。默认选中 720p，当前选项使用绿色主按钮样式高亮，另一项使用次按钮样式；两个按钮互斥，点击即可切换。
3. 选择或粘贴源视频文件夹路径。输出文件夹可选，留空时使用默认路径 `<源文件夹>/横改竖`；无需为每条视频分别选目录。点击“读取视频”，只扫描文件列表，展示所选输出规格、候选文件数量及逐条文件名；不读取视频内容、大小、修改时间或媒体元信息，不调用 ffprobe，也不检查全片帧时间戳。
4. 列表中有候选视频文件即可点击“开始横改竖”，空列表禁用执行按钮。开始后由后台逐个探测视频信息、判断横屏及可处理性、读取基础帧率信息，再计算缩放尺寸和输出名称并转换；当前文件检查完即处理，不等待整个目录检查完。
5. 后台顺序转换，检查期间显示“正在检查视频…”，随后展示当前转换进度。总体按候选文件数量计算，成功、失败、跳过和不可处理条目均计入已结束文件数，并展示逐条原因。支持取消剩余任务；已完成的结果保留。
6. 返回工具台、切换页面或刷新后仍可在“任务记录”查看该批次，类型显示“横改竖”。任务详情展示源目录、输出目录、所选输出规格和结果路径。

表单从上到下依次为：输出分辨率双按钮 → 源视频文件夹 → 输出文件夹（可选）→ 读取视频 / 开始横改竖 → 文件列表。分辨率使用两个按钮直接选择；窄屏空间不足时允许按钮自然换行。

修改源目录、输出目录或切换到另一输出分辨率后，旧预检立即失效，清空预检列表并禁用“开始横改竖”，需要重新读取。再次点击已选中的分辨率按钮不改变选择，也不使现有预检失效。读取期间切换选项时，旧请求的迟到响应不更新当前列表。提交时后端只再次校验文件名清单，增删或改名时提示重新读取。读取列表后替换同名视频，开始时使用当前文件内容；逐文件检查开始时记录大小和修改时间，检查结束后核对指纹，检查期间变化则记录失败。输出名称在逐文件检查通过后由后端计算。

按钮通过 `aria-pressed` 表示选中状态，组标题为“输出分辨率”，支持键盘聚焦及 Enter / Space 激活。预检与任务记录保存 `resolution`、`output_width` 和 `output_height`，转换及任务详情均使用该批次的规格；旧记录缺少规格字段时仍显示 720×1280。

读取视频仅列出文件，视频元信息及可处理性检查延后到任务启动后的后台流程；处理后的效果通过结果视频查看，暂不增加单独的实时效果预览。

任务详情沿用原有切片任务抽屉风格：标题、状态和目录使用现有页首样式，总体进度下方用四张统计卡片显示文件、成功、失败和取消数量。输出规格、编码、检查汇总及当前文件使用现有浅灰信息栏，避免用大字号正文堆叠状态。取消按钮全宽；任务结束后的删除入口右对齐。逐文件结果使用两位序号、紧凑描述、状态标签和细进度条，错误在对应条目下方展示。复用 `slice-job-stats`、`slice-encoder-summary`、`record-delete-zone`、`item-row` 和 `mini-progress`，字号、配色、圆角和窄屏布局与切片详情保持一致。


## 4. 扫描与输出约定

| 项目 | 首版规则 |
| --- | --- |
| 扫描范围 | 所选目录第一层，不递归子目录 |
| 输入扩展名 | MP4、MOV、M4V、MKV，大小写不敏感；开始后逐文件使用 ffprobe 验证视频流 |
| 排序 | 按文件名稳定排序，保证预检与执行顺序一致 |
| 排除 | 隐藏文件、`._` 伴生文件、临时文件和本工具输出文件 |
| 默认输出目录 | `<源文件夹>/横改竖`，执行时创建，预检不创建目录 |
| 输出名称 | `<原文件名不含扩展名>_横改竖.mp4` |
| 同名处理 | 已有目标及同批同名不同扩展名输入，依次追加 `_2`、`_3`，不覆盖、不凭文件名判定已处理 |
| 视频规格 | 默认 720×1280，可选 1080×1920；9:16、H.264、`yuv420p`、MP4，便于常用播放器预览 |
| 帧率 | 使用 `-fps_mode passthrough` 保留源帧时间戳，不统一转为 30fps；不逐帧预检或提前拒绝 VFR，恒定与可变帧率样片均验证转换结果 |
| 音频 | 保留第一条有效音轨，转 AAC；无音频输入保持无音频，不生成静音轨 |
| 原文件 | 保留完整，不改名、不移动、不覆盖 |

本工具生成文件名使用保留后缀 `_横改竖` 及其数字后缀；扫描时排除这些名称，并在面板提示。默认输出子目录也因不递归而自然排除。

首版普通 SDR、单视频轨素材优先支持；损坏文件、无视频流、无法解析的旋转、HDR、隔行和多视频轨素材在开始后的逐文件检查中标明不可处理及原因。透明通道、字幕和附加数据轨不纳入输出保留范围，任务详情显示相应提示。音频多轨时提示仅保留第一条。

执行前确认目录可读、输出可写及基本可用空间；自选输出目录与源目录相同时，仍使用独立结果名称。输出路径由后端计算，不接受前端任意指定逐文件目标。

## 5. 处理与任务设计

```text
只列出视频文件 → 提交固定文件名清单
  → 逐文件 ffprobe 基础信息读取及横屏判断
  → 计算缩放尺寸与输出名称 → 解码、统一显示方向与像素比例
  → split
      ├─ 背景：等比覆盖 → 居中裁切 → 高斯模糊
      └─ 前景：等比完整缩放
  → 前景居中叠加背景 → 视频编码并合入源音频
  → 临时 MP4 → 输出校验 → 发布结果
```

- 使用现有 FFmpeg/ffprobe 运行与进度读取方式，管线流式处理，不把所有帧导出成图片。首版本工具内一次执行一个批次，逐条转换。
- 视频编码优先使用 `h264_videotoolbox`：Apple Silicon 上检测 FFmpeg 是否提供该编码器，使用质量参数 65、High profile、yuv420p，并设置 `-allow_sw 0`，禁止编码器内部静默软编。检测不可用时使用 `libx264`、CRF 18、preset medium。输出启用 faststart；缩放、模糊和叠加仍由 CPU 滤镜处理。
- 编码器存在不代表一定能创建硬编会话。硬编执行或输出校验失败时，记录原因、清理临时输出并重置当前文件进度，使用 libx264 从头重试一次；同批次后续文件直接使用软编并保留回退原因。软编仍失败则记录单文件失败并继续；取消、退出或源文件变化不触发软编重试。
- 新策略在后端更新并重启后用于新建任务；已在旧进程中运行的任务继续按原策略完成。历史记录按保存的实际编码器展示。
- 文件先写入输出目录内唯一临时文件。完成后检查可解码、所选输出宽高、视频时长、音频存在性及容器已有的帧数信息；时长容差为两帧或 0.1 秒中的较大值。目标若被其他进程占用，重新分配后缀，再发布，禁止覆盖。
- 单文件失败记录错误、清理临时文件并继续。批次状态区分全部成功、部分失败、全部失败和取消；跳过项不算成功输出。
- 当前文件进度根据已处理时间与源时长估算，总体同时显示已结束文件数/候选文件数，全部输出校验结束前不显示成功完成。
- 取消时终止当前 FFmpeg、清理未完成输出，未开始项标记取消；已发布输出保留。
- 任务清单和状态持久化至本机任务存储。应用重启后保留历史，未结束任务标记“已中断”，不自动恢复。桌面退出统计和关闭流程纳入该任务管理器。
- 运行中任务不能删除；删除已结束任务记录不删除输出视频。

## 6. 接口与实现落点

所有接口沿用现有登录会话校验。以下接口已接入。预检响应的 `id` 用作提交请求的 `preview_id`。

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/tools/landscape-to-portrait/preview` | 接收 `source_directory`、可选 `output_directory` 和 `resolution`（`720p` / `1080p`，默认 `720p`），仅返回文件列表标识、目录、文件名/路径、所选输出规格及候选数量；不探测视频内容 |
| `POST /api/v1/tools/landscape-to-portrait` | 接收 `preview_id`；再次校验文件名清单，返回批次 ID 并启动后台逐文件检查与转换；成功提交后该预检标识失效 |
| `GET /api/v1/tools/landscape-to-portrait/jobs` | 查询批次，供统一任务记录展示 |
| `GET /api/v1/tools/landscape-to-portrait/{id}` | 查询批次和逐文件状态、进度、结果及错误 |
| `POST /api/v1/tools/landscape-to-portrait/{id}/cancel` | 取消当前处理和剩余文件 |
| `DELETE /api/v1/tools/landscape-to-portrait/{id}` | 删除已结束记录，保留视频文件 |

批次 `encoding` 保存计划编码器、硬编能力检测结果、实际编码器汇总、回退条目数与原因；逐文件保存 `planned_video_encoder`、`actual_video_encoder`、`encoder_fallback_reason` 和 `encoder_attempts`。任务详情按实际记录显示 VideoToolbox / libx264；尚未开始时明确标注计划编码器，旧软编记录缺少字段时仍显示 libx264。

文件列表清单仅包含文件名、源路径、待处理状态和所选输出宽高；保留原 `preview_id` / `pending_count` 接口字段，其中待处理数量表示候选文件数，读取阶段跳过和不可处理数量均为 0。大小、修改时间、显示宽高、帧率、时长、音频、输出路径和检查结果在开始后逐文件补充，`current_phase` 区分 `inspecting` 和 `rendering`；后端保管清单，前端不能修改结果来注入额外源文件。

| 位置 | 已接入内容 |
| --- | --- |
| `frontend/app.js` | 为现有卡片接入面板；分辨率双按钮位于源目录上方，负责互斥选择、高亮和预检失效；目录选择、预检、提交、取消及任务记录类型/详情 |
| `frontend/index.html`、`frontend/styles.css` | 复用工具台容器、路径选择和进度样式，按实际变更更新缓存版本 |
| `frontend/assets/tools/landscape-to-portrait.svg` | 封面示意为横屏 16:9 → 竖屏 9:16 |
| `smartstitch/landscape_to_portrait.py`（新增） | 扫描、尺寸计算、滤镜生成、执行、进度、清理与输出校验 |
| `smartstitch/video_encoding.py` | 切片和横改竖共用的硬编能力检测、编码器常量与参数 |
| `smartstitch/api.py` | 工具请求模型、接口和管理器生命周期接入 |

## 7. 验收标准

1. 选择含多个横屏视频的目录后，清单与实际第一层视频一致；子目录、伴生文件、本工具结果不重复读取。
2. 16:9 和非 16:9 横屏素材均按所选分辨率输出 720×1280 或 1080×1920；前景人物、文字和四角保留，画面不变形，背景补满画布。
3. 通过运动片段核对前景与背景同帧；前景清晰，只有背景模糊。带旋转元数据和非方形像素样片按显示比例处理。
4. 有声、无声样片保持对应音轨行为；24、25、30及 30000/1001 fps 样片的速度、长度和音画同步正确。
5. 混合竖屏、正方形、损坏文件时逐条解释原因，有效横屏视频仍可处理；没有候选文件时不能启动；只有竖屏或损坏文件也可提交，逐文件检查后结束，不产生结果。
6. 中文路径、空格、同名不同扩展名、已有输出和重复提交不会覆盖源文件或已有成片。
7. 单文件失败不影响后续；取消和退出应用清理临时文件，成功结果保留；刷新、返回及重启后任务记录符合约定。
8. 分辨率两个按钮位于源视频文件夹上方，默认选中 720p；切换后高亮及 `aria-pressed` 同步更新。切换到另一规格会使旧预检失效，再次点击当前规格则保留预检。预检和任务详情显示实际所选宽高，旧任务仍显示 720×1280。
9. 硬编成功、硬编执行失败或输出校验失败后软编重试、后续文件跳过重复硬编、回退原因保存与展示符合约定；取消时不继续启动软编重试。
10. 扫描/尺寸计算/命名冲突测试、实际 FFmpeg 音视频样片验收，以及工具台和任务记录交互检查通过。

首版不接入渲染集群、人物跟踪裁切、超分、文件夹拼接或项目视觉特效；这些扩展另行设计。

## 8. 首版实现与验证记录

- 工具台卡片已开放；封面更新为横屏 → 竖屏。选择文件夹、可选输出目录、预检列表和统一任务记录已接入。
- 新增本机 `portrait_jobs` SQLite 记录；支持查看、取消和删除已结束记录，退出时停止 FFmpeg，重启后未完成批次及条目标记中断。
- 已取消转换前的全片帧时间戳检查及其 120 秒等待，仅调用 ffprobe 读取基础流/容器信息（30 秒超时）。基础帧率用于时长容差估计；名义帧率与平均帧率相同时保留帧率和容器已有帧数校验，不扫描帧数。两者不同的素材不要求源、结果平均帧率及容器帧数完全相同，避免可变帧率视频在保留时间戳后被误判；仍校验时长、尺寸及音轨。
