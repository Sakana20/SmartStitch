# 素材文件名字段分隔符 `|!|` 切换设计

状态：源码、两份现用共享配置及结构化素材文件名均已切换并完成扫描验收。现有安装包尚未包含本次源码改动，需构建和分发新版本后，各设备才能使用新规则。旧任务快照中的素材绝对路径仍是历史值，重新运行历史任务前需按改名映射迁移。

本文替代《通用项目积木式文件名设计》第 4、6 节中关于 `-`、`_` 切片及旧配置兼容的方案，也替代《通用成片动态命名与素材元数据拼接设计》中依赖旧分隔符的素材解析示例。其他命名块、计划和输出规则继续适用。

## 1. 范围和原则

- `|!|` 是**素材文件名中业务字段**的唯一分隔符，按三个字符组成的完整字符串精确匹配。`|`、`!`、`-`、`_` 单独出现时均为普通字段内容。
- 不修改成片输出文件名的连接方式。积木画布中的 `-` 等自填文字仍按用户配置输出；`|!|` 只用于读取素材文件名，不自动写入成片名。
- 单字段素材名可以没有 `|!|`；没有被命名块引用的库不因缺少分隔符而失效。被引用的库必须能提供所选字段。
- 不保留旧分隔方式、旧签名或自动回退。旧文件名、旧样本和旧命名配置需要在同一次切换中处理，不能指望新代码继续识别它们。
- `|!|` 为保留序列，不得作为字段内容原样出现。若业务文字需要相近符号，改用其他字符；不做隐式转义或猜测。

示例：

```text
00006|!|周小小闹_大学宿舍_|!|谁不想在短剧里急头白脸地爽活一回|!|2027-02-28__001_pool-8_f0-1658.mp4
瑞幸|!|咖啡|!|ai1.mp4
1.mp4
```

第一行的 `_` 和标题中的 `-` 不再被拆分；四个业务字段依次为编号、达人、标题、日期。`1.mp4` 只有一个字段。

## 2. 解析协议

1. 取文件名，先去掉**最后一个扩展名**；扩展名不参与字段解析。
2. 仅当末尾符合 SmartStitch 切片后缀协议时，去掉整个后缀。普通文件名中的 `__` 必须保留，不能再使用“从第一个 `__` 截断”。单段、组合段以及重名版本后缀均需识别，例如 `__001_pool-8_f0-1769`、`__g003_pool-8_p007-009`、末尾 `-v2`。不符合协议的 `__` 属于业务字段内容。
3. 对剩余主干按字面量 `|!|` 拆分。`-`、`_`、单个 `|` 或 `!` 不触发拆分。前后端使用同一套测试样例，确保结果一致。
4. 字段值去掉首尾空白；空字段、只有空白的字段、首尾分隔符以及连续分隔符均报明确错误。不得悄悄跳过空字段而使位置偏移。
5. 完整日期 `YYYY-MM-DD` 或 `YYYYMMDD` 本来就是一个字段；日期块另按其配置校验真实日期并转换输出格式。

`|!|` 本身不构成文件名后缀；SmartStitch 的 `__...` 是独立的切片元数据标记，仍可保留。切片器代码现已保留源主干中的 `|!|`，并只追加技术后缀。实际 NAS 已通过 `|!|` 路径创建、读取、ffprobe 与重扫验证；切片器由自动化测试覆盖。

## 3. 积木式命名配置

- 样本选择器展示拆分后的完整字段，分隔符不作为可选字段。示例 `瑞幸|!|咖啡|!|ai1.mp4` 展示 `瑞幸`、`咖啡`、`ai1`。
- 素材字段块保存来源库和从零开始的**字段序号**。样本文件名用于展示和校验，不把样本值固化成输出值。
- 新规则不再使用由 `N_T-T-D`、`T-T-T` 等旧字符模式生成的 `signature`。需要区分同库多种结构时，配置明确记录字段总数及对应字段序号；扫描时精确匹配该结构，找不到或出现多种可能时标为命名异常，不猜测。
- 同一素材库被多个块引用时，各块仍取同一条实际抽中的素材。扫描、草稿预览、计划生成和正式输出必须共用后端解析结果；前端样本展示与后端结果一致。
- 被命名块引用的已启用、正权重素材若字段不足、结构不匹配或目标字段为空，按现有规则标为异常并排除抽取；无可用候选时阻止生成。未被引用的库只做媒体有效性检查。

旧配置中 `variants[].sample_name`、`signature`、`token_index` 与旧文件名绑定，切换时**重建**为新字段规则；不运行时转换，不保留旧样本分支。红果项目的编号、达人、标题、日期位置需按新文件名重建；闪购前贴的品牌、品类位置也需重建。旧 `source_metadata.pattern` 如仍启用，固定要求编号、达人、标题、日期四个 `|!|` 字段，正则也必须改为识别该结构；不得继续以 `_`、`-` 作为业务分隔符。

### 3.1 当前共享配置的加载错误与重建值

切换前红果共享配置有两个旧命名块，分别保存 `token_index: 2`（达人）和 `token_index: 6`（日期），且样本名使用 `_`、`-` 分字段。新模型要求 `field_count` 和 `field_index`，所以当时加载配置会产生四条缺少字段的校验错误。现已重建配置并消除该错误。

红果剧情库的目标主干为 `编号|!|达人|!|标题|!|日期`。两个块都要把 `sample_name` 更新为真实改名后的样本，并分别设置：

```yaml
# 达人块
variants:
  - sample_name: '00002|!|主持人于欢|!|重生之红果编剧在我手上|!|2027-07-31__014_pool-8_f543-1766.mp4'
    field_count: 4
    field_index: 1
# 日期块使用同一新样本，field_count: 4，field_index: 3
```

闪购前贴的目标主干为 `品牌|!|品类|!|文案`。品牌块为 `field_count: 3, field_index: 0`，品类块为 `field_count: 3, field_index: 1`。原库还有四字段文件：改名后如继续启用，两个块都需要各加一条 `field_count: 4` 的样本规则，字段序号仍分别为 `0` 和 `1`。规则按字段总数精确匹配，不能只配置三字段样本就假定四字段文件会继续可用。

新配置**不再保留** `signature`、`token_index`。旧 `sample_name`、旧素材路径和旧分隔格式也不得留在当前共享配置中。只重建命名块但不改名，扫描时仍会把旧文件名视为字段数量不匹配；只改名但不重建命名块，配置仍无法加载。

## 4. 文件改名与配置引用

后续批量改名以每个项目的**实际共享配置**和素材目录为输入，先输出逐文件的旧名、新名、来源库、字段拆分结果、配置引用和目标冲突清单。业务字段中原有的 `-`、`_` 可原样保留；只把确实表示字段边界的字符替换为 `|!|`，不能全局字符串替换。技术后缀 `__...` 保持不变。

改名同时更新当前共享配置中的素材路径、显式启停和权重条目；路径生成的素材 ID、缓存键也会变化，须在重新扫描后核对。历史成片快照、任务清单若需要按旧路径重新运行，应单独迁移或保留明确的映射记录，不应无声失效。目标名重复、路径超过限制、文件不存在或 NAS 不支持目标字符时停止切换。

## 5. 无兼容切换顺序

新解析代码与旧素材文件名不能长期混用，按一次受控切换执行：

1. 盘点所有项目、所有库、当前配置、切片输出和历史引用；生成改名映射、配置重建结果与回滚清单。确认 `|!|` 在实际 NAS 路径、FFmpeg/ffprobe 与其他需要访问素材的设备上可用。
2. 暂停新的扫描、切片和生成任务，等待运行中任务结束；备份共享配置并记录文件名映射与内容哈希。
3. 启用已实现的前端、后端和切片器新版本；按映射改名素材、更新当前配置的路径并重建命名块。三项必须作为同一次切换交付：仅改文件名不能修复当前 `field_count` / `field_index` 校验错误；仅改配置会让旧文件名扫描失败。切换期间不接受生成请求。
4. 对每个项目逐库重扫，核对文件数、启用数、权重、命名覆盖率、预览字段和实际成片名。通过后恢复生成；任一步失败则按映射与备份整体回滚，不做旧规则运行时兼容。

## 6. 验收

- `00006|!|周小小闹_大学宿舍_|!|标题-甲|!|2027-02-28__001_pool-8_f0-1658.mp4` 能提取完整达人、标题及日期；字段内部 `_`、`-` 不改变字段序号。
- `瑞幸|!|咖啡|!|ai1.mp4` 提取品牌与品类；`1.mp4` 只提供第 1 个字段，选择第 2 个字段时报错。
- `甲|!||!|乙.mp4`、`|!|甲.mp4`、`甲|!|.mp4` 因空字段报错。
- 文件主干中含非切片用途的 `__` 时不截断；真实单段、组合段及 `-v2` 切片后缀正确剥离。新切片再次入库后字段仍保持 `|!|`。
- 改名并重建配置后，红果与闪购项目的扫描、计划预览、正式命名和清单字段一致；旧分隔格式不被解析器自动接受。
- 红果共享配置的达人、日期块可用 `field_count: 4` 与字段序号 `1`、`3` 正常加载；闪购前贴三字段、四字段样本分别配置后均覆盖应启用的素材。配置加载不得出现缺少 `field_count` / `field_index` 的校验错误。
- 每个受影响库的文件总数在改名前后不变，当前配置的显式权重与停用状态不丢失，目标路径无冲突。
