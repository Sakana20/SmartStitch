# 简单模式与高级模式设计

## 1. 目标

配置管理分为三个层级：

1. **简单模式**：默认入口，用大卡片展示业务含义，只开放常用设置。
2. **高级模式**：原“可视化配置”，保留素材目录、编码、扫描、响度和批处理等全部参数。
3. **YAML 专家模式**：直接编辑完整配置文本。

简单模式只修改用户可见字段，保存时以现有完整配置为基础合并修改，因此不会重置隐藏的高级参数。

## 2. 简单模式结构

简单模式采用大卡片和问答式标题，按业务流程组织，不强行把技术参数塞入固定步数。桌面端第一排将项目信息与风险提示语并列展示，各占一半宽度；拼接顺序、视觉去重与成片效果保持全宽。移动端自动恢复单列：

- 项目信息：项目名称、项目类型和目录健康状态。启用状态只在高级模式管理。
- 视频拼接顺序：先展示“每个启用视频库随机取一条 → 按列表顺序拼接 → 输出成片”的生成逻辑，再显示自动步骤编号、视频库名称、素材数量、实际文件夹名和“参与拼接”开关；支持拖拽、上下移动、添加和删除。单击文件夹名会使用 macOS Finder、Windows 资源管理器或 Linux 文件管理器打开对应目录。简单模式关闭开关时将视频库设为停用；高级模式继续保留“必需 / 可选 / 停用”的详细选择。
- 风险提示语图片：开关、识别状态、显示范围、复制受管目录位置和直接更换图片。
- 视觉去重：只显示总开关、轻度/标准/强化效果预设、边框开关和受管项目的选择/更换边框；不显示模糊数值、Alpha、编码、循环和缩放策略。
- 命名设置：通用项目使用独立全宽卡片，简单模式展示启用开关、产品、利益点、可选序号起点和只读文件名预览。
- 输出设置：位于其他业务卡片之后，通过大选项选择竖屏、横屏、方形，快速、推荐、高清画质，以及允许重复、尽量避免、完全不重复；同时保留音量均衡开关。

简单模式不直接展示源目录、视频库物理目录和输出路径等技术信息；这些内容仍可在高级模式查看和编辑。

## 3. 隐藏的高级字段

简单模式不显示但完整保留以下设置：

- 配置 ID、schema、稳定素材池 ID和原始 timeline。
- 扩展名、默认权重、图片持续时长和精确素材路径。
- 编码器、像素格式、CRF/VBR、码率、采样率、声道和 Faststart。
- LUFS、LRA、dBTP 等响度参数。
- 随机算法、种子、批处理限制和扫描过滤规则。
- 风险图精确坐标、缩放算法和透明度。
- 视觉去重的前景精确比例、高斯模糊参数、背景亮度、边框模式和文件路径、缩放与循环策略、透明度、Alpha 模式及媒体预检详情。
- 成片命名模板、素材类别范围、SmartStitch 切片后缀处理、文件名解析正则、日期格式、达人/日期合并规则和重名后缀。

通用项目的产品和利益点可同时出现在简单模式和高级模式，但必须绑定同一份结构化草稿。简单模式保存时不得重建命名配置对象，以免覆盖高级解析规则。完整界面规范见[《通用成片动态命名与素材元数据拼接设计》](./16-成片动态命名与素材元数据拼接设计.md)。

视觉去重也必须绑定同一份结构化草稿。高级数值不匹配预设时，简单模式显示“自定义（高级设置）”，不自动重置；只有用户主动选择预设时才更新对应的缩放和模糊字段。完整协议见[《视觉去重边框与高斯模糊背景设计》](./18-视觉去重边框与模糊背景设计.md)。

## 4. 风险提示语图片替换

受管项目可在简单模式直接选择 PNG、JPG、WEBP 或 BMP 图片，最大 20 MB。系统会：

1. 校验配置版本，避免覆盖其他窗口的新修改。
2. 使用 ffprobe 验证图片可读。
3. 将原风险图移动到 `.smartstitch/overlay-backups/`，不直接删除。
4. 把新图片放入项目的“风险提示语图片”目录。
5. 设置为必需叠图，并继续由扫描器按唯一图片规则识别。

通用模式只显示“整条视频”和“指定时间”；淘宝闪购继续支持主要内容和利益点部分。

## 5. 模式切换

- 每次打开配置管理都默认进入简单模式，不沿用上一次关闭时所在的高级或 YAML 模式。
- 从高级模式切到简单模式时，先收集未保存的高级表单内容，再基于同一份草稿渲染简单模式。
- 每个配置继续分别记住高级区域折叠状态和各编辑器滚动位置。

## 6. 新功能的前端架构约束

后续包括视觉去重在内的新配置功能，必须沿用现有原生前端架构增量开发：

- 简单功能增加到 `renderSimpleConfig()` 和 `bindSimpleConfigControls()`。
- 复杂参数增加到 `renderVisualConfig()`，使用现有 `configInput/configSelect/configSwitch` 与 `data-config-path` 机制。
- 所有模式共用 `state.configDraft`、`setConfigMode()`、`currentStructuredDraft()`、`collectVisualConfig()` 和现有保存接口。
- 扫描状态继续使用 `state.scan` 和 `scanAssets()`，文件替换继续使用统一 `api()`、编辑租约、配置哈希和 `refreshConfigEditor()` 流程。
- 复用当前卡片、大选项、表单、开关、toast、折叠区和响应式样式。

不得为单个新功能引入前端框架、状态库、组件库、新打包链、独立 SPA、iframe、新路由页面或第二套配置草稿。新功能如果在现有边界下难以实现，应先扩展现有 helper 或数据模型，不得自创平行架构。
