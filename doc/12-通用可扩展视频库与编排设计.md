# SmartStitch 通用可扩展视频库与编排设计

## 1. 背景与目标

当前 SmartStitch 的受管视频库围绕淘宝闪购业务创建，默认包含“前贴、引子、利益点、结尾、尾帧”等固定素材类别。虽然利益点已经可以增删和排序，但其他类别仍带有固定业务语义，无法满足完全不同的视频组合流程。

本需求新增一套**通用可扩展模式**：用户创建项目后，可以自行新增任意数量的视频库，为每个视频库命名、配置素材目录、增删视频库，并通过拖拽决定最终拼接顺序。

核心原则：

- 淘宝闪购现有配置、目录、接口和生成结果保持不变。
- 通用模式不预设“前贴、引子、利益点、结尾、尾帧”。
- 每个自定义视频库是一个独立素材池，每条成片从中抽取一个素材。
- 拼接顺序由用户拖拽后的顺序决定，不由名称或编号推断。
- 新能力通过独立模式和新协议扩展，不自动改写淘宝闪购配置。

本文档是讨论稿，确认后再进入代码实现。

## 2. 术语约定

为避免“视频库”同时指整个磁盘目录和单个素材池，本文采用以下术语：

- **项目库**：一次创建得到的受管根目录，包含原始视频、多个视频库、成片输出、工作记录和 `.smartstitch` 元数据。
- **视频库**：用户在项目库内创建的一个独立素材池，例如“开场”“产品展示”“用户证言”“行动引导”。界面使用这个名称。
- **素材池**：视频库在后端和配置协议中的含义；内部稳定标识使用 `pool_<n>`。
- **拼接顺序**：一条成片依次抽取和渲染各视频库的顺序，是生成流程的唯一顺序依据。
- **业务模板**：创建项目库时选择的模式。首期包括“淘宝闪购”和“通用自定义”。

如果最终希望界面也避免歧义，可把单个“视频库”改称“片段库”或“素材库”；这是本文末尾的待确认项。

## 3. 模式隔离与兼容策略

### 3.1 淘宝闪购模式

淘宝闪购继续使用当前逻辑：

- 继续识别 schema 1 和 schema 2 配置。
- 继续使用 `pre_roll`、`hook`、`benefit_<n>`、`ending`、`end_card`。
- 引子、结尾、至少一个利益点等必备约束不变。
- “添加利益点”、风险提示语图片、产品标签匹配和当前目录结构不变。
- 当前计划、权重、去重、渲染、清单及时间线切片行为不变。
- 现有 YAML、视频库目录和 `.smartstitch/library.json` 不自动迁移。

旧配置中没有模式字段时，一律按淘宝闪购兼容模式加载，避免升级后改变现有结果。

### 3.2 通用自定义模式

通用模式采用独立的 `workflow_type: generic`，允许任意 `pool_<n>` 素材池。通用模式不再校验引子、利益点和结尾等淘宝闪购专属规则，只校验通用拼接规则。

建议只有新建通用项目库时才写入新协议；首期不提供“一键把淘宝闪购配置转成通用配置”，防止迁移改变现有生成结果。

### 3.3 创建入口

“新建视频库”向导第一步增加业务模板选择：

```text
选择创建方式

┌─────────────────────────┐  ┌─────────────────────────┐
│ 淘宝闪购                │  │ 通用自定义              │
│ 保留现有标准目录和规则  │  │ 自己创建视频库和顺序    │
└─────────────────────────┘  └─────────────────────────┘
```

- 默认仍选中“淘宝闪购”，保证现有用户操作路径不变。
- 选择“淘宝闪购”后，后续向导和创建结果完全沿用当前实现。
- 选择“通用自定义”后，只创建通用项目骨架，不自动创建固定业务视频库。

## 4. 通用模式的用户流程

1. 用户点击“新建视频库”。
2. 选择“通用自定义”。
3. 填写配置 ID、项目名称、项目文件夹名和保存位置。
4. 系统创建一个尚未包含业务视频库的通用项目库。
5. 页面进入“视频库编排”区，引导用户点击“添加视频库”。
6. 用户依次创建“开场”“场景展示”“产品特写”“行动引导”等视频库。
7. 系统为每个视频库建立独立素材目录。
8. 用户拖拽视频库卡片决定拼接顺序。
9. 用户把素材放入目录，或在时间线切片页把审核片段分类进入相应视频库。
10. 预检通过后，系统按当前顺序从每个启用的视频库抽取素材并生成成片。

通用项目允许暂时没有任何视频库，方便用户先建立项目再设计流程；但空项目不能预览或开始生成。

## 5. 页面与交互设计

### 5.1 视频库编排区

通用配置的高级配置页新增“视频库编排”主区域：

```text
视频库编排                                      ＋ 添加视频库
拖动卡片调整最终拼接顺序

┌──────────────────────────────────────────────────────────┐
│ ⠿  01  开场              必需   12 个素材   编辑  删除 │
│        视频库/pool_1                                   │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ ⠿  02  场景展示          必需    8 个素材   编辑  删除 │
│        视频库/pool_2                                   │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ ⠿  03  行动引导          可选    4 个素材   编辑  删除 │
│        视频库/pool_3                                   │
└──────────────────────────────────────────────────────────┘
```

每张卡片显示：

- 拖拽手柄和当前顺序。
- 用户可编辑的显示名称。
- 必需、可选或停用状态。
- 当前有效素材数量和预检状态。
- 受管目录的相对路径。
- 编辑、打开目录和删除操作。

### 5.2 添加视频库

点击“添加视频库”打开轻量弹窗，首期包含：

1. 视频库名称：必填，例如“开场”。
2. 使用方式：必需、可选或停用；默认“必需”。
3. 默认素材权重：默认 `1`。
4. 说明：可选，只用于界面说明和清单快照。

受管通用项目中的目录由系统分配，用户不直接填写目录：

```text
视频库/pool_1
视频库/pool_2
视频库/pool_3
```

显示名称变化时不重命名目录。这样可避免因中文名称修改、重名或文件占用导致路径失效。

添加成功后，新卡片默认放在列表末尾。用户可以立即拖到任意位置。

### 5.3 编辑视频库

首期允许修改：

- 显示名称。
- 说明。
- 使用方式。
- 默认权重。
- 支持的视频扩展名；普通用户使用默认值，高级配置中可编辑。

稳定标识 `pool_<n>` 和受管目录默认只读，不随名称修改。外部素材配置仍可在高级模式中选择其他目录，但不会被系统自动创建或删除。

### 5.4 拖拽排序

- 用户只能从拖拽手柄开始拖动，避免点击卡片时误排序。
- 放下卡片后立即更新拼接顺序并原子保存。
- 拖动只修改顺序，不修改视频库 ID、目录、素材、权重或历史清单。
- 支持键盘“上移/下移”，保证不使用鼠标也能排序。
- 连续拖动使用最后一次有效顺序；保存失败时恢复到服务端顺序并提示原因。
- 多窗口同时编辑时提交当前配置哈希；哈希冲突返回 `409`，不静默覆盖另一窗口的修改。

### 5.5 删除视频库

删除前必须显示：

- 视频库名称。
- 受管目录完整路径。
- 当前目录内素材数量。
- “只删除编排配置，不删除目录和素材”的明确说明。

确认后，系统从配置和拼接顺序中移除该视频库，但保留磁盘目录与全部文件。通用项目允许删除最后一个视频库；删除后进入空项目状态，预览和生成按钮禁用。

如果未来需要清理遗留目录，应设计独立“项目库整理”功能，不能复用删除视频库操作。

## 6. 配置协议建议

建议通用模式使用 schema 3，并尽量复用现有 `sources`、`timeline`、权重和输出结构：

```yaml
schema_version: 3
workflow_type: generic

id: generic-product-demo
name: 通用产品演示
enabled: true
description: 通用自定义视频组合
source_root: "/绝对路径/通用产品演示"

# 唯一权威拼接顺序；拖拽只修改此列表。
timeline:
  - pool_1
  - pool_2
  - pool_3

sources:
  pool_1:
    label: "开场"
    description: "吸引注意力的前 3 秒"
    mode: required
    directory: "视频库/pool_1"
    extensions: [".mp4", ".mov", ".mkv"]
    default_weight: 1
    items: []

  pool_2:
    label: "场景展示"
    description: "展示使用场景"
    mode: required
    directory: "视频库/pool_2"
    extensions: [".mp4", ".mov", ".mkv"]
    default_weight: 1
    items: []

  pool_3:
    label: "行动引导"
    description: "可选的收尾行动引导"
    mode: optional
    directory: "视频库/pool_3"
    extensions: [".mp4", ".mov", ".mkv"]
    default_weight: 1
    items: []

# 输出、随机、批处理和扫描规则继续复用现有结构。
randomization:
  mode: quota_shuffle
  duplicate_policy: best_effort

output:
  directory: "/绝对路径/通用产品演示/成片输出"
  width: 720
  height: 1280
  fps: 30

batch:
  default_count: 10
  concurrency: 2
```

### 6.1 为什么继续使用 `sources + timeline`

- 当前扫描、权重、计划、渲染和清单已经围绕这两个结构工作。
- `sources` 负责视频库定义，`timeline` 负责顺序，职责清楚。
- 淘宝闪购可以继续使用原有固定键，通用模式只需放宽为 `pool_<n>`。
- 不需要再维护一套完全不同的生成配置格式。

### 6.2 稳定标识规则

- 通用视频库 ID 必须匹配 `^pool_[1-9][0-9]*$`。
- `n` 单调递增，删除后不回收，避免旧清单中的 `pool_2` 指向后来创建的另一个视频库。
- 显示名称允许重复，但界面应提示，不建议重复；内部始终用稳定 ID 区分。
- `timeline` 不允许重复 ID。首期同一个视频库在一条成片中最多出现一次。
- 每个未停用的视频库必须且只能在 `timeline` 出现一次。

### 6.3 通用校验规则

- 空项目可以保存，但不能预览或生成。
- 开始生成时至少存在一个非 `disabled` 视频库。
- `required` 视频库必须至少有一个启用、有效且权重大于 `0` 的素材。
- `optional` 视频库有可用素材时抽取一个，没有可用素材时跳过。
- `disabled` 视频库保留配置和目录，但不参与预览与生成。
- `timeline` 不得包含未知视频库或重复视频库。
- 首期建议最多允许 50 个视频库，避免误操作导致预览和 FFmpeg 输入无限增长。

## 7. 通用项目目录结构

选择“通用自定义”后创建：

```text
<用户选择的保存位置>/
└── <项目名称>/
    ├── 原始视频/
    ├── 视频库/
    │   ├── pool_1/
    │   ├── pool_2/
    │   └── pool_3/
    ├── 未归类/
    ├── 成片输出/
    ├── 工作记录/
    │   ├── 切片清单/
    │   └── 生成清单/
    └── .smartstitch/
        └── library.json
```

刚创建时 `视频库/` 可以为空；每次添加视频库时再创建对应 `pool_<n>/`。

淘宝闪购现有的 `切片素材/前贴`、`切片素材/引子`、`切片素材/利益点` 等目录保持原样，不改名、不移动。

### 7.1 通用项目元数据

通用项目建议使用新的布局版本：

```json
{
  "layout_version": 2,
  "workflow_type": "generic",
  "library_id": "bcbf9da3-14dd-45f3-bc6a-b842d42b6206",
  "created_for_config_id": "generic-product-demo",
  "display_name": "通用产品演示",
  "next_pool_number": 4,
  "paths": {
    "originals": "原始视频",
    "pools": "视频库",
    "unclassified": "未归类",
    "outputs": "成片输出",
    "records": "工作记录"
  }
}
```

淘宝闪购继续读取 `layout_version: 1`；系统根据布局版本和 `workflow_type` 选择对应规则，不原地升级旧标记。

## 8. 计划、权重与渲染

### 8.1 组合计划

通用计划器按 `timeline` 遍历非停用视频库：

1. 对每个视频库独立生成权重序列。
2. `required` 视频库每条计划选择一个素材。
3. `optional` 视频库有候选时每条计划选择一个素材，无候选时整段跳过。
4. 按 `timeline` 顺序组合成完整成片计划。

素材权重只在同一个视频库内部比较，不跨视频库归一化。

### 8.2 去重

- 通用模式的核心组合签名是本条成片实际选择的全部 `pool_<n>` 素材序列。
- `best_effort` 尽量减少完整序列重复，同时保持各视频库的权重次数。
- `strict` 的理论组合数是所有非空必选视频库候选数的乘积；有素材的可选视频库也纳入实际组合签名。
- 任一必选视频库为空时禁止生成，并明确显示视频库名称和 ID。

### 8.3 渲染

- 渲染器不识别“开场”“结尾”等名称，只严格按 `timeline` 顺序拼接计划中的素材。
- 输入素材继续按输出配置统一分辨率、帧率、像素格式、音频规格和响度。
- 任意视频库顺序改变后，只影响新预览和新任务；运行中的任务继续使用启动时冻结的配置快照。
- 任务清单必须同时记录视频库稳定 ID、当时的显示名称、顺序和素材路径。

## 9. 风险提示语图片与静态图片

为了保证首期范围可控，建议：

- 通用视频库首期只抽取视频素材，不把普通图片作为任意时间线节点。
- 通用模式仍可复用配置级风险提示语图片，但首期只支持 `full` 和 `custom` 时段。
- 淘宝闪购继续支持现有 `main`、`benefits` 等业务时段，行为不变。
- 如果后续需要通用静态图片节点，再给视频库增加 `media_type: video | image | mixed` 和图片持续时长，单独设计预览及音轨规则。

这样可以避免首期把尾帧图片的特殊处理扩散到所有自定义视频库。

## 10. 时间线切片与入库

通用项目选中后，时间线审核页的分类菜单不再显示固定类别，而是按当前拼接顺序动态显示：

```text
未归类
01 · 开场
02 · 场景展示
03 · 行动引导
```

- 分类值保存稳定 ID，例如 `pool_2`，不保存易变的显示名称。
- 入库目标由当前配置和项目标记共同解析到 `视频库/pool_2`。
- 拖动编排顺序后，分类菜单顺序同步变化，但已经入库的文件路径不变化。
- 视频库被删除后，新的切片任务不能再选择它；已经保存的历史清单仍显示删除时的名称和路径快照。
- 提交切片任务时继续校验审核版本、配置哈希、目录边界和目标健康状态。

## 11. 数据与清单

通用任务的 `manifest.json` 建议继续使用动态 `selections`：

```json
{
  "workflow_type": "generic",
  "timeline": ["pool_1", "pool_2", "pool_3"],
  "pool_labels": {
    "pool_1": "开场",
    "pool_2": "场景展示",
    "pool_3": "行动引导"
  },
  "selections": {
    "pool_1": "/项目/视频库/pool_1/a.mp4",
    "pool_2": "/项目/视频库/pool_2/b.mp4",
    "pool_3": "/项目/视频库/pool_3/c.mp4"
  }
}
```

CSV 清单按任务快照中的 `timeline` 动态展开列，列名建议同时包含顺序和稳定 ID，例如 `01_pool_1_开场`。显示名称变化不回写历史清单。

## 12. 接口设计草案

现有接口保留，新增或扩展：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/libraries` | 增加可选 `workflow_type`；缺省仍创建淘宝闪购项目库 |
| `POST` | `/api/v1/configs/{config_id}/pools` | 分配稳定 ID、创建目录并追加视频库 |
| `PATCH` | `/api/v1/configs/{config_id}/pools/{pool_id}` | 修改名称、说明、模式和默认权重 |
| `DELETE` | `/api/v1/configs/{config_id}/pools/{pool_id}` | 从配置移除，保留目录和素材 |
| `PUT` | `/api/v1/configs/{config_id}/timeline` | 原子保存拖拽后的完整顺序 |
| `GET` | `/api/v1/libraries/by-config/{config_id}/slice-targets` | 淘宝闪购返回固定类别，通用模式返回动态视频库 |

添加视频库请求示例：

```json
{
  "label": "场景展示",
  "description": "展示真实使用场景",
  "mode": "required",
  "default_weight": 1,
  "current_config_hash": "<sha256>",
  "client_request_id": "<uuid>"
}
```

排序请求提交完整顺序，不能只提交“从 A 移到 B”，以便服务端直接校验最终状态：

```json
{
  "timeline": ["pool_3", "pool_1", "pool_2"],
  "current_config_hash": "<sha256>"
}
```

新增视频库操作通过请求 ID 保持幂等；编辑、删除和排序提交完整目标状态。所有写操作对同一项目库串行化，并校验配置哈希；配置哈希不一致时返回 `409`。

## 13. 异常与恢复

| 场景 | 处理方式 |
|---|---|
| 创建通用项目后尚无视频库 | 允许保存，显示引导；禁止预览和生成 |
| 添加视频库时目录已存在 | 不覆盖内容，可安全关联并提示已有素材数量 |
| 添加目录成功但配置保存失败 | 只回收本次新建且仍为空的目录；非空目录保留 |
| 拖拽保存时配置已被其他窗口修改 | 返回 `409`，恢复服务端顺序并提示刷新 |
| 删除视频库 | 删除配置引用，目录和素材原样保留 |
| 删除最后一个视频库 | 进入空项目状态，不删除项目库 |
| 必需视频库没有有效素材 | 预检失败，指出显示名称、稳定 ID 和目录 |
| 外接盘断开 | 不在其他位置创建同名目录，明确提示卷未挂载 |
| 项目标记损坏 | 禁止自动建目录，提供只读诊断和修复计划 |
| 淘宝闪购旧配置 | 始终走原规则，不自动变成通用配置 |

## 14. 验收标准

1. 新建向导可选择“淘宝闪购”或“通用自定义”，默认仍为淘宝闪购。
2. 使用淘宝闪购模式创建、编辑、扫描、预览、生成和切片时，行为与改造前一致。
3. 新建通用项目库时不自动创建前贴、引子、利益点、结尾或尾帧目录。
4. 用户可以从空项目开始创建至少 1～50 个视频库，每个视频库获得稳定 ID 和独立目录。
5. 修改显示名称不会修改稳定 ID、目录、素材或历史清单。
6. 拖拽任意视频库后，新预览、新任务和清单严格按新顺序排列。
7. 键盘上移、下移与鼠标拖拽产生相同配置结果。
8. 删除视频库后，新任务不再使用它，但对应目录和全部素材保持不变。
9. 删除最后一个视频库后配置仍可打开和继续编辑，但预览与生成被明确禁用。
10. 必需视频库为空时禁止生成；可选视频库为空时安全跳过。
11. 时间线切片分类菜单按当前通用顺序显示，入库路径与稳定 ID 正确对应。
12. 固定配置快照、素材快照、数量和随机种子时，通用组合计划可复现。
13. 运行中的任务不受后续重命名、删除或拖拽影响。
14. schema 1、schema 2 和现有受管视频库均可继续使用，且不会因打开而被改写。
15. 任一失败操作都不会删除用户已有目录、素材或成片。

## 15. 建议分期

### 第一阶段：通用视频编排

- 新建通用项目库。
- 视频库的添加、编辑、删除和拖拽排序。
- 动态扫描、权重、计划、渲染和清单。
- 时间线切片动态分类入库。
- 淘宝闪购回归测试。

### 第二阶段：增强节点类型

- 通用静态图片节点及显示时长。
- 同一视频库在时间线中重复出现。
- 视频库复制、归档和重新关联已保留目录。
- 条件分支、随机跳过概率和最少/最多抽取数量。

## 16. 讨论前需要确认

以下是实现前最值得确认的产品决策，括号内为本文建议：

1. 单个可排序单元在界面叫“视频库”“素材库”还是“片段库”？（建议叫“视频库”，项目根目录改称“项目库”。）
2. 通用项目刚创建时是否允许完全为空？（建议允许，生成前再校验。）
3. 首期是否只支持视频素材？（建议只支持视频，静态图片作为第二阶段。）
4. 可选视频库有素材时，是每条必定抽取一个，还是按概率整段跳过？（建议首期有素材就抽取，后续再加跳过概率。）
5. 同一个视频库是否需要在一条成片中出现多次？（建议首期不支持，第二阶段引入独立编排节点。）
6. 通用模式是否首期需要风险提示语图片？（建议保留 `full/custom`，不引入“利益点区间”等淘宝语义。）
7. 删除视频库后是否需要提供“重新关联保留目录”？（建议首期仅保留文件，第二阶段增加重新关联。）

确认这些决策后，可据此拆分实现任务和测试矩阵。
