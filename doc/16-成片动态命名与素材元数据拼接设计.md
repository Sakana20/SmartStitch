# 通用成片动态命名与素材元数据拼接设计

## 1. 背景

当前成片文件名由 `output.filename_template` 生成，只支持以下变量：

- `config`：配置名称。
- `date`：生成任务的当天日期。
- `batch`：批次短 ID。
- `index`：批内序号。
- `seed`：随机种子。

现在需要增加一套业务命名逻辑，默认生成：

```text
产品-利益点-达人名-限制日期-序号.mp4
```

其中：

- `产品` 和 `利益点` 由用户在配置中填写和修改。
- `达人名` 和 `限制日期` 必须来自本条成片实际抽中的素材文件，不能使用批次级固定值。
- `序号` 是本次生成任务中的成片顺序，从 `1` 开始，每条成片都写入文件名。

本文档同时作为已实现功能的配置与交互说明。

本稿只设计 `workflow_type: generic` 的通用视频项目。素材来自用户自由新增和排序的 `pool_<n>` 视频库，不预设任何固定业务角色。其他工作流是否启用这套命名逻辑，不在本稿范围内。

## 2. 设计目标

1. 成片名称可直接表达业务含义。
2. 命名结果必须由已经选定的拼接素材决定，计划预览与最终成片保持一致。
3. 同一条成片中出现多个达人或多个限制日期时，必须有明确、稳定的合并规则。
4. 原始视频经 SmartStitch 切片入库后，仍能从切片文件名追溯和解析原文件元数据。
5. 解析失败时不得静默产生错误文件名。

## 3. 建议配置结构

新配置放在 `output.naming` 下。`output.filename_template` 保留，作为旧配置兼容路径；只有 `naming.enabled: true` 时才使用新逻辑。

```yaml
output:
  directory: "/输出目录"

  # 旧命名方式继续保留，旧配置不需要立即迁移。
  filename_template: "{config}_{date}_{batch}_{index:04d}.mp4"

  naming:
    enabled: true

    # 批次内固定的业务字段，用户可直接修改。
    product: "燕麦奶"
    benefit: "第二件半价"
    # 可选序号起点，默认 1；例如填 50 后从 50 开始递增。
    sequence_start: 1

    # 五个字段固定输出；sequence 是从 1 开始的批内成片序号。
    template: "{product}-{benefit}-{talents}-{restriction_date}-{sequence}.mp4"

    source_metadata:
      # 当前红果短剧项目只从“一口价剧情”视频库提取元数据。
      categories: ["pool_8"]

      # SmartStitch 切片名形如 <原文件名>__002_pool-1_f166-1027.mp4。
      # 解析前先取第一个 "__" 之前的原文件名。
      strip_smartstitch_suffix: true

      # 正则必须包含 talent 和 restriction_date 两个命名分组。
      # source_index/source_title 只用于校验或追溯，不覆盖 product/benefit。
      pattern: '^(?P<source_index>\d+)_(?P<talent>[^-]+)-(?P<source_title>.+)-(?P<restriction_date>\d{4}-\d{2}-\d{2})$'
      restriction_date_formats: ["%Y-%m-%d"]
      on_unmatched: error

    talent:
      merge: ordered_unique
      separator: "+"

    restriction_date:
      merge: earliest
      output_format: "%Y%m%d"

    # 模板异常导致重名时的额外保护后缀，不代替 sequence。
    duplicate_suffix: "-{serial:02d}"
```

### 3.1 为什么不直接复用 `config.name`

`产品` 和 `利益点` 是输出文件名中的业务字段，而 `config.name` 是 SmartStitch 页面和任务列表中的配置展示名。两者分开可以避免运营人员修改业务文件名时，意外改变整个配置的展示名。

### 3.2 为什么保留可配置解析正则

系统不应猜测任意文件名。通过带命名分组的正则，可以明确告诉系统“达人名”和“限制日期”在文件名的什么位置。若不同业务线后续有不同命名方式，只需改配置，无需改 Python 代码。

前端不应要求普通用户直接编写正则。简单模式只展示“产品”和“利益点”；解析规则放在高级模式，并提供系统默认值。

### 3.3 配置难易度分类

不以“字段数量少”作为简单设置的唯一标准，而以用户是否需要理解文件名解析、正则表达式、聚合策略和冲突处理来分类。

| 设置 | 难易度 | UI 位置 | 原因 |
|---|---|---|---|
| 是否使用“产品-利益点-达人-日期”命名 | 简单 | 简单模式 | 用户只需要表达是否启用业务命名。 |
| 产品 | 简单 | 简单模式、高级模式同步展示 | 高频业务输入，需要运营人员经常修改。 |
| 利益点 | 简单 | 简单模式、高级模式同步展示 | 高频业务输入，需要运营人员经常修改。 |
| 序号起点 | 简单 | 简单模式 | 临时续接上一批编号时可改为 50 等正整数，默认 1。 |
| 文件名效果预览 | 简单 | 简单模式 | 只读反馈，用于确认输入效果。 |
| 命名模板 `template` | 高级 | 高级模式 | 修改后会改变字段数量和顺序。 |
| 元数据来源视频库 | 高级 | 高级模式 | 需要理解 `pool_<n>` 稳定标识和通配选择。 |
| SmartStitch 切片后缀处理 | 高级 | 高级模式 | 是兼容切片命名协议的技术开关。 |
| 文件名解析正则 `pattern` | 高级 | 高级模式 | 正则表达式错误会使整批素材无法解析。 |
| 允许的日期格式 | 高级 | 高级模式 | 涉及日期解析和两位年份语义。 |
| 解析失败策略 | 高级 | 高级模式 | 会决定是否允许有风险的占位文件名。 |
| 多达人合并规则和连接符 | 高级 | 高级模式 | 属于聚合算法，常规使用不需改动默认值。 |
| 多日期合并规则和输出格式 | 高级 | 高级模式 | 涉及业务风险规则，默认保守取最早日期。 |
| 重名后缀 | 高级 | 高级模式 | 只在冲突时生效，属于文件系统策略。 |
| 完整 YAML | 专家 | YAML 专家模式 | 用于批量粘贴、备份和精确编辑所有字段。 |

一个字段可以在简单和高级模式同时出现，但必须绑定同一份 `state.configDraft` 数据。这不是两套配置，也不应产生相互覆盖的副本。

## 4. 文件名解析规则

### 4.1 解析对象

预检阶段应检查命名范围内所有“已启用且权重大于 0”的候选视频素材，避免任务是否成功取决于随机抽取结果。计划项的最终文件名则只汇总该条实际选中的素材。

当前项目的命名范围为 `categories: ["pool_8"]`，具体含义为：

- 以最终 `timeline` 为顺序权威。
- 只读取本条计划从 `pool_8` 实际抽中的视频。
- `pool_1`～`pool_7` 和 `pool_9` 仍照常参与拼接，但不参与达人名和限制日期提取。
- 风险提示语图片等叠加层不属于 `sources` 时间线，不参与达人和日期汇总。

其他通用项目可以在高级模式将 `categories` 改为自己的明确视频库列表，或使用 `pool_*`。未列入的视频库仍正常参与拼接，只是不为成片文件名提供达人和限制日期。

### 4.2 SmartStitch 切片文件

当原视频为：

```text
00016_小慧不大乖-红果拿下了我全家-2026-11-14.mp4
```

切片入库后可能为：

```text
00016_小慧不大乖-红果拿下了我全家-2026-11-14__002_pool-8_f3-1327.mp4
```

解析步骤为：

1. 去掉扩展名。
2. 当 `strip_smartstitch_suffix: true` 时，保留第一个 `__` 之前的内容。
3. 对 `00016_小慧不大乖-红果拿下了我全家-2026-11-14` 执行 `pattern` 匹配。
4. 取得 `talent=小慧不大乖`、`restriction_date=2026-11-14`。开头的 `00016` 和中间文案不进入最终文件名。

组合切片 `__g001_...` 也使用相同规则，因为它同样保留原始源文件名作为前缀。

### 4.3 解析失败

首版建议固定使用 `on_unmatched: error`：

- 预检页明确显示哪个素材、哪个类别不符合规则。
- 任务不得进入渲染，避免输出 `未知达人` 或错误日期。
- 界面同时展示“期望格式”和“实际文件名”。

后续若确有历史素材兼容需求，可再增加 `warn` 模式和明确的占位值，但不建议将它作为默认行为。

## 5. 多素材拼接规则

### 5.1 达人名

一条成片可能包含多个达人。建议按最终 `timeline` 顺序收集，去除重复名字后用 `+` 连接。

```text
pool_1 -> 张三
pool_2 -> 李四
pool_3 -> 张三
pool_4 -> 王五

结果：张三+李四+王五
```

“按时间线首次出现顺序去重”比字母排序更符合视频内容，且在固定随机种子时结果稳定。

### 5.2 限制日期

一条成片同时使用多个限制日期时，建议取最早日期：

```text
2026-10-31 + 2026-10-20 + 2026-11-15 -> 2026-10-20
```

理由：组合视频的可用期不应晚于其中任何一个素材的限制日期。这是更保守、更容易避免过期投放的规则。

当前项目输入使用 `YYYY-MM-DD`，内部转为真实日期后比较，最终文件名统一输出为 `YYYYMMDD`。

## 6. 输出名称示例

配置：

```yaml
product: "燕麦奶"
benefit: "第二件半价"
```

本条计划从 `pool_8` 选中素材：

```text
pool_8  00016_小慧不大乖-红果拿下了我全家-2026-11-14__002_pool-8_f3-1327.mp4
```

输出：

```text
燕麦奶-第二件半价-小慧不大乖-20261114-1.mp4
```

批内第二条成片无论素材是否相同，序号都会继续递增：

```text
燕麦奶-第二件半价-小慧不大乖-20261114-2.mp4
```

序号不是素材文件名前面的 `00016`，而是 SmartStitch 根据计划项顺序生成的批内编号。默认从 `1` 开始；若 `sequence_start: 50`，则该任务依次使用 `50`、`51`、`52`……。

## 7. 安全与校验

### 7.1 字段校验

- `product` 和 `benefit` 去除首尾空白后不得为空。
- `talent` 捕获结果去除首尾空白后不得为空。
- `restriction_date` 必须能按配置格式转为有效日期；如 `20260230` 必须报错。
- `pattern` 必须能编译，且同时含有 `talent` 和 `restriction_date` 命名分组。
- `template` 只允许 `product`、`benefit`、`talents`、`restriction_date`、`sequence` 五个变量，并要求全部存在，防止漏掉业务字段或序号。

### 7.2 文件名安全

- 替换 `/`、`\\`、`<`、`>`、`:`、`"`、`|`、`?`、`*`、NUL 和控制字符，防止生成子目录或跨平台无效路径。
- 折叠连续空白，去掉文件名末尾的空格和点。
- 保留正常中文、英文、数字、`-`、`_` 和 `+`。
- 整个文件名设置长度上限；达人过多超长时应在预检报错，不应静默截断名字。
- 扩展名统一由系统补为 `.mp4`。

### 7.3 重名处理

现有批次目录本身带时间和批次 ID，不同批次之间不会直接覆盖。批内名称由从 `1` 开始的 `sequence` 保证唯一，重名后缀仅作为自定义格式异常时的额外保护。

命名应保持确定性：相同配置快照、素材组合、数量和随机种子，必须得到相同的重名序号。

## 8. 计划、清单与追溯

每个计划项除 `output_name` 外，建议在 `manifest.json` 中保存派生命名信息：

```json
{
  "output_name": "燕麦奶-第二件半价-小慧不大乖-20261114-1.mp4",
  "naming": {
    "product": "燕麦奶",
    "benefit": "第二件半价",
    "talents": ["小慧不大乖"],
    "restriction_date": "2026-11-14",
    "sequence": 1,
    "sources": [
      {
        "category": "pool_8",
        "asset": "00016_小慧不大乖-红果拿下了我全家-2026-11-14__002_pool-8_f3-1327.mp4",
        "talent": "小慧不大乖",
        "restriction_date": "2026-11-14"
      }
    ]
  }
}
```

`manifest.csv` 新增 `product`、`benefit`、`talents`、`restriction_date`、`sequence` 五列。清单中的结构化值是权威数据，文件名只是便于人工识别的表示。

## 9. UI 交互设计

### 9.1 总体原则

命名功能必须延伸现有配置管理交互，不新增独立页面、弹窗或第四种配置模式。

现有结构保持不变：

```text
配置管理
├── 简单模式：大卡片、业务语言、高频操作
├── 高级模式：可折叠分区、完整参数
└── YAML 专家模式：完整配置文本
```

命名字段继续使用现有的结构化配置草稿、模式切换、折叠状态记忆、污点判断、租约锁、内容哈希和“校验并保存”流程。

只有 `workflow_type: generic` 时渲染本节的命名 UI。其他项目类型的配置界面和命名行为保持现状。

### 9.2 简单模式

通用项目增加独立的 **04 命名设置** 全宽卡片，现有输出设置顺延为 **05 输出设置**。淘宝闪购不展示命名卡片，原有编号保持不变。

分组内只放四个元素：

1. **业务命名开关**：文案为“按产品、利益点、达人和限制日期命名”。
2. **产品**：普通文本输入框。
3. **利益点**：普通文本输入框。
4. **序号起点**：正整数输入框，默认 `1`，允许临时改为 `50` 等续编编号。
5. **效果预览**：只读的 `simple-info-strip`，例如 `预计：燕麦奶-第二件半价-小慧不大乖-20261114-1.mp4`。

命名卡片复用 `simple-config-card simple-wide-card` 外观；卡片内容使用独立的 `simple-naming-card-body`，产品、利益点和序号起点使用三列输入网格，移动端自动变为单列。

开关关闭时：

- 产品和利益点输入框折叠隐藏，不删除已填内容。
- 预览显示“将继续使用原文件名模板”。
- 保存时不改写任何高级命名字段。

开关打开时：

- 产品和利益点为必填。
- 表单下方显示简短说明：“达人和限制日期会从本条成片抽中的素材中自动提取。”
- 已完成素材扫描时，预览优先使用一条可用素材的真实解析结果；尚未扫描时使用“达人名”和“限制日期”占位。
- 预检有文件名解析错误时，在预览条下显示警告和“查看高级规则”入口，点击后使用现有 `setConfigMode("advanced")` 切换，并展开成片命名分区。

简单模式不显示模板、正则、日期格式、类别标识、合并策略和重名后缀。

### 9.3 高级模式

在现有“成片输出”折叠区后、“批处理与扫描”折叠区前，新增一个同样使用 `config-section` 的折叠区：

```text
成片命名
产品、利益点与素材文件名解析
```

分区使用 `data-config-section="output-naming"`，因此可直接复用现有的折叠状态记忆逻辑。首次打开高级模式时默认折叠；当简单模式通过错误入口跳转时自动展开。

分区从上到下分为四组：

1. **业务字段**
   - 启用业务命名。
   - 产品。
   - 利益点。
   - 命名模板。
2. **素材文件名解析**
   - 参与解析的视频库，用逗号分隔列表输入，并配置帮助气泡说明 `pool_*` 表示所有通用视频库。
   - 移除 SmartStitch 切片后缀开关。
   - 解析正则，使用宽行文本输入，下方同时展示必须存在的 `talent` 和 `restriction_date` 命名分组。
   - 允许的限制日期格式，用逗号分隔列表输入。
   - 解析失败策略。首版 UI 只提供“报错并停止”；配置模型保留枚举位置，不提前展示尚未实现的 `warn` 选项。
3. **多素材合并**
   - 达人合并规则：首版仅“按时间线去重”。
   - 达人连接符，默认 `+`。
   - 限制日期合并规则：首版仅“取最早日期”。
   - 限制日期输出格式，默认 `%Y%m%d`。
4. **重名与预览**
   - 重名后缀模板，默认 `-{serial:02d}`。
   - 实时示例。
   - “用已扫描素材测试解析”按钮，只做读操作，列出匹配数、失败数和最多前 10 个失败文件。

已有 `output.filename_template` 和 `output.collision_policy` 继续留在“成片输出”分区，但在业务命名启用时标注为“备用命名，当前不生效”，不删除、不清空已有值。

所有高级字段继续使用现有 `configInput`、`configSelect`、`configSwitch`、`configHelp` 和 `config-form-grid` 组件，避免引入另一套表单样式。

### 9.4 YAML 专家模式

YAML 专家模式显示完整 `output.naming` 结构，不额外增加可视化快捷按钮。`config/template.commented.yaml` 和正式配置规范应给出与界面相同的默认值。

### 9.5 模式切换与保存

- 简单模式只能改写 `output.naming.enabled`、`output.naming.product` 和 `output.naming.benefit`。
- 简单模式保存必须以完整的现有 `state.configDraft` 为基础，不得用简化表单重建 `output.naming`，因此高级字段会原样保留。
- 从高级模式切回简单模式时，继续先执行现有 `collectVisualConfig()`，然后用同一草稿重新渲染简单卡片。
- 在任一模式修改产品或利益点后，切到另一模式必须立即看到新值，无需先保存。
- 从 YAML 专家模式切回结构化模式的行为继续遵守现有 YAML 同步逻辑，本需求不单独改变它。
- 最终仍使用配置弹窗底部现有的“校验并保存”按钮，不在命名卡片内再放一个保存按钮。

### 9.6 校验与错误展示

校验分为三层，并复用现有的错误提示和预检区域：

1. **输入时即时校验**：产品、利益点为空，模板变量错误，或正则无法编译时，在对应字段附近显示错误。
2. **保存时结构校验**：由 Pydantic 模型拒绝未知变量、缺失命名分组、非法日期格式和无效后缀模板。
3. **扫描时素材校验**：将不匹配的具体文件加入现有 `scan.errors`，顶部扫描摘要继续显示“预检未通过”，并阻止预览组合和开始生成。

错误文案必须面向文件操作，例如：

```text
视频库 2：无法从“素材片段__002_pool-2_f166-1027.mp4”识别达人名和限制日期。
请按“编号_达人名-中间文案-YYYY-MM-DD”检查 pool_8 源文件名，或在高级模式调整解析规则。
```

### 9.7 响应式与视觉一致性

- 桌面端的产品、利益点和序号起点使用三列网格；宽度小于 560px 时沿用现有媒体查询改为单列。
- 预览文件名允许换行和长单词断行，不横向撑开配置弹窗。
- 开关、输入框、帮助气泡、信息条、折叠区和按钮全部复用现有视觉类，不为命名功能引入新配色或第二套间距系统。
- 警告、阻塞错误和正常预览继续使用当前的 `warning`、`invalid` 和 `ok` 语义颜色。

## 11. 兼容与迁移

- 旧的通用配置没有 `output.naming` 时，继续使用现有 `filename_template`。
- 非通用工作流不展示本稿新增的命名 UI，也不因本需求改变原有文件名。
- 配置 API 应通过模型默认值向结构化编辑器返回完整的 `output.naming` 对象；前端不在渲染时自行拼一套可能与后端不同的高级默认值。
- 新增配置建议使用可选字段和默认值，暂不为此单独提升 `schema_version`。
- 开启新命名前，页面先扫描并列出不匹配的历史素材，由用户确认改名或调整解析规则。
- 不自动重命名任何原始素材、切片素材或已生成成片。

## 12. 测试与验收要点

1. 单达人、单日期生成标准五段名称，默认首条以 `-1.mp4` 结尾。
2. 多达人按时间线首次出现顺序去重并用 `+` 拼接。
3. 多个限制日期取最早值。
4. `YYYY-MM-DD` 能转为 `YYYYMMDD` 输出，非法日期报错。
5. 普通切片 `__002_...` 和组合切片 `__g001_...` 都能回溯到原始文件名。
6. 默认按 `timeline` 汇总所有已启用的 `pool_<n>`，叠加图层不污染达人和日期。
7. 任一参与命名的素材无法解析时，预检阻止生成并指出具体文件。
8. 同批内序号严格从 `sequence_start` 递增；设为 `50` 时首两条以 `-50.mp4`、`-51.mp4` 结尾，固定种子时素材组合与对应序号保持稳定。
9. 文件名中含中文、空格和 `+` 时可正常生成，路径分隔符和控制字符被安全处理。
10. 计划预览、`manifest.json`、`manifest.csv` 和实际输出文件名完全一致。
11. 未开启 `output.naming` 的旧配置产出结果不变。
12. 简单模式只展示启用开关、产品、利益点、序号起点和文件名预览，不暴露正则和合并策略。
13. 简单模式保存后，高级命名字段保持原值。
14. 简单、高级与 YAML 模式切换时，产品和利益点值及时同步，不丢失未保存修改。
15. 高级命名分区的折叠状态按配置记忆，且可从简单模式的解析错误直接跳转和展开。
16. 桌面端三列和移动端单列布局不出现溢出，长文件名可正常换行。

## 13. 需要确认的业务决策

开发前需要最终确认以下三点：

1. **限制日期的合并规则**：本稿建议取最早日期。若业务定义不是“素材失效日”，需更换规则。
2. **达人范围**：本稿默认从通用时间线的全部已启用 `pool_<n>` 收集；需确认是否存在应默认排除的通用转场或品牌视频库。
3. **原视频文件名格式**：已按当前 `pool_8` 的 133 个现有文件确认，格式为 `编号_达人名-中间文案-YYYY-MM-DD__切片信息`。
