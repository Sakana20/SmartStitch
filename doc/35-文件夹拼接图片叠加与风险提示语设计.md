# 文件夹拼接图片叠加与风险提示语设计

状态：源码已实现并完成验收。本次未构建或分发桌面安装包，已安装的旧版应用需要更新后才能使用。

## 1. 目标与需求解释

工具台“文件夹拼接”从 A、B 两个文件夹按文件名排序配对，逐组生成 A → B 成片，并支持可选风险提示语图片。

用户开启“添加风险提示语”后，可以选用现有配置的提示语图片，也可以添加本地/NAS 图片。同批成片固定使用这一张图片，统一居中叠加在最高层；可设置尺寸适配、透明度和显示时段，没有位置选择控件。

本稿将“图片叠加”和“风险提示语添加”按同一项功能设计：风险提示语由用户提供的图片承载。首版只有一个固定图片图层，不另设普通图片和风险提示语两套图层，也不提供文字输入、文字转图片或自动生成提示语。若后续需要同时添加其他图片与风险提示语，再扩展多图层方案。

| `smartstitch/scanner.py` 的 `scan_fixed_overlay` | 已支持读取和探测唯一固定图片 | 复用图片扫描能力，处理扫描错误 |

现有 `OverlayTiming.scope` 默认是 `benefits`。文件夹拼接使用 `pool_1/pool_2`，没有利益点类别；本工具显式默认 `full`，支持 `full/a/b/custom`。A/B 范围由每条任务的 `overlay_scope` 根据所选素材计算，普通项目的时段模型保持原有语义。

## 3. 产品规则

### 3.1 开关和图片选择

1. “添加风险提示语”默认关闭。关闭时不读取、不探测图片，图片路径失效也不影响拼接。
2. 开启后必须选择一张有效图片；缺失或不可解码时阻止提交，不允许无声跳过风险提示语。
3. 支持静态 PNG、JPG/JPEG、WebP、BMP，扩展名大小写不敏感。首版不支持 GIF、动态 WebP、HEIC、PDF、视频或文件夹。
4. 文件大小上限为 20 MB，与现有风险图片更换规则一致。必须同时检查实际格式、静态帧数、可解码性和正数宽高，不能只检查扩展名。
5. 支持透明通道，推荐使用透明 PNG/WebP；JPG 等不透明图片正常覆盖对应区域，不自动抠图。
6. 图片来源包括“从现有配置选择”和“添加图片”。现有配置列表读取显式 `benefit_overlays.file` 或受管库目录中的唯一图片；原配置显示开关关闭时仍可引用。添加图片允许选择任意可读的本地/NAS 文件。两种来源互斥，不从 A/B 文件夹自动猜测图片。
7. 同一批所有配对使用同一张图片，不随机抽取，不参与 A/B 配对或积木命名。

### 3.2 图层和输出

- 图片叠加在拼接后的最终画面上，处于最高视觉图层，不插入时间线、不增加视频时长。
- 保持 A → B 的画面和声音顺序；无音轨片段继续按现有策略补静音。
- 输出尺寸、帧率继续取本批首个配对的 A 视频，宽高按现有规则转为偶数。图片按该最终画布适配，不按每个源视频分别计算。
- 配对、未配对数量、默认文件名、积木命名、批次目录、编码设置与硬件失败回退规则沿用现有行为。
- 原视频和原图片保留。叠加配置仅用于本工具本批任务，不修改其他项目 YAML 或全局风险提示语设置。

### 3.3 固定居中、尺寸与透明度

| 设置 | 首版选项与默认值 | 对应行为 |
| --- | --- | --- |
| 图片尺寸 | 原图尺寸（默认）、等比适配画布、铺满画布 | 对应 `original/fit/stretch`；铺满会拉伸，应在选项旁说明 |
| 超大图片 | 默认自动等比缩小到画布内 | `shrink_if_oversized: true`；首版不开放关闭此保护 |
| 位置 | 固定居中，不显示控件 | 图片始终处于最高视觉图层 |
| 透明度 | 0–100%，默认 100% | 请求和配置保存为 0–1；与原图 Alpha 相乘 |

后端统一归一为 `x: (W-w)/2`、`y: (H-h)/2`，旧请求携带的位置值不影响新任务。铺满画布时坐标为 `0,0`，同样覆盖整幅画布。图片内容本身决定提示语在透明画布中的排布，不额外提供定位设置。

“等比适配画布”将图片等比缩放到不超过画布的最大尺寸，可能放大较小图片；它不是自定义宽高或可拖动缩放。自定义大小、边距和画布拖拽暂不纳入首版。

### 3.4 显示时段

- **整条成片**（默认）：从成片开头显示到结束，跨越 A/B 拼接点连续显示。
- **仅 A 文件夹**：每组从 0 显示到该组 A 视频结束，不包含 B 的首帧。
- **仅 B 文件夹**：每组从该组 A 视频结束开始显示，到 B 视频结束。
- **自定义时段**：开始秒数以最终成片起点为 0，必须为有限非负数；结束可留空表示成片结束，否则必须为有限正数且大于开始。
- 自定义区间按每组成片实际时长判断。结束超过成片时长时截到片尾，并在预检摘要中提示受影响组数；开始大于或等于任一组成片时长时，该组没有可显示区间，整批阻止提交并列出组号。
- 用户选择完全透明的 0% 时允许提交，但预检摘要明确提示“图片透明度为 0%，成片中不可见”。
- A/B 时段按每组实际素材时长独立计算，采用开始包含、结束不包含的区间；不固定为首组时长。普通项目的“主视频”“利益点”选项不出现在本工具。

## 4. 操作面板与用户流程

在输出目录之后、成片命名之前放置“风险提示语”卡片，标题右侧提供“添加风险提示语”开关。

关闭时只显示简短说明“开启后，为本批所有成片叠加同一张图片”。开启后展开：

1. “图片来源”选择现有配置或添加图片。现有配置显示“配置名 · 图片名”列表及刷新按钮，无图、坏图或目录多图的配置不可选；初次优先选当前项目的可用图片，其次首张可用图片。添加图片显示路径输入框与“添加图片”按钮，取消时保留原选择。
2. 读取状态：文件名、尺寸、文件大小、格式或明确错误。
3. 图片尺寸、透明度设置，位置固定居中。
4. 显示时段包括整条成片、仅 A 文件夹、仅 B 文件夹、自定义；只有自定义时显示开始和结束输入框。

同一面板内关闭再开启时保留已有路径和参数；离开工具后重新进入按默认关闭初始化，首版不增加跨会话偏好保存。

“预览配对”继续以 A/B 文件名和输出文件名为主，同时展示“未添加风险提示语”或图片名、尺寸、位置、透明度、时段。开启叠加时，预检需探测配对视频时长和首个 A 的输出规格，完成时段校验；关闭时保留现有轻量文件名预览。首版不新增整段视频试听、拖动定位或逐帧合成预览。

改变目录、命名规则、叠加开关、图片或任何叠加参数后，清除正式配对预检结果。异步响应使用独立请求版本号，过期响应不得覆盖当前选择。自动读取命名样本仍只获取 A/B 文件名，不因尚未选图而失败；不能将该轻量读取结果当作已完成叠加预检。

“开始拼接”允许直接提交，由后端再次完成全部校验；不以之前预览成功替代提交校验。提交后进入现有任务详情，显示本批风险提示语摘要，支持原有进度、取消和失败记录。

## 5. 请求、配置与预检响应

### 5.1 请求字段

`POST /api/v1/tools/folder-concat/preview` 和 `POST /api/v1/tools/folder-concat` 共用新增字段 `benefit_overlays`，复用现有字段名称与渲染配置结构。缺失或 `null` 表示关闭，兼容旧请求。

```json
{
  "directory_a": "/素材/A",
  "directory_b": "/素材/B",
  "output_directory": "/成片",
  "naming": null,
  "benefit_overlays": {
    "mode": "required",
    "file": "/素材/风险提示语.png",
    "placement": {
      "scale_mode": "original",
      "x": "(W-w)/2",
      "y": "(H-h)/2",
      "shrink_if_oversized": true,
      "opacity": 1.0
    },
    "timing": {
      "scope": "full",
      "start_seconds": 0,
      "end_seconds": null
    }
  }
}
```

新增工具专用请求模型，转换为现有 `BenefitOverlayConfig`，不继承 `benefits` 默认值。工具仅接受 `required/disabled`、三种尺寸模式、`shrink_if_oversized: true`、`full/a/b/custom` 和有效有限数值，位置统一居中。关闭时前端发送 `null`，后端先归一为关闭配置，忽略旧图片参数。

选用配置图片时以 `config_id` 替代 `file`，如 `{"mode":"required","config_id":"hongguo","timing":{"scope":"b"}}`。两种来源只能填写一种。预览与提交都重新读取所选配置的当前图片，再冻结副本，不信任页面列表中的旧路径。源配置名与 ID 写入本批摘要。

`GET /api/v1/tools/folder-concat/overlay-images` 返回 `items`，包含配置 ID/名称、可用状态、图片路径/名称/尺寸或不可用原因。该接口只探测提示语图片，不扫描项目视频、不改写配置。

图片路径沿用 `normalize_path_input`、`expanduser` 和路径解析规则。手工请求同样执行媒体和参数校验，不能绕过界面限制。

### 5.2 正式预检响应

保留现有 `count_a/count_b/pair_count/unpaired_a/unpaired_b/pairs/naming`。新增 `benefit_overlays` 摘要和 `warnings`：摘要至少包含启用状态、规范化源路径、图片名、尺寸、文件大小、放置参数、时段和预期输出尺寸/帧率；关闭时仅返回启用状态为否。

开启时每个 `pairs` 条目补充成片预计时长与实际叠加开始/结束，用来解释短视频截断。配对预览中的错误应包含组号、A/B 文件名和原因。

A/B 命名样本读取需保留独立的轻量调用方式，例如不传 `benefit_overlays` 的现有预览请求。开启功能后的正式预检必须携带完整叠加配置。

### 5.3 图片选择器

现有工具使用目录选择器，仓库还有视频文件选择器，但没有工具专用图片选择器。本期拟增加 `POST /api/v1/system/image-file-picker`，沿用原生选择器调用和取消返回约定，只允许单选图片并返回路径。实际格式与可读性由后端预检确认。无原生选择器的环境仍可粘贴路径。

不复用受管项目的图片上传替换接口：该接口会修改项目库图片，本工具只引用用户选择并为本批冻结副本。

## 6. 扫描、快照与任务构建

1. `inspect_folders` 保持原排序配对与命名职责，接收规范化叠加设置；媒体预检使用与正式任务相同的辅助校验函数，避免分别实现时段规则。
2. 先生成工具配置并执行 `scan_config`。开启后检查固定图片扫描错误及 `selectable`，不得只检查 A/B 素材后继续创建任务。确认首个 A 的实际输出规格后计算位置和各组显示区间。
3. 所有输入、图片、时段与磁盘空间通过校验后，再创建批次目录。校验失败不留下任务记录或空批次目录。
4. 将选中的有效图片复制到批次目录的 `assets/risk-overlay.<实际扩展名>`，记录源路径、文件名、字节数、SHA-256 与副本路径。使用临时文件、复制后探测和原子提交；复制时源文件发生变化、断开或副本无效则阻止创建，并清理此次创建的目录。
5. 配置快照 `benefit_overlays.file` 指向冻结副本；每条任务的 `overlay` 写入同一个已探测副本 Asset。复制完成后以副本为渲染依据，用户随后更换或删除原图片不影响该批。
6. 配置快照保存实际输出规格、叠加参数和现有命名/编码设置；任务详情及 JSON 清单保存源图片说明与副本信息。逐条记录实际显示区间；CSV 清单至少补充图片名、是否开启、开始/结束秒数，不把图片纳入 A/B 素材命名字段。
   工具请求的原始时段与来源说明写入快照 `folder_concat_overlay`。A/B 模式下通用配置使用 `full` 占位，每条 `PlanItem.overlay_scope` 独立覆盖渲染区间，避免改变普通项目配置校验。
7. 本工具所有新增文件均位于新批次目录内，不改写原素材。若任务保存前任一步失败，清理本次新建文件；已登记任务沿用现有任务清理流程。

仅保存图片路径或 Asset 元数据不能保证同批图片一致，因此本设计明确增加实际图片副本，而不是依赖后续仍可变化的原文件。

## 7. 渲染与兼容性

复用 `build_ffmpeg_command` 的静态图片循环输入、尺寸适配、RGBA 与透明度处理，在 A/B concat 之后执行 overlay。图片图层不参与音轨和输出时长计算，硬件编码回退继续使用同一份图片副本和参数。

自定义时段沿用当前渲染器的时间判断；结束时刻按输出帧采样显示，不承诺小于一帧的边界精度。末端被截断的范围与预检、任务记录一致。带透明 PNG/WebP、非透明 JPG/BMP、超大图片和不同视频尺寸应通过真实 FFmpeg 输出验证。

| 场景 | 处理方式 |
| --- | --- |
| 旧请求未传新字段，旧任务 `overlay: null` | 仍是纯 A → B 拼接；详情显示未添加风险提示语 |
| 开关关闭，保留路径已失效 | 不访问该路径，正常拼接 |
| 开关开启，缺图、坏图、多帧图片或文件过大 | 预检/提交报错，不创建任务 |
| 某组自定义开始时间越过片尾 | 整批拒绝，标明受影响配对 |
| 某组结束时间越过片尾 | 截到片尾，显示警告与实际范围 |
| 预检后原图片修改或 NAS 断开 | 提交重新读取校验；复制失败不创建任务 |
| 任务启动后原图片被替换/删除 | 使用批次副本，已启动批次保持一致 |
| 批次副本被删除或损坏 | 对应渲染失败并记录原因，不回退到其他图片或无图输出 |
| 透明度 0% | 允许，预检及任务摘要标明不可见 |

普通项目继续使用原有 `BenefitOverlayConfig` 和 `main/benefits` 语义，不改变默认值；工具专用限制只在文件夹拼接入口生效。历史任务不补写图片字段、不迁移旧快照。本期不接入集群执行或全局特效库。

## 8. 实施顺序与验收标准

1. 请求与预检：工具专用模型、默认关闭、路径规范化、图片有效性和时段检查。
2. 任务与快照：批次图片副本、哈希、每条 `overlay`、摘要及清单字段。
3. 界面：开关、配置图片/新增图片选择、尺寸/透明度/时段、预检摘要和失效处理。
4. 实际渲染与回归：使用现有扫描器、滤镜和任务执行管线完成验证。

| 验收项 | 通过标准 |
| --- | --- |
| 默认关闭与旧请求 | 配对、顺序、命名、音频和输出规格与原行为一致 |
| 开启与关闭切换 | 关闭后不读图片；同面板再开启保留输入；不污染普通项目 |
| 固定图片 | 多组成片都使用同一冻结图片，A/B 拼接点前后连续显示 |
| 图片参数 | 固定居中、三种尺寸模式、超大图缩小和 0/50/100% 透明度结果符合设置 |
| Alpha | 半透明像素与透明度相乘，透明区域保留底层画面 |
| 显示区间 | 全片、仅 A、仅 B、自定义、结束留空、结束超时长、开始越界均符合第 3.4 节 |
| 配置图片 | 显式路径和受管目录可选；显示关闭仍可引用；空目录、多图、坏图不可选；原配置不改动 |
| 图片异常 | 缺图、目录、损坏、伪扩展名、多帧、超过 20 MB 均在提交前拒绝 |
| 快照一致性 | 任务创建后修改或删除原图不改变本批输出；副本损坏时明确失败 |
| 预检交互 | 修改任一叠加设置后旧摘要失效；慢响应不覆盖新选择；命名样本读取独立工作 |
| 任务生命周期 | 进度、取消、硬件回退和失败记录正常，不因图片循环输入挂住或延长成片 |
| 可追溯性 | 任务详情、配置快照、JSON/CSV 清单中的图片与参数能对应到实际输出 |
