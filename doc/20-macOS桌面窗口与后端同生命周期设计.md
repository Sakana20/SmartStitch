# SmartStitch macOS 桌面窗口与后端同生命周期设计

> 实施状态：核心桌面生命周期已于 0.1.0 后的开发版本落地。当前正式包使用 pywebview/Cocoa WKWebView、随机环回端口和受控 Uvicorn 线程；关闭最后一个主窗口会停止任务管理器、本地服务及已登记的 FFmpeg 进程。本文中标为后续增强的项目不属于本次核心改造。

## 1. 背景与问题

改造前的 `SmartStitch.app` 启动后执行以下流程：

```text
启动 PyInstaller 可执行文件
  → 启动本地 Uvicorn/FastAPI 服务
  → 调用默认浏览器打开 http://127.0.0.1:8766
```

浏览器标签页不是 `SmartStitch.app` 的窗口，也不拥有后端进程。用户关闭标签页、关闭浏览器或找不到终端窗口时，Uvicorn、任务线程和 FFmpeg 子进程仍可能继续运行。macOS 菜单栏和 Dock 也没有一个清晰的 SmartStitch 退出入口，用户无法判断后端是否已经停止。

浏览器的 `beforeunload`、`pagehide` 或 `sendBeacon` 都不能作为进程退出保证：浏览器可能崩溃、强制关闭、禁止请求，页面也可能被刷新而非真正退出。因此不能通过“关闭网页时调用 shutdown API”单独解决该问题。

## 2. 目标

正式打包版改为单一桌面应用体验：

- `SmartStitch.app` 自己创建一个 macOS 原生主窗口，在窗口内显示现有 Web UI。
- 桌面窗口和 FastAPI 服务由同一个应用进程统一拥有和管理。
- 点击主窗口左上角红色关闭按钮后，SmartStitch 完成必要的优雅退出并结束后端。
- `Command + Q`、菜单栏“退出 SmartStitch”和关闭主窗口使用同一退出流程。
- 退出完成后不遗留 Uvicorn 监听端口、任务线程或 SmartStitch 启动的 FFmpeg/ffprobe 子进程。
- 发生启动错误时显示可读的原生错误提示，不留下不可见的后台进程。
- 保留现有 FastAPI、静态前端、SQLite、FFmpeg、NAS 和视频拼接业务逻辑。
- 保留 `start.command` 作为开发模式；开发模式仍可以使用默认浏览器和 `Ctrl+C` 停止服务。

## 3. 非目标

本改造不做以下工作：

- 不把前端重写为 SwiftUI、AppKit、Electron 或 Tauri。
- 不把 FastAPI 接口改成仅供 JavaScript Bridge 调用的私有协议。
- 不修改视频拼接、素材扫描、配置解析、飞书同步或时间线算法。
- 不增加菜单栏常驻、系统托盘、“关闭后继续在后台运行”等模式。
- 不允许关闭最后一个主窗口后只隐藏应用；关闭即退出是本项目的明确产品语义。
- 不用浏览器页面卸载事件替代桌面进程的生命周期管理。

## 4. 技术方案

### 4.1 桌面容器

正式 macOS 应用采用 `pywebview` 的 Cocoa/WKWebView 后端承载现有前端。它使用系统 WebKit 渲染页面，不需要捆绑 Chromium 或 Node.js 运行时。

```text
SmartStitch.app（一个主 Python 进程）
├── 主线程：DesktopController
│   ├── macOS 菜单栏与 Dock 生命周期
│   └── WKWebView 主窗口（现有 frontend）
├── 服务线程：Uvicorn Server（现有 FastAPI app）
├── 工作线程：现有任务管理器与同步管理器
└── 受控子进程：FFmpeg / ffprobe
```

这里的“前后端合并”指用户可见窗口与本地服务合并为同一个桌面应用生命周期，并不取消前端与 FastAPI 之间的 HTTP 边界。保留 HTTP 边界可以最大限度复用现有代码和测试，也不会改动核心业务逻辑。

### 4.2 运行模式分离

项目保留两种明确模式：

| 模式 | 入口 | UI | 后端退出方式 |
|---|---|---|---|
| 正式桌面模式 | 双击 `SmartStitch.app` | 应用内 WKWebView | 关闭主窗口或 `Command + Q` |
| 开发模式 | `start.command` / `smartstitch` | 默认浏览器 | 终端 `Ctrl+C` |

正式桌面模式不再自动打开默认浏览器。开发模式不强制依赖桌面容器，便于热重载、查看日志和调试接口。

### 4.3 本地服务地址

桌面模式仍只监听 `127.0.0.1`，但不再依赖用户记住或手工访问固定端口。启动时由桌面控制器预留一个可用的本机端口，并把实际 URL 交给 WKWebView。

预留端口和启动 Uvicorn 必须使用同一个已绑定 socket，避免“先找空闲端口、后启动服务”之间被其他进程抢占。开发模式继续使用默认 `127.0.0.1:8766`。

WKWebView 只允许导航到本次启动的本地 origin。飞书帮助页等外部链接交给默认浏览器打开，不能在应用窗口内替换 SmartStitch 页面。

## 5. 启动流程

正式桌面模式按以下顺序启动：

1. 初始化日志目录和全局异常处理。
2. 解析应用资源目录、可写数据目录和配置目录。
3. 配置内置 FFmpeg/ffprobe 路径。
4. 调用 `create_app()` 创建 FastAPI 实例。
5. 创建并预留仅监听 `127.0.0.1` 的 socket。
6. 在受控的非 daemon 服务线程中启动 `uvicorn.Server`。
7. 等待 Uvicorn 报告服务已启动。
8. 在 macOS 主线程创建 WKWebView 窗口并加载本地 URL。
9. health 检查或页面加载失败时显示原生错误框，随后执行统一清理并退出。

窗口只有在后端 health 成功后才显示业务页面。启动期间显示轻量原生启动状态或空白加载页，不能先弹出一个永久转圈的窗口。

## 6. 关闭与退出语义

### 6.1 用户操作定义

- 点击红色关闭按钮：请求完全退出 SmartStitch。
- `Command + W`：等同于关闭主窗口并完全退出。
- `Command + Q`：请求完全退出 SmartStitch。
- 菜单“SmartStitch → 退出 SmartStitch”：请求完全退出。
- 最小化黄色按钮：仅最小化，不退出。
- 页面刷新：仅重新加载 UI，不退出后端。

### 6.2 两阶段关闭

关闭流程分为“确认”和“停止”两个阶段，防止未保存编辑或进行中的任务被静默丢弃。

```text
RUNNING
  → CLOSE_REQUESTED
      ├── 用户取消 → RUNNING
      └── 用户确认 → STOPPING
                         → TERMINATED
```

第一次收到原生窗口关闭事件时，桌面控制器检查后端活动任务：

- 存在 queued/running/cancelling 的成片或切片任务时，提示“退出将停止正在处理的任务”。
- 存在进行中的飞书同步或待重试同步时同样提示。
- 没有活动任务时无需额外确认，直接进入停止阶段。

确认对话框提供：

- “取消”：取消关闭，保持窗口和服务运行。
- “好”：开始统一停止流程。

pywebview 退出事件返回后，桌面控制器在进程退出前同步执行统一清理，并设置 10 秒总超时。

### 6.3 后续增强：前端未保存状态握手

如后续需要检测表单尚未保存的编辑，可在桌面容器和页面间增加最小关闭桥接协议：

- 原生窗口关闭事件触发前端 `smartstitch:close-requested` 事件。
- 前端汇总当前未保存状态，并从后端读取活动任务摘要。
- 用户确认后通过受限 Bridge 调用 `confirm_close()`。
- Bridge 只允许确认退出、取消退出和读取桌面能力，不暴露任意文件或命令执行接口。

如果页面无响应或 WebView 已崩溃，桌面控制器等待最多 2 秒，然后显示原生确认框。用户仍可以选择退出；不能因为前端失效而永远无法关闭后端。

## 7. 后端优雅停止

桌面控制器是唯一退出协调者。确认退出后依次执行：

1. 将状态设为 `STOPPING`，拒绝重复关闭和新的任务提交。
2. 停止接受新的成片、切片和飞书同步任务。
3. 通知现有任务管理器取消等待队列，并终止当前受控任务。
4. 对 SmartStitch 启动的 FFmpeg/ffprobe 发送正常终止信号。
5. 等待子进程和工作线程在限定时间内退出。
6. 清理未完成的 `.part` 等临时产物，不删除已经原子提交成功的成片。
7. 将退出时仍未完成的持久化任务标为 `interrupted`，不能伪装为成功。
8. 尝试释放本机持有的配置租约；异常情况下仍由现有租约超时机制兜底。
9. 设置 `uvicorn.Server.should_exit = True`，关闭监听 socket并等待服务线程退出。
10. 刷新日志和 SQLite 状态，销毁窗口并结束主进程。

正常退出目标时间不超过 10 秒。超过限制后记录超时对象，升级为强制终止受控子进程，然后退出应用。强制终止只针对当前 SmartStitch 实例登记的 PID/进程组，绝不能按进程名批量杀死用户自行运行的 FFmpeg。

### 7.1 子进程所有权

所有 FFmpeg/ffprobe 调用需要通过统一的受控子进程入口登记：

- 记录 PID、所属任务 ID、用途和启动时间。
- 正常完成后立即注销。
- 退出时仅处理仍在登记表中的进程。
- POSIX 下为长时间运行的 FFmpeg 建立独立进程组，先发送温和终止信号，超时后再终止整个组。
- 短时 ffprobe 同样登记，避免关窗时残留扫描进程。

这属于运行时管理改造，不改变提交给 FFmpeg 的业务参数和视频处理逻辑。

## 8. 异常情况

### 8.1 后端启动失败

NAS 未挂载、配置错误、SQLite 无法打开或内置资源缺失时：

- 显示包含现有错误原文的原生对话框；NAS 错误继续明确显示“未连接 NAS”。
- 不创建业务主窗口，或关闭启动窗口。
- 停止已经启动的线程和 socket。
- 进程以非零退出码结束，不留后台服务。

打包版原有“NAS 未挂载时回退到 `~/Library/Application Support/SmartStitch/`”规则保持不变；源码开发模式的 NAS 强提示也保持不变。

### 8.2 后端运行中崩溃

服务线程意外退出时，桌面窗口显示“SmartStitch 服务已停止”，提供“退出应用”和“查看日志”，不能继续展示一个无法工作的页面。随后执行同一清理流程。

### 8.3 WebView 页面崩溃

WebView 页面崩溃但主进程仍存活时允许重新加载页面。若用户关闭窗口，则走原生兜底确认和后端停止流程。

### 8.4 强制退出或系统关机

`SIGTERM`、系统注销和关机事件尽量进入统一停止流程。`SIGKILL`、断电和进程崩溃无法保证执行清理，因此仍需依赖现有 SQLite `interrupted` 恢复机制、配置租约过期和下次启动时的临时文件整理。

## 9. 后续增强：单实例与重复启动

桌面版后续可增加单实例限制：

- 第二次双击应用时优先激活已有主窗口。
- 如果无法与已有实例通信，则显示“SmartStitch 已在运行”，不再启动第二套服务。
- 单实例锁位于本机 Application Support 目录，并包含 PID 与随机实例 ID。
- 不能只根据 PID 判断锁是否有效，必须同时进行进程存在和实例握手检查，避免 PID 重用造成永久假锁。

开发模式不受桌面单实例限制，开发者仍可通过不同端口启动独立实例。

## 10. 代码边界规划

实施阶段建议新增或调整以下职责，具体文件名可以在实现时微调：

```text
packaging/launcher.py
  仅负责桌面入口、错误兜底和启动 DesktopController

smartstitch/desktop.py
  DesktopController、窗口事件、服务线程、关闭状态机、单实例管理

smartstitch/runtime.py
  保留资源目录、可写目录和内置工具路径解析

smartstitch/api.py
  提供 create_app()；增加活动任务摘要和应用停止协调入口

smartstitch/processes.py
  集中登记与终止 FFmpeg/ffprobe 子进程

frontend/app.js
  增加桌面关闭事件、未保存状态汇总和退出进度 UI
```

`DesktopController` 不直接实现视频任务业务。它只调用任务管理器公开的 `shutdown()`/`active_summary()` 协议，从而避免桌面层了解成片、切片或飞书同步内部细节。

## 11. 打包与发布调整

- 在锁定依赖中加入 `pywebview` 及其 macOS Cocoa 依赖。
- PyInstaller 明确收集 pywebview/PyObjC 所需模块和元数据。
- `Info.plist` 保持普通 Dock 应用，不设置为后台 agent。
- 正式包仍为 Apple Silicon arm64、内置 Python、FFmpeg 和 ffprobe。
- 继续使用现有 ad-hoc signing；新增的 Mach-O/PyObjC 组件必须纳入现有逐层签名和验证。
- GitHub Actions 黑盒测试保留无窗口服务测试，并增加桌面生命周期的可测试控制器测试。
- `start.command` 不引入 pywebview 启动要求，仍走浏览器开发模式。

## 12. 测试计划

### 12.1 单元测试

- DesktopController 状态只能按允许路径转换。
- 重复关闭请求不会启动两次 shutdown。
- 前端确认取消后恢复 `RUNNING`。
- 页面无响应时触发原生兜底确认。
- 只终止当前实例登记的子进程。
- Uvicorn 启动失败后窗口和 socket 都被清理。
- 无活动任务时关闭不弹多余确认。
- 活动任务摘要和未保存状态能触发确认。

### 12.2 集成测试

- 使用真实 Uvicorn 和临时 config/data 目录启动桌面控制器的无窗口测试替身。
- 模拟关闭窗口后 health endpoint 在限定时间内不可访问。
- 模拟长时间 FFmpeg 子进程，确认退出时先温和终止、超时后强制终止。
- 确认运行中任务写为 `interrupted`，成功输出不被删除。
- 确认 SQLite、日志和配置锁状态可在下一次启动时正常恢复。
- 确认开发模式仍能通过 `start.command` 启动并用 `Ctrl+C` 退出。

| 最小化窗口 | 后端继续运行，任务不受影响 |

## 13. 验收标准

本改造完成需同时满足：

1. 正式包不再把默认浏览器作为主 UI。
2. 关闭主窗口、`Command + Q` 和菜单退出都会停止本实例后端。
3. 正常关闭后不存在 SmartStitch 监听端口或其启动的 FFmpeg/ffprobe。
4. 有未保存内容或活动任务时不会无提示退出。
5. 关闭清理存在明确超时，不会因为某个线程卡住而永久无法退出。
6. 退出状态可追溯，进行中任务不会错误标记为成功。
7. 开发模式、NAS 行为、飞书连接、SQLite 数据和视频业务逻辑保持兼容。
8. PyInstaller、arm64、ad-hoc signing、自动测试、DMG 和 GitHub Release 流程继续有效。

## 14. 实施顺序

1. 抽象 Uvicorn 服务线程和 DesktopController 状态机，先用假窗口完成测试。
2. 为任务管理器和受控子进程补充统一的活动摘要与 shutdown 协议。
3. 接入 pywebview/WKWebView，完成窗口关闭的两阶段握手。
4. 增加启动失败、页面无响应和退出超时兜底。
5. 更新 PyInstaller 收集规则、签名检查和 GitHub Actions 黑盒测试。
6. 在干净 macOS arm64 环境生成 DMG，逐项执行打包后验收表。

当前实现已完成上述第 1、2、3、5 项的核心路径：窗口与服务同生命周期、活动任务确认、任务管理器停止接口、PyInstaller 收集、ad-hoc 签名和 CI 黑盒测试。前端未保存状态桥接、单实例锁、运行中服务崩溃提示属于后续增强。
