# SmartStitch 片段审核与分类切片设计

## 1. 目标

当前时间线下方显示“断点列表”，而用户真正要审核、分类和交给 FFmpeg 的对象是断点之间的片段。本设计将列表从“管理切割点”升级为“管理待入库片段”：

- 将“断点列表”改为“片段列表”，每行代表一个完整的开始帧到结束帧区间。
- 在每个片段行右侧，即界面示意图红框位置，放置“片段类型”选择按钮。
- 用户可将片段设为前贴、引子、某个利益点、结尾、尾帧、未归类或不入库。
- 每次选择都将该片段实时归入下方“批量切片入库”的对应分类清单，但此时不调用 FFmpeg。
- 用户点击“切割并入库”后，前端才把已保存的断点审核版本和当前入库清单交给后端，由后端生成任务快照并执行 FFmpeg。

该流程已实现于时间线片段列表、前端入库分组、审核版本校验和后端 FFmpeg 切片服务。

## 2. 术语与权威数据

- **断点**：相邻两个片段的边界，以整数 `frame_index` 表示。
- **片段**：由相邻边界围成的半开区间 `[start_frame, end_frame)`。
- **片段类型**：片段切割后的业务用途和目标素材池。
- **断点审核版本**：后端已保存的断点和派生片段范围，由 `review_revision` 唯一标识。
- **入库草稿**：前端中尚未提交的“片段 → 类型”归类集合，实时显示在下方批量切片区。
- **切片任务快照**：用户点击“切割并入库”后，后端固化的审核版本、配置哈希和全部分类，FFmpeg 只消费该快照。

片段必须由后端根据断点派生：

```text
boundaries = [0, ...reviewed_breakpoints, frame_count]
segment[i] = [boundaries[i], boundaries[i + 1])
```

前端不得单独提交可改写的 `start_frame` 或 `end_frame` 让后端直接信任。启动切片时，后端必须根据已保存断点审核版本重新派生片段，再按 `segment_index` 绑定本次入库清单的分类。

## 3. 列表从断点改为片段

### 3.1 整体布局

时间线下方标题从“断点列表”改为“片段列表”，摘要改为：

```text
片段列表
10 个片段 · 9 个断点 · 8 个已分类 · 2 个待分类
```

每行建议布局：

```text
┌───────────────────────────────────────────────────────────┐
│ 02  00:00:02:46 → 00:00:17:07  861 帧  14.350 s  [选择类型 ▾]  结束：画面转场 │
└────────────────────────────────────────────────────────────┘
```

每个片段行必须显示：

- 片段序号。
- 开始时间码和结束时间码。
- 开始帧、结束帧或总帧数；桌面端至少显示总帧数。
- 片段时长。
- 片段类型按钮。
- 结束边界的机器依据或人工状态，如“画面转场”、“静音结束”、“人工调整”；最后一段显示“视频结束”。

### 3.2 行交互

- 单击片段行：选中整个片段，播放头定位到片段首帧，时间线上对应区间同步高亮。
- 双击片段行：从片段首帧开始预览，播放到片段末尾自动暂停，不跨越到下一段。
- 单击类型按钮：只展开分类菜单，不触发行选中或播放。
- 拖动断点仍在上方时间线中完成；片段列表不再把断点伪装成独立行。
- 列表滚动不影响时间线水平缩放和滚动位置。

## 4. 片段类型按钮

### 4.1 位置和外观

按钮放在每个片段行右侧，位于“结束边界依据”左侧，对应需求图 2 红框位置。

- 未选择时显示中性描边按钮“选择类型 ▾”。
- 选择后显示带颜色和文字的标签按钮，例如“引子 ▾”或“利益点 2 ▾”。
- 按钮使用文字表意，颜色只用于快速识别，不能仅靠颜色区分类别。
- 选择结果同步到时间线片段色块，使用户可直接看到整条素材的类型分布。
- 只要已选择一个有效配置，类型按钮就应可用；不因视频库尚未受管或布局需修复而隐藏整个片段分类界面。
- 没有选择配置时，按钮保留在行内但禁用，并显示“请先选择配置”，避免页面因状态不同发生布局跳变。

### 4.2 菜单内容

菜单顺序与业务时间线保持一致。前贴、引子、动态利益点、结尾和尾帧来自当前配置的 `timeline` 与 `sources`；“不入库”和“未归类”是系统选项：

```text
不入库
未归类
──────
前贴
引子
利益点 1
利益点 2
...
结尾
尾帧
```

- `skip`（不入库）：显式表示该片段不执行 FFmpeg，也不产生视频文件。
- `unclassified`（未归类）：用户确认需要切割，但暂不归入业务类别，输出到 `切片素材/未归类`。
- `pre_roll`（前贴）、`hook`（引子）、`ending`（结尾）和 `end_card`（尾帧）：输出到当前受管库对应素材池。
- `benefit_<n>`（利益点 N）：菜单根据当前配置动态生成，输出到 `切片素材/利益点/<n>`。

“待分类”是草稿状态，不是一个可提交类别。为避免因忘记操作而把片段误放入“未归类”，新片段默认为“待分类”；用户必须显式选择一项。

### 4.3 快速操作

- 菜单记住“上次选择”，但不自动应用到下一段。
- 列表聚焦后可用数字键选择固定类别；利益点数量动态且容易冲突，第一版不为其分配默认快捷键。
- 后续可增加“将选中的多个片段设为同一类型”，第一版不引入框选和多选。

## 5. 断点变化时的分类保留

断点改变后必须重新派生片段，不得用旧索引静默套用可能已不对应的类别。

- 开始帧和结束帧都未变的片段：保留已选类型。
- 移动某个断点：与该断点相邻的两个片段重置为“待分类”，其他帧区间未变的片段保留类型。
- 新增断点：被拆分的旧片段失效，新产生的两段均为“待分类”。
- 删除断点：新合并的片段为“待分类”。
- 任何断点变化都使上一个 `review_revision` 过期，必须重新保存才能切片。
- 断点变化后，下方入库草稿必须同步移除受影响的旧片段，不得留下与新帧区间不一致的待切片条目。

重置时需在片段行显示“边界已变更，请重新选择类型”，不只改颜色。

## 6. 审核和切片流程

```text
机器粗分析
   ↓
人工新增 / 移动 / 删除断点
   ↓
保存人工审核，获得 review_revision
   ↓
根据已审核断点展示片段列表
   ↓
用户为每段选择类型
   ↓
片段实时进入下方“批量切片入库”的对应分类清单
   ↓
用户点击“切割并入库”
   ↓
后端校验审核版本、分类清单、受管库和目标目录
   ↓
生成切片任务快照并执行 FFmpeg
   ↓
ffprobe 校验 → 原子改名 → 切片清单
```

界面按钮和下方区域调整：

- “保存人工审核”继续保存断点，不启动 FFmpeg。
- 上方片段行选择类型后，对应条目立即移入下方区域的相应分组；更改类型时从原分组移到新分组。
- 下方按“前贴 / 引子 / 利益点 N / 结尾 / 尾帧 / 未归类 / 不入库 / 待分类”分组显示片段明细，每个条目显示片段序号、首尾时间码和时长。
- 下方分组是待执行清单，不再放第二套类型下拉框；点击条目可回到上方对应片段。
- 只有当断点已保存、没有“待分类”片段，且当前配置是布局健康的受管视频库时，“切割并入库”才可用。
- 点击“切割并入库”之前，选择和分组只是前端草稿，不启动后端 FFmpeg。

## 7. 数据模型

### 7.1 断点审核版本

```json
{
  "review_revision": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "saved_at": "2026-09-15T12:30:00+08:00",
  "breakpoints": [166, 1027],
  "segments": [
    {
      "segment_index": 1,
      "segment_id": "f000000000-f000000166",
      "start_frame": 0,
      "end_frame": 166,
      "start_seconds": 0.0,
      "end_seconds": 2.766667,
      "duration_frames": 166,
      "end_boundary_reason": "scene_change"
    },
    {
      "segment_index": 2,
      "segment_id": "f000000166-f000001027",
      "start_frame": 166,
      "end_frame": 1027,
      "duration_frames": 861,
      "end_boundary_reason": "scene_change"
    },
    {
      "segment_index": 3,
      "segment_id": "f000001027-f000001800",
      "start_frame": 1027,
      "end_frame": 1800,
      "duration_frames": 773,
      "end_boundary_reason": "video_end"
    }
  ]
}
```

- `segment_id` 由源视频的帧区间派生，用于前端在断点变化后识别未变片段，不代替数据库主键。
- `review_revision` 由 `analysis_id + 源视频指纹 + breakpoints` 的规范化内容计算，只代表已保存的帧边界。

### 7.2 前端入库草稿

```json
{
  "analysis_id": "0123456789abcdef01234567",
  "review_revision": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "config_id": "product-library",
  "config_hash": "0123456789abcdef...",
  "assignments": [
    {"segment_index": 1, "segment_id": "f000000000-f000000166", "category": "hook"},
    {"segment_index": 2, "segment_id": "f000000166-f000001027", "category": "benefit_1"},
    {"segment_index": 3, "segment_id": "f000001027-f000001800", "category": "ending"}
  ]
}
```

- 每次点击片段类型后立即更新 `assignments`，并重新渲染下方分组清单。
- `category` 必须是 `skip`、`unclassified`、固定类别或当前配置存在的 `benefit_<n>`。
- 该草稿不是 FFmpeg 任务。分组和移动片段条目都只发生在前端，直到用户点击“切割并入库”。
- 页面刷新后可以丢弃未提交草稿；若后续引入本地自动保存，也必须按 `analysis_id + review_revision + config_id` 隔离。

### 7.3 切片任务快照与条目

后端接收提交后，先将 `review_revision`、`config_id`、`config_hash`、`library_id` 和全部 assignments 写入不可变任务快照，再启动 FFmpeg。切片清单中每个片段需包含：

- `review_revision`、`segment_id`、`segment_index`。
- `category`、`target_directory`、`output_path`。
- `start_frame`、`end_frame`、`fps`、`start_seconds`、`duration_seconds`。
- `status: skipped/pending/running/succeeded/failed`。
- FFmpeg 退出码、ffprobe 校验结果和错误摘要。

`skip` 片段也必须出现在清单中，状态为 `skipped`，但不创建 `.part` 或正式视频文件。

## 8. API 调整

### 8.1 保存人工断点

沿用 `PUT /api/v1/timeline/decisions`，继续保存断点并返回后端派生的片段范围：

```json
{
  "analysis_id": "0123456789abcdef01234567",
  "frame_indexes": [166, 1027, 1134]
}
```

后端校验断点位于首尾之间、升序且不重复，并返回 `frame_indexes.length + 1` 个派生片段和 `review_revision`。该接口不启动 FFmpeg，也不必须提交片段分类。

### 8.2 执行 FFmpeg 切片

`POST /api/v1/timeline/slices` 在用户点击“切割并入库”时调用，同时提交已审核边界和下方待执行清单：

```json
{
  "analysis_id": "0123456789abcdef01234567",
  "config_id": "product-library",
  "review_revision": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "current_config_hash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "assignments": [
    {"segment_index": 1, "category": "hook"},
    {"segment_index": 2, "category": "benefit_1"},
    {"segment_index": 3, "category": "skip"},
    {"segment_index": 4, "category": "ending"}
  ],
  "client_request_id": "1fbd890c-7693-45fc-955a-3f652cf50ace"
}
```

该请求到达前，后端不执行 FFmpeg。请求到达后必须先：

- 加载与 `review_revision` 完全匹配的审核记录；过期或不匹配时返回 `409`。
- 校验每个派生片段恰好有一个 assignment，不允许缺失、重复或越界索引。
- 复核当前配置哈希；除 `skip` 和 `unclassified` 外，每个类别必须仍存在于配置的 `timeline` 与 `sources` 中。
- 重新查询当前配置的切片目标；利益点已删除、目录缺失或库布局不健康时不启动任何 FFmpeg 进程。
- 原子写入带全部 assignments 的切片任务快照，然后依次或按受控并发执行 FFmpeg。

## 9. FFmpeg 切片规则

对每个非 `skip` 片段：

```text
start_seconds    = start_frame / fps
duration_seconds = (end_frame - start_frame) / fps
```

第一版继续采用精确重编码切片，而不使用只能依赖关键帧的直接流拷贝：

```text
ffmpeg -i <source> -ss <start> -t <duration> \
  -map 0:v:0 -map 0:a:0? \
  -c:v libx264 -preset fast -crf 18 \
  -c:a aac -movflags +faststart <temporary.part.mp4>
```

- 先写目标目录内的唯一 `.part.mp4`，不直接覆盖正式文件。
- FFmpeg 成功后使用 ffprobe 确认存在视频流、文件非空且时长在允许容差内。
- 校验成功后原子改名为正式 `.mp4`。
- 一段失败不终止已通过全批预检的其他片段；清单记录每段结果。
- 同一 `client_request_id` 重试时返回原清单，不重复生成；新请求的目标文件已存在时使用 `-v2`、`-v3` 后缀。
- 文件名应包含源文件名、片段序号、类别和帧区间，例如 `source__002_benefit-1_f166-1027.mp4`。

对 VFR 素材，必须使用真实 PTS 索引或先转换为 CFR；在尚未实现 PTS 索引前，界面必须明示帧精度限制。

## 10. 异常和边界

| 场景 | 行为 |
|---|---|
| 还有待分类片段 | 允许保存断点，但禁用“切割并入库”并定位第一个待分类行 |
| 断点在保存后变化 | 使审核版本过期，禁用切片按钮 |
| 利益点在审核后被删除 | 预检拒绝执行，提示重新分类 |
| 切片目录缺失或为越界符号链接 | 预检拒绝执行，不启动 FFmpeg |
| 用户选择不入库 | 清单记录 `skipped`，不生成文件 |
| 用户选择未归类 | 输出到未归类目录，不自动猜测 |
| 源视频被替换或修改 | 源指纹不一致时拒绝执行 |
| 中途单段失败 | 清理该段 `.part`，其他段继续，清单记录错误 |
| 审核网页刷新 | 加载最后已保存断点版本；未提交入库草稿可丢弃，不伪装成已执行任务 |

## 11. 验收标准

1. 原“断点列表”已替换为“片段列表”，`N` 个断点稳定派生 `N + 1` 个片段。
2. 每行清楚显示开始/结束时间码、帧区间、时长和结束边界依据。
3. 图 2 红框位置存在片段类型按钮，可选前贴、引子、当前所有利益点、结尾、尾帧、未归类和不入库。
4. 类型变化同步到列表标签和上方时间线片段色块。
5. 移动、新增或删除断点后，只保留帧区间完全未变的片段类型，受影响片段重置并要求重审。
6. 每次选择类型后，该片段立即出现在下方“批量切片入库”对应分组；切换类型时条目正确移组。
7. 存在待分类片段时仍可保存断点，但无法启动切片。
8. 选择类型和下方归类过程不调用 FFmpeg；只有点击“切割并入库”才向后端提交入库清单。
9. 点击后，后端先生成包含 `review_revision`、配置哈希和全部分类的任务快照，再执行 FFmpeg。
10. 利益点被删除、库布局不健康、目标越界或源视频指纹变化时，FFmpeg 不启动。
11. 每个非跳过片段都写入正确类别目录，并能从清单追溯到审核版本、源视频和权威帧区间。
12. 切片任务重试不会重复生成，失败的 `.part` 文件会被清理，已成功文件不被覆盖。

## 12. 实现顺序

1. 扩展断点审核响应，由后端返回派生片段和 `review_revision`。
2. 把断点列表替换为片段列表，完成选中、预览和类型按钮。
3. 将分类颜色同步到时间线轨道，并把片段实时归入下方批量切片分组。
4. 调整切片 API，在点击“切割并入库”时接收 `review_revision` 和当前 assignments，生成不可变任务快照。
5. 完成 FFmpeg 预检、切割、ffprobe 校验、入库和清单回归测试。
6. 删除下方区域重复的类型下拉框，保留按类别分组的待执行明细、批次摘要和执行状态。
