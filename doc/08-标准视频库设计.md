# SmartStitch 标准视频库设计

## 1. 目标与范围

在时间线完成断点审核后，SmartStitch 需要把原视频批量切割到一套结构固定、可扫描、可追溯的视频库中。本设计解决三个问题：

- 新建配置或视频库时，必须先询问用户保存在哪个目录，不默认写入项目目录、用户主目录或任意外接卷。
- 系统一次创建当前流程所需的全部文件夹，并自动把配置路径指向它们。
- 用户新建利益点段时，同步创建对应素材文件夹，不再要求用户手工建目录或手填路径。

该协议已实现于视频库服务、配置接口、时间线批量切片服务和前端建库/入库交互。

## 2. 概念与兼容原则

- **受管视频库**：由 SmartStitch 创建，根目录内存在 `.smartstitch/library.json` 标记的视频库。系统可在预定义范围内自动建目录。
- **外部素材配置**：旧配置或人工维护的任意目录，没有视频库标记。扫描和生成能力保持不变，但系统不得把它误认为受管库后大范围改造。
- **保存位置**：用户既可选择上级目录，也可直接选择一个与视频库文件夹同名的空目录。前者的最终路径为 `保存位置/视频库名称`；后者直接把所选目录作为视频库根目录，不再追加同名子目录。
- **视频库根目录**：一个库的边界；标准库配置的 `source_root` 指向此目录。

第一版沿用 `schema_version: 2`，不引入必须迁移的 YAML 字段。新库通过标记文件识别，旧配置不会被自动搬运、重命名或改写路径。

## 3. 标准目录结构

新建视频库时一次创建以下结构：

```text
<用户选择的保存位置>/
└── <视频库名称>/
    ├── 原始视频/
    ├── 切片素材/
    │   ├── 前贴/
    │   ├── 引子/
    │   ├── 利益点/
    │   │   └── 1/
    │   ├── 结尾/
    │   ├── 尾帧/
    │   └── 未归类/
    ├── 风险提示语图片/
    ├── 成片输出/
    ├── 工作记录/
    │   ├── 切片清单/
    │   └── 生成清单/
    └── .smartstitch/
        └── library.json
```

各目录的用途：

| 目录 | 用途 | 是否被素材扫描 |
|---|---|---|
| `原始视频` | 放置或引用待批量切割的长视频 | 否 |
| `切片素材/前贴` | 可选或必需的前贴素材池 | 是 |
| `切片素材/引子` | 必需引子素材池 | 是 |
| `切片素材/利益点/<n>` | `benefit_<n>` 的独立素材池 | 是 |
| `切片素材/结尾` | 必需结尾素材池 | 是 |
| `切片素材/尾帧` | 静态图片或视频尾帧素材池 | 是 |
| `切片素材/未归类` | 切片时无法确定类别的安全落点 | 否 |
| `风险提示语图片` | 存放唯一一张透明叠图；标准库自动识别 | 单图自动识别，不参与随机 |
| `成片输出` | 按批次存放最终 MP4 | 否 |
| `工作记录` | 存放切片清单，以及成片批次清单的索引或副本 | 否 |
| `.smartstitch` | 库身份和布局元数据，不放业务素材 | 否 |

空目录必须保留，因为它们是用户可见的工作流入口，不依赖 Git 的空目录表示方式。

## 4. 新建视频库交互

### 4.1 必填信息

“新建配置”升级为“新建视频库”向导，至少包含：

1. 配置 ID：沿用小写英文、数字、短横线规则。
2. 配置名称：用于页面展示。
3. 视频库文件夹名：默认取配置名称，用户可修改。
4. 保存位置：必须由用户选择或明确输入绝对路径。

界面需实时显示最终路径和将创建的目录树。用户没有选择保存位置时，“创建视频库”按钮不可用。目录选择器取消视为无变更，不创建配置或任何文件夹。

### 4.2 创建前检查

- 保存位置必须存在、是目录且当前可写。
- 保存位置末级名称与视频库文件夹名不同时，最终视频库根目录必须不存在。
- 两者同名时直接使用所选目录，但目录中只能包含 `.DS_Store`、`Thumbs.db`、`desktop.ini` 等系统元数据；存在其他文件或子目录时必须拦截，禁止自动合并。
- 文件夹名不得为空，不得包含 `/`、NUL 或当前平台非法字符，不得为 `.` 或 `..`。
- 规范化后的最终路径必须仍是用户选择位置的直接子目录。
- 外接卷未挂载、只读或中途断开时必须报出具体原因，不得在其他位置创建同名替代目录。

### 4.3 提交语义

创建操作必须尽可能保持原子性：

1. 常规模式在用户选择的父目录内创建唯一临时目录；同名空目录模式则直接使用所选目录。
2. 创建全部标准子目录和 `library.json`；同名空目录模式保留已有的系统元数据文件。
3. 生成并校验对应的 schema 2 配置内容；失败时只回滚本次创建的结构。
4. 将临时目录原子重命名为最终库名称。
5. 原子保存配置文件，然后向前端返回完整路径和配置。

任一步失败时，只清理本次创建的空临时目录和新文件，不删除用户已有文件。如果视频库已提交但配置保存失败，返回可重试的恢复状态，不静默留下“看似成功”的配置。

## 5. 标准库与配置的映射

创建后的默认配置映射如下：

```yaml
schema_version: 2
source_root: "/绝对路径/<视频库名称>"

timeline: [pre_roll, hook, benefit_1, ending, end_card]

sources:
  pre_roll:
    mode: optional
    directory: "切片素材/前贴"
  hook:
    mode: required
    directory: "切片素材/引子"
  benefit_1:
    mode: required
    directory: "切片素材/利益点/1"
  ending:
    mode: required
    directory: "切片素材/结尾"
  end_card:
    mode: optional
    directory: "切片素材/尾帧"

benefit_overlays:
  mode: disabled
  file: ""

output:
  directory: "/绝对路径/<视频库名称>/成片输出"
```

标准库默认将 `benefit_overlays.mode` 设为 `optional`，并允许 `benefit_overlays.file` 留空。扫描器会从库标记指定的 `风险提示语图片` 目录自动识别唯一一张受支持图片：目录为空时不启用叠图；恰好一张时自动使用；多张时阻止预检并要求用户只保留一张。显式填写 `file` 时仍优先使用该文件。

## 6. 新建利益点时自动建目录

### 6.1 用户可见行为

用户在受管视频库内点击“添加利益点”后，系统完成以下单一操作：

1. 分配一个从未使用过的稳定标识 `benefit_<n>`。
2. 创建 `切片素材/利益点/<n>` 文件夹。
3. 在 `sources` 中添加该素材组，默认 `mode: required`、`directory: "切片素材/利益点/<n>"`。
4. 在 `timeline` 的 `ending` 之前加入该标识。
5. 保存配置和视频库元数据，返回“利益点 N 已创建”以及完整文件夹路径。

这是一个立即持久化的库操作，不是只存在于前端内存的草稿。如果当前配置编辑器还有其他未保存修改，前端必须先完成校验和保存，再发起新建利益点操作；校验失败则不建目录。

### 6.2 编号规则

- `n` 从 1 开始单调递增，标识数字本身不因删除而回退；同一配置同时存在的利益点段仍最多 20 个。
- 删除 `benefit_2` 的配置后，下一个仍使用从未用过的编号，不为填空洞而复用 2。
- `library.json` 保存 `next_benefit_number`，避免删除配置后失去历史编号。
- 如果目标目录因中断或人工操作已存在，不覆盖、不清空、不改名其中文件；后端可安全关联该目录，并在响应中告知用户已有多少个候选素材。

### 6.3 原子性与并发

- 后端对单个视频库的元数据和配置修改串行化，防止两次点击分配同一编号。
- 请求带客户端请求 ID；重试同一请求时返回同一利益点，不重复创建。
- 先创建目标目录，再原子写入配置和元数据。后两者任一失败时，可删除的只是本次新建且仍为空的目录；已有目录或有文件的目录一律保留。
- 配置成功但元数据计数器写入失败时，下次启动通过现有 `benefit_<n>` 和目录名推导出安全的更大编号。

### 6.4 删除语义

“删除利益点”仍只从 `timeline` 和 `sources` 移除配置，**不删除目录和任何视频**。界面的确认文案必须明示保留路径。如需整理废弃文件夹，应在后续提供独立的“库整理”功能，不复用配置删除操作。

## 7. 视频库元数据

`.smartstitch/library.json` 使用 UTF-8 JSON，建议结构：

```json
{
  "layout_version": 1,
  "library_id": "8ac7a3df-5908-4c87-8491-7d8cfbe49537",
  "created_for_config_id": "taobao-xingguang",
  "display_name": "淘宝闪购-星广",
  "created_at": "2026-09-15T10:30:00+08:00",
  "next_benefit_number": 2,
  "paths": {
    "originals": "原始视频",
    "slices": "切片素材",
    "benefits": "切片素材/利益点",
    "overlays": "风险提示语图片",
    "outputs": "成片输出",
    "records": "工作记录"
  }
}
```

- `library_id` 是库身份，不使用可能变更的绝对路径代替。
- `created_for_config_id` 只记录建库来源，不限制其他配置引用同一视频库。
- `paths` 只保存相对库根的路径，便于整库移动。
- 标记文件不存储用户凭证和素材内容。
- 读取时必须校验版本、必需键、相对路径越界和库根一致性。标记损坏时库进入“需修复”状态，不盲目自动建缺失目录。

## 8. 批量切片与入库

- 时间线审核仍以原视频帧号为权威断点。
- 用户连续点击时间线中的首尾帧区间后，片段列表累计显示待切割子集；每行可选择前贴、引子、某个利益点、结尾、尾帧或未归类，也可移除。
- 不再设置独立的批量切片分组区。用户点击列表右上角“切割并入库”时，系统先保存最新断点审核版本，再提交列表子集。已分类切片进入对应素材池；“未归类”片段进入 `切片素材/未归类`；未标记片段不提交、不切割。
- 片段列表、分类按钮、审核版本和 FFmpeg 交接细节见[《片段审核与分类切片设计》](./09-片段审核与分类切片设计.md)。
- 切片文件先写同目录的 `.part` 文件，FFmpeg 成功且 ffprobe 校验后再原子改名。
- 默认不移动、改名或删除原视频。“导入到原始视频”是显式可选操作，默认建议复制而不是移动。
- 每次任务在 `工作记录/切片清单` 写入清单，记录源文件指纹、帧区间、目标类别、输出路径和结果。
- 同一 `client_request_id` 的重试直接返回已有清单，不重复切割；新请求若遇到同名文件，自动创建 `-v2`、`-v3` 后缀，不静默覆盖。

## 9. API 草案

API 前缀沿用 `/api/v1`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/system/directory-picker` | 打开本机目录选择器，返回用户确认的绝对路径；取消时返回 `cancelled: true` |
| POST | `/libraries/preflight` | 只读检查保存位置、最终路径、重名和可写性 |
| POST | `/libraries` | 创建标准视频库和配置 |
| GET | `/libraries/by-config/{config_id}` | 返回库身份、布局健康状态和完整路径 |
| POST | `/libraries/by-config/{config_id}/repair-plan` | 只读返回缺失目录和建议修复项，不直接写盘 |
| POST | `/configs/{config_id}/benefits` | 分配编号、自动创建文件夹并原子保存配置 |
| GET | `/libraries/by-config/{config_id}/slice-targets` | 返回当前库可用的切片入库类别和目录 |
| POST | `/timeline/slices` | 按每个审核片段的类别选择批量切割、校验并入库 |

创库请求示例：

```json
{
  "new_id": "taobao-xingguang",
  "new_name": "淘宝闪购-星广",
  "parent_directory": "/Volumes/Elements SE/视频库",
  "folder_name": "淘宝闪购-星广",
  "client_request_id": "f4bd27f4-f863-4f75-bef0-b4f6c1d11fd7"
}
```

新建利益点请求应包含 `client_request_id` 和当前配置内容哈希。哈希不一致时返回 `409`，要求前端刷新，避免静默覆盖其他编辑。

## 10. 安全与路径规则

- 所有路径均以结构化参数处理，不拼接到 shell 命令。
- 创库只能在用户本次明确选择的父目录下创建一个直接子目录。
- 受管库内的自动建目录只能发生在 `library.json` 宣告的相对路径下，规范化后不得越过库根。
- 不跟随把目标指向库外的符号链接；发现后拒绝写入并告知用户。
- 扫描时忽略 `.smartstitch`、工作记录、成片输出和 `.part` 文件，避免成片回流成素材。
- 不提供任意绝对路径的通用“建目录”接口；所有写操作都绑定到创库或受管库业务操作。

## 11. 异常与恢复

| 场景 | 行为 |
|---|---|
| 用户取消选择保存位置 | 保持向导原状，不写盘 |
| 同名库已存在 | 拒绝合并，提示更换名称或走“关联已有库”流程 |
| 保存位置不可写 | 创建前拦截并显示路径 |
| 外接盘创建中断开 | 任务失败，保留足以恢复的错误信息，不改用其他目录 |
| 利益点目录已存在 | 安全关联且保留全部内容，返回警告 |
| 利益点创建中配置冲突 | 返回 `409`，不覆盖配置，不删除非空目录 |
| 标记文件损坏 | 标记为需修复，只读生成修复计划 |
| 删除配置 | 保留整个视频库，明确显示其路径 |

## 12. 验收标准

1. 新建视频库时，未选保存位置不能提交；选择后界面明确展示最终绝对路径。
2. 创建成功后，第 3 节列出的所有目录和 `.smartstitch/library.json` 均存在。
3. 新配置的 `source_root`、各 `sources.*.directory` 和 `output.directory` 指向新库中的对应目录。
4. 点击“添加利益点”后，新的 `benefit_<n>`、时间线条目和 `切片素材/利益点/<n>` 同时成功，失败时不留下半完成配置。
5. 删除利益点配置后，对应目录和素材原样保留，后续新建使用更大的从未使用编号。
6. 中文、空格和外接卷路径下能正常创建、扫描和新建利益点。
7. 同名库、不可写路径、卷未挂载和符号链接越界都会在写入前或写入边界处被明确拦截。
8. 重复提交同一客户端请求不会创建两个视频库或两个利益点。
9. 旧配置在没有标记文件时仍能按原路径扫描和生成，不会被自动迁移或创建整套目录。
10. 批量切片的每个成功文件都能从切片清单追溯到原视频、帧区间和目标素材类别。
