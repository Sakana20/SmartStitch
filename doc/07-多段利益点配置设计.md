# SmartStitch 多段利益点配置设计

## 1. 目标

将原来单一的“利益点视频”拆成可增加、删除和排序的多个利益点段。一条成片可以按顺序抽取“利益点 1、利益点 2、利益点 3”中的各一个片段，从而用更快的人物切换缩短单人连续口播的拖沓感。

该协议已实现于配置模型、扫描、计划、渲染、清单和前端配置页。现有 schema 1 YAML 保持原文件不变，加载时在内存中迁移，用户主动保存后才写回 schema 2。

## 2. 核心决策

- 每个利益点段是一个独立素材池，拥有自己的目录、素材列表、启用状态和权重。
- 配置键使用稳定标识 `benefit_1`、`benefit_2`、`benefit_3` 等；前端显示为“利益点 1”、“利益点 2”、“利益点 3”。
- `timeline` 是成片顺序的唯一权威。利益点标识不必连续；例如删除 `benefit_2` 后可以保留 `benefit_1` 和 `benefit_3`，无需重命名导致历史清单失去对应关系。
- 新配置使用 `schema_version: 2`。第一版的 `benefit_video` 在加载时等价迁移为 `benefit_1`，不要求用户手工重写旧配置。
- 成片至少保留一个必需的利益点段。如果需要少一段，应删除该段在 `timeline` 和 `sources` 中的配置；删除配置不删除磁盘上的原素材。

## 3. YAML 结构

```yaml
schema_version: 2

timeline:
  - pre_roll
  - hook
  - benefit_1
  - benefit_2
  - benefit_3
  - ending
  - end_card

sources:
  hook:
    mode: required
    directory: "引子"
    extensions: [".mp4"]
    default_weight: 1
    items: []

  benefit_1:
    mode: required
    directory: "利益点/1"
    extensions: [".mp4"]
    default_weight: 1
    items: []

  benefit_2:
    mode: required
    directory: "利益点/2"
    extensions: [".mp4"]
    default_weight: 1
    items: []

  benefit_3:
    mode: required
    directory: "利益点/3"
    extensions: [".mp4"]
    default_weight: 1
    items: []

  ending:
    mode: required
    directory: "结尾"
    extensions: [".mp4"]
    default_weight: 1
    items: []

benefit_overlays:
  timing:
    # benefits = 从实际选中的第一个利益点段开始，到最后一个利益点段结束。
    scope: benefits
```

### 3.1 增加利益点

增加一段时，同时执行两个配置变更：

1. 在 `sources` 中增加一个未使用的 `benefit_<n>` 素材组。
2. 在 `timeline` 中将该标识放到期望的播放位置。

前端的“添加利益点”操作应一次完成这两处更改，避免产生半完成配置。对受管视频库，该操作还必须自动创建 `切片素材/利益点/<n>`，并将建目录、更新 `sources/timeline` 和递增库编号视为一个持久化操作。详细协议见[《标准视频库设计》](./08-标准视频库设计.md)。

### 3.2 删除利益点

删除一段时，同时从 `timeline` 和 `sources` 移除该标识。删除前应在界面中确认，但不触碰该素材组指向的本地目录和文件。

以下配置是合法的，成片只包含两段利益点：

```yaml
timeline: [pre_roll, hook, benefit_1, benefit_3, ending, end_card]
sources:
  benefit_1: {mode: required, directory: "利益点/1"}
  benefit_3: {mode: required, directory: "利益点/3"}
```

### 3.3 排序和停用

- 拖动利益点卡片只改变 `timeline` 中的顺序，不改变稳定标识。
- `mode: disabled` 用于临时保留配置但不进入成片；确定不再需要时才删除该组。
- `mode: optional` 表示有可用素材时抽取一个，没有时跳过；为保证口播结构稳定，利益点段默认使用 `required`。

## 4. 素材组织与人物切换

每个利益点段每条成片抽取一个视频。运营人员可将表达同一层意思、但由不同人物讲述的片段放入同一素材池：

```text
利益点/
├── 1/    # 不同人物讲“利益点 1”
├── 2/    # 不同人物讲“利益点 2”
└── 3/    # 不同人物讲“利益点 3”
```

各段独立按权重抽取，所以同一条成片可以在利益点之间切换人物。本需求不强制“同一条成片中人物不重复”；若必须保证不同人，需在后续需求中引入人物标签和跨素材池约束，不应依赖文件名猜测人物。

## 5. 校验规则

- 利益点标识必须匹配 `^benefit_[1-9][0-9]*$`。
- `timeline` 中的标识不得重复，且每个标识都必须存在于 `sources`。
- `sources` 中未被 `timeline` 引用的启用组视为配置错误；`disabled` 组可以保留但不渲染。
- `timeline` 必须包含 `hook`、`ending` 和至少一个非 `disabled` 的 `benefit_<n>`。
- 每个 `required` 利益点段都必须至少有一个可用且权重大于 0 的素材，否则禁止生成。
- 利益点上限先定为 20 段，防止误配置使预览、组合数和 FFmpeg 输入无限膨胀。

## 6. 计划、去重与渲染

- 计划器对每个利益点段独立生成加权序列，然后按批次序号合并为完整时间线。
- 核心组合签名改为 `hook + 所有实际启用的 benefit_<n> + ending`。
- 严格去重时的可用组合数为上述所有必选组候选数量的乘积；任意一个必选组为空都不可生成。
- 渲染器严格按 `timeline` 展开实际选中素材，不再写死单个 `benefit_video` 的位置。
- 利益点图片的 `scope: benefits` 覆盖从第一个实际选中的利益点段开始，到最后一个实际选中的利益点段结束。区间中如果穿插了其他类别，图片仍连续显示。

## 7. 数据、清单与前端

- `Asset.category` 和 `RenderItem.selections` 保留动态类别键，不增加固定的 `benefit_1_asset_id`、`benefit_2_asset_id` 数据库列。
- `manifest.json` 在 `selections` 中按稳定标识记录每个利益点素材。
- `manifest.csv` 按当次配置动态展开 `benefit_1`、`benefit_2` 等列，列顺序与 `timeline` 一致。
- 配置页将单一“利益点视频”卡片改为可排序卡片列表，提供“添加利益点”、“删除”和排序操作。
- 任务预览和详情页必须逐段显示人物片段来源，不能只显示一个合并后的“利益点”值。

## 8. 兼容迁移

`schema_version: 1` 的旧配置按以下规则加载：

1. 将 `sources.benefit_video` 改名为 `sources.benefit_1`。
2. 将 `timeline` 中的 `benefit_video` 就地替换为 `benefit_1`。
3. 将 `benefit_overlays.timing.scope: benefit_video` 替换为 `benefits`。
4. 在内存中标记为 schema 2；只有用户主动保存时才原子写回新格式，且保留旧文件备份。

迁移后的计划顺序、权重、随机种子和素材路径保持不变。算法版本会记录在新任务清单中；旧清单不回写。

## 9. 验收标准

1. 配置三个利益点段时，每条成片都按 `timeline` 顺序包含三个独立抽取的片段；在受管视频库中，每段的标准文件夹也已自动建立。
2. 删除中间的利益点配置后，新预览和新成片不再包含该段，其他段标识和原素材文件不受影响。
3. 对某一段设置 `required` 且无可用素材时，预检明确指出具体的 `benefit_<n>` 并禁止启动。
4. 固定配置快照、素材快照、数量和随机种子时，多段利益点计划可复现。
5. `strict` 去重把全部启用的利益点段纳入核心签名和组合数计算。
6. `scope: benefits` 的利益点图片从第一段利益点开始显示，在最后一段结束时停止。
7. schema 1 单段配置可无损加载为 schema 2，未主动保存前不覆盖原文件。
