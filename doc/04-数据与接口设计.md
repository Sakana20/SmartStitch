# SmartStitch 数据与接口设计

## 1. 建议项目结构

以下是后续开发阶段的目标结构，本轮不创建代码文件：

```text
SmartStitch/
├── backend/
│   ├── app/
│   │   ├── api/
│   │   ├── models/
│   │   ├── services/
│   │   ├── workers/
│   │   └── main.py
│   └── tests/
├── frontend/
│   ├── src/
│   └── tests/
├── config/
├── data/
│   ├── smartstitch.db
│   └── logs/
├── doc/
└── scripts/
```

运行期生成的数据库、日志、缓存和输出视频不应提交到 Git。

## 2. 核心数据模型

### 2.1 Library

- `library_id`：创建时生成的 UUID，是视频库稳定身份。
- `layout_version`：标准目录布局版本，第一版为 `1`。
- `created_for_config_id`：创建视频库时的来源配置 ID，不是独占引用限制。
- `config_ids`：运行时通过 `source_root` 反查到的关联配置列表，不写入库标记。
- `root_path`：运行时解析的规范化绝对路径，不写入库内标记的 `paths`。
- `next_benefit_number`：从未使用的下一利益点编号，删除配置不回收编号。
- `paths`：原始视频、切片素材、利益点、风险提示语图片、成片和工作记录等相对库根的标准路径。
- `health`：运行时派生的 `healthy/missing/unmounted/invalid_marker/needs_repair`，不写入标记文件。

Library 的持久化权威是 `<source_root>/.smartstitch/library.json`；SQLite 可保存索引和最近健康状态，但不能在整库移动后覆盖库内元数据。

### 2.2 Config

- `id`：稳定唯一标识。
- `name`：展示名称。
- `schema_version`：配置版本。
- `enabled`：是否启用。
- `yaml_path`：配置文件路径。
- `content_hash`：内容哈希。
- `updated_at`：最后修改时间。

### 2.3 Asset

- `id`：由配置、类别和规范化路径确定。
- `category`：`pre_roll/hook/benefit_<n>/ending/end_card/benefit_overlay/visual_border`；`benefit_<n>` 是动态稳定标识，不拆成固定数据库列，`visual_border` 来自全局库。
- `path`：规范化绝对路径。
- `enabled`、`weight`、`tags`。
- `size_bytes`、`modified_at`。
- 视频元数据：时长、宽高、帧率、编解码、像素格式、音频信息。
- `probe_status`、`probe_error`。

Asset 是扫描快照，不应把外部素材移动进项目目录。

### 2.4 BatchJob

- `id`、`config_id`、`config_snapshot_path`。
- `status`：`draft/queued/running/completed/partial_failed/failed/cancelling/cancelled/interrupted`。
- `requested_count`、`success_count`、`failure_count`。
- `seed`、`randomization_mode`。
- `output_directory`、`concurrency`。
- `created_at`、`started_at`、`finished_at`。

### 2.5 RenderItem

- `id`、`batch_id`、`sequence_number`。
- `selections`：按时间线类别标识记录选中的 Asset ID，包括可变数量的 `benefit_<n>`。
- `visual_border`：计划阶段从全局库确定的唯一边框 Asset ID；不进入视频时间线类别顺序。
- `output_path`、`temp_output_path`。
- `expected_duration`、`actual_duration`。
- `status`：`pending/running/succeeded/failed/cancelled`。
- `attempts`、`ffmpeg_exit_code`、`error_summary`。
- `started_at`、`finished_at`。

### 2.6 Manifest

`manifest.json` 是批次的权威导出记录，除以上字段外，还应记录：

- SmartStitch 版本和组合算法版本。
- FFmpeg/ffprobe 版本。
- 素材的大小、修改时间和可选哈希。
- 最终执行参数的安全版本。
- 权重理论分布和实际分布。
- 重复组合情况与调整说明。
- `manifest.json` 保留动态 `selections` 对象；`manifest.csv` 按配置时间线动态展开 `benefit_<n>` 列。

### 2.7 TimelineReview

- `analysis_id`、原视频路径、文件指纹和分析版本。
- `fps`、`frame_count`、宽高与时长。
- `machine_breakpoints`：机器候选帧、候选依据和置信度。
- `reviewed_breakpoints`：人工最终确认的整数帧序号、来源与修改时间。
- `segments`：由 `[0, ...reviewed_breakpoints, frame_count]` 生成的片段帧范围。
- `review_revision`：由分析记录、源指纹和人工断点规范化计算的审核版本，切片提交必须指定该值。
- `slice_assignments`：前端片段列表中已标记并分类的待执行子集；点击“切割并入库”时与最新 `review_revision` 一起提交并写入任务快照。
- `interaction_settings`：时间线缩放、视口起点和 Shift 吸附阈值；用于问题复现，不影响最终断点帧。

`frame_index` 是权威值，`time_seconds` 和时间码均由它派生。加载旧审核结果时应重新计算显示时间，不得用小数秒反推并覆盖已保存的帧序号。

### 2.8 GlobalVisualBorderAsset

- `asset_id`：由文件内容哈希生成的稳定 ID，相同内容只保存一次。
- `display_name`、`storage_path`、`content_hash`、`size_bytes`、`created_at`；`storage_path` 按共享根保存相对路径，不能写某台电脑的 `/Volumes/...` 绝对挂载路径。
- `media_type`：`qtrle_video/image`。
- `width`、`height`、`fps`、`duration`、`codec_name`、`pixel_format`、`has_audio`。
- `has_alpha`、`has_transparent_samples`、`alpha_mode`。
- `enabled`、`default_weight`、`probe_status`、`probe_error`。
- `library_revision`：全局库乐观并发版本，不与项目配置哈希混用。

权威目录为 `<SmartStitch 共享根>/全局素材库/视觉去重边框`，注册表为 `<SmartStitch 共享根>/.smartstitch/visual-border-library.json`。文件提交后不可原地改写；停用只影响新计划，已冻结任务仍可读取原内容。

## 3. HTTP API 草案

API 前缀建议为 `/api/v1`。

### 3.1 环境与预检

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/system/health` | 服务状态 |
| GET | `/system/ffmpeg` | FFmpeg/ffprobe 版本和可用性 |
| POST | `/system/directory-picker` | 打开本机目录选择器，只返回用户确认的绝对路径 |

### 3.2 视频库

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/libraries/preflight` | 只读检查建库路径、同名冲突和可写性 |
| POST | `/libraries` | 原子创建标准目录、库标记和配置 |
| GET | `/libraries/by-config/{config_id}` | 查询库路径、布局健康和缺失项 |
| POST | `/libraries/by-config/{config_id}/repair-plan` | 只读生成修复计划 |
| POST | `/configs/{config_id}/benefits` | 新建利益点目录并同步保存素材组和时间线 |
| GET | `/libraries/by-config/{config_id}/slice-targets` | 列出受管库中可选的切片目标素材池 |

### 3.3 配置

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/configs` | 配置列表 |
| POST | `/configs` | 新建外部素材配置；新建受管库使用 `/libraries` |
| GET | `/configs/{id}` | 读取配置 |
| PUT | `/configs/{id}` | 校验并保存配置 |
| POST | `/configs/{id}/clone` | 复制配置 |
| DELETE | `/configs/{id}` | 删除配置，需二次确认 |
| POST | `/configs/{id}/validate` | 结构和路径校验 |
| POST | `/configs/{id}/scan` | 扫描并探测素材 |

### 3.4 组合预览与任务

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/plans/preview` | 根据数量和种子生成只读计划 |
| POST | `/jobs` | 冻结配置快照并创建批次 |
| GET | `/jobs` | 查询批次列表 |
| GET | `/jobs/{id}` | 批次详情 |
| GET | `/jobs/{id}/items` | 条目列表 |
| POST | `/jobs/{id}/start` | 启动草稿批次 |
| POST | `/jobs/{id}/cancel` | 取消批次 |
| POST | `/jobs/{id}/retry-failed` | 重试失败条目 |
| GET | `/jobs/{id}/manifest` | 下载清单 |

### 3.4.1 全局视觉边框库

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/global-assets/visual-borders` | 列出全局边框、预检状态和库版本 |
| POST | `/global-assets/visual-borders` | 流式上传并预检；按内容哈希去重 |
| PATCH | `/global-assets/visual-borders/{asset_id}` | 修改显示名称、启用状态、默认权重或 Alpha 模式 |
| DELETE | `/global-assets/visual-borders/{asset_id}` | 软停用素材，不立即物理删除 |
| POST | `/global-assets/visual-borders/rescan` | 重新扫描注册表中的素材并返回诊断 |
| POST | `/global-assets/visual-borders/migrate` | 预检并导入旧项目边框；默认只复制、不删除源文件 |

所有写接口必须携带期望的 `library_revision`。版本冲突返回 `409`；上传使用原始流和文件名请求头，不用 Base64 或 JSON 承载大型 MOV。

任务创建和启动分为两个接口，使用户能在真正消耗计算资源前确认冻结后的计划。

### 3.5 进度推送

第一版可使用 Server-Sent Events：

```text
GET /api/v1/jobs/{id}/events
```

事件类型：

- `job_status_changed`
- `item_started`
- `item_progress`
- `item_succeeded`
- `item_failed`
- `job_finished`

前端断线重连后必须通过任务详情接口重新取得权威状态，不能只依赖事件流。

### 3.6 时间线分析与审核

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/timeline/analyze` | 粗略分析视频并返回机器候选断点 |
| GET | `/timeline/media/{token}` | 通过短期令牌读取本地视频供播放器预览 |
| PUT | `/timeline/decisions` | 按整数帧保存人工断点，返回派生片段和审核版本，不启动 FFmpeg |
| POST | `/timeline/slices` | 点击“切割并入库”时提交审核版本和当前归类清单，预检通过后启动 FFmpeg |

保存接口只接受规范化、去重且按升序排列后的帧序号。吸附和精细拖动属于前端交互，但服务端仍需拒绝首尾范围外、重复或无对应分析记录的断点。

## 4. 关键接口行为

### 4.1 配置保存

- 请求先做 Schema 校验，再做语义校验。
- 路径不存在不一定阻止保存草稿，但必须阻止启用或创建任务。
- 保存成功返回新的内容哈希和修改时间。
- 并发编辑时使用内容哈希避免后保存者静默覆盖前者。

### 4.2 视频库创建与利益点变更

- `/libraries/preflight` 只读，不通过“试建后删除”判断可写性。
- `/libraries` 请求必须包含配置 ID、名称、用户选择的父目录、库文件夹名和客户端请求 ID。
- 同名最终目录已存在时返回 `409`，不自动合并。
- 新建利益点请求必须带当前配置内容哈希和客户端请求 ID；后端串行化分配编号、创建目录、写配置和更新库元数据。
- 上述请求对同一客户端请求 ID 幂等。配置哈希冲突时返回 `409`，不静默覆盖。
- 删除配置和删除利益点都不删除视频库、素材目录或视频。

### 4.3 计划预览

请求包含配置 ID、数量、可选种子和本次覆盖项。响应包含：

- 实际使用的种子。
- 每条组合，其中利益点段数量和顺序与配置快照的 `timeline` 一致。
- 各素材预计使用次数。
- 重复组合数量。
- 警告和阻塞错误。

预览本身不写视频，但允许创建短生命周期的服务端计划缓存。

### 4.4 任务幂等性

- 创建任务接受客户端请求 ID，重复提交时返回同一任务。
- 启动已运行或已完成任务不得重复执行。
- 重试失败项创建新 attempt，不覆盖原错误记录。

## 5. 文件命名与目录

建议每批输出到独立目录。受管视频库以 `成片输出` 为输出根：

```text
视频库根目录/成片输出/
└── 20260914_淘宝闪购-星广_ab12cd34/
    ├── 淘宝闪购-星广_20260914_ab12cd34_0001.mp4
    ├── 淘宝闪购-星广_20260914_ab12cd34_0002.mp4
    ├── manifest.json
    ├── manifest.csv
    ├── config.snapshot.yaml
    └── task.log
```

批次 ID 的短前缀可避免同一天多次任务重名。文件名应清理 `/`、NUL 等非法字符，但允许正常中文。
