# SmartStitch 音频波形轨道与语音停顿断点设计

## 1. 目标

在时间线审核台的现有片段轨道下方增加一条音频波形轨道，并在同一版本将现有“静音结束”候选升级为“语音停顿”候选。用户可以像在 Premiere Pro 中一样，结合声音包络观察句尾、停顿区间和断点的关系，再进行人工确认。

参考图只用于确认以下逻辑：

- 视频与音频分成上下两条对齐轨道。
- 音频轨道按时间显示波形。
- 播放头、断点和时间标尺在两条轨道上共享同一时间位置。
- 机器候选点落在一段语音之后的静音区前部，而不是下一段声音开始处。
- A1 提供独立轨道锁；参考的是轨道锁定逻辑，不参考控件颜色和外观。

参考图的深色背景、蓝色片段、青色波形、按钮和轨道控制区均不是视觉参考。实现时不得替换 SmartStitch 当前的时间线颜色体系。

## 2. 范围与非目标

### 2.1 本期范围

- 显示源视频自带音频的单声道视觉包络。
- 保持波形与时间标尺、视频片段、断点和播放头的帧级对齐。
- 水平滚动、适应窗口和 `Option + 滚轮` 缩放时同步重绘波形。
- 无音轨、解码失败或波形仍在生成时提供明确的轨道内状态。
- 同时解析 `silence_start` 和 `silence_end`，建立完整静音区间。
- 将音频候选点放在静音开始后的短尾音保留位置，防止切掉说话尾音或贴到下一句开头。
- 在界面开放“最短语音停顿”参数，默认为 `0.35s`。
- 保留现有断点审核、片段选择和批量入库流程。
- A1 默认锁定；锁定时纯音频机器候选不参与片段划分、吸附、选择或拖动，解锁后恢复参与。

### 2.2 本期非目标

- 不做多轨编辑，不新增第二条音频素材。
- 不实现音频片段的独立拖动、裁剪、分离或对齐。
- 不实现静音、独奏、增益、淡入淡出和音量关键帧。
- 本版不引入 ASR、标点恢复或语义分句，因此不声称机器点是严格的“句子结束”。
- 本版不对呼吸、背景音乐、环境噪声中的语义边界做模型级判断；候选名称统一为“语音停顿”。

## 3. 现有基线与约束

现有时间线只包含两层可见内容：42 px 高的时间标尺和 70 px 高的片段轨道，由同一个 `timelineCanvas` 承载。横坐标的权威换算是：

```text
x = frame / fps * pixels_per_second
```

音频轨道必须复用这一换算，不得建立第二套时间比例或独立滚动容器。

现有配色是产品设计基线：

- 保留时间标尺、轨道背景、各片段分类色、机器/人工断点色、选中态和播放头颜色。
- 不修改现有 CSS 变量的值，不为了音频轨道重新着色视频轨道。
- 波形只使用现有中性色或品牌绿的低对比度派生色；不从参考图取蓝色或青色。
- 新增轨道与现有轨道使用相同圆角容器和边框语言，不把审核台改成 PR 的深色界面。

## 4. 界面结构

### 4.1 轨道层级

```text
┌时间标尺栏　00:00:00:00       00:00:05:00       00:00:10:00─┐
├视频片段轨道　[V1 片段 1      ][片段 2 ][片段 3       ]┤
├音频波形轨道　[A1  ▂▃▅▇▄▂▁▁▂▆▇▄▂▁▁▃▇▅▂▁▁▁▁▂▅▇▃▁▁ ]┤
└────────────────────────────────┼───────────────────────────────┘
                                播放头，贯穿 V1 和 A1
```

建议尺寸：

| 区域 | 高度 | 说明 |
|---|---:|---|
| 时间标尺 | 42 px | 保持现状 |
| V1 视频片段轨道 | 70 px | 保持现状 |
| A1 音频波形轨道 | 64 px | 新增，中线上下对称显示包络 |
| 时间线画布总高 | 176 px | 不含容器边框 |

`V1` 和 `A1` 是帮助识别轨道的小标签；A1 标签左侧增加一个轨道锁按钮，但不引入静音、独奏或录音按钮。标签与锁应是左侧的视口级覆盖层，不占用时间轴宽度，不得将零秒位置向右推移。控件继续使用 SmartStitch 现有中性色和品牌色，不复制参考图配色。

### 4.3 分析参数

现有“转场敏感度”旁新增“最短语音停顿”输入：

| 参数 | 界面名称 | 默认值 | 范围 | 说明 |
|---|---|---:|---:|---|
| `silence_duration_seconds` | 最短语音停顿 | 0.35s | 0.1–3s | 低于该时长的短暂音量下降不生成候选 |
| `scene_threshold` | 转场敏感度 | 0.30 | 0.05–0.9 | 沿用现有画面候选参数 |

输入值必须写入分析记录的 `settings`，以便重现机器结果。噪声阈值和尾音保留时长首期不在主界面暴露，由后端使用下述稳定默认值，但同样需记入 `settings`。

## 5. 波形语义

### 5.1 声道处理

- 单声道源：直接生成包络。
- 双声道或多声道源：首期混合为单声道后显示一条对称波形，不分开显示 L/R。
- 无音轨源：保留 A1 轨道高度，居中显示“此视频没有音轨”，不隐藏整条轨道导致布局跳变。

波形不表示 LUFS 或主观响度，而是用于定位的峰值包络。每个可见横向采样桶至少保留 `min_peak` 和 `max_peak`，避免缩小时丢掉短促声音。

### 5.2 与断点的关系

- 断点仍以 `frame_index` 为权威值，波形不保存或改写断点。
- `scene_change` 机器候选只显示在 V1，`speech_pause` 机器候选只显示在 A1；不得用一根机器线同时贯穿两条轨道，造成两种算法给出同一原始切点的误解。
- 同一采用断点同时包含两类依据时，V1 和 A1 各显示一个同帧候选；这表示两类依据在合并窗口内达成一致，而不是音频轨与视频轨被独立切开。
- 人工新增、拖动或确认后的断点是最终媒体边界，使用贯穿 V1 与 A1 的线表示。MP4 最终切割仍只有一个共同时间点，不能让同一输出片段的音频和视频使用不同边界。
- V1 机器候选始终可选中和拖动；A1 机器候选只有在音频轨道解锁时才可交互。一旦人工拖动，状态变为 `human_adjusted`，改用贯穿式最终断点显示。
- A1 锁定时，纯 `speech_pause`/历史 `silence_end` 点不参与片段边界和吸附；同时包含 `scene_change` 的共同命中点仍属于 V1 有效边界。人工新增或调整点也始终有效。
- 锁定只影响审核选择和边界集合，不静音、不删除源音轨；切割输出仍保留所选视频区间内的同步音频。
- 波形只是机器候选的可视化依据；候选仍由后端音频分析生成，不从 Canvas 像素反推。
- 波形的存在不得覆盖机器断点的原始静音区间证据、置信度或人工审核状态。

## 6. 语音停顿候选算法

### 6.1 命名与语义

本版生成的是“语音停顿候选”，原因标识使用 `speech_pause`。它表示音量低于阈值且持续足够时间的区间，不等同于 ASR 识别出的语义句号。

新分析不再把 `silence_end` 直接当作断点；`silence_end` 仅作为完整静音区间的后边界证据。历史记录中的 `silence_end` 原因仍必须能正常加载和显示。

### 6.2 静音区间提取

第一层沿用 FFmpeg `silencedetect`：

```text
noise = -35 dB
minimum_duration = silence_duration_seconds  # 默认 0.35s
```

后端必须按输出顺序同时解析：

```text
silence_start: <seconds>
silence_end: <seconds> | silence_duration: <seconds>
```

解析结果建立为完整区间：

```json
{
  "start_seconds": 5.0,
  "end_seconds": 5.6,
  "duration_seconds": 0.6
}
```

短视频常带持续背景音乐，固定绝对阈值可能得到零个区间。此时启用第二层自适应 RMS 回退：

```text
window_seconds = 0.05
base_level = 第 30 百分位窗口能量
threshold = min(-12 dB, max(-35 dB, base_level + 2 dB))
```

音频先下混为单声道、8 kHz PCM，每 50ms 计算一个 RMS 能量值；连续达到界面“最短语音停顿”的相对低能量区间生成候选。低能量区中单个 50ms 的瞬态尖峰可桥接，避免背景音乐鼓点把一个停顿误拆成两段。分析记录必须写明 `speech_pause_method`、实际阈值和每个区间的 `detector`。该回退仍是声学能量检测，不等同于 ASR/VAD 的语义分句。

边界规则：

- 文件开头就处于静音中的区间不生成断点，因为它前面没有可切的语音。
- 一直延续到文件结尾且没有 `silence_end` 的区间可保留为证据，但不在首尾帧附近生成断点。
- 无音轨、FFmpeg 报告不匹配音频流或无法得到成对边界时，返回空音频候选，不影响画面转场分析。
- 所有时间先保留浮点秒数作为原始证据，最终候选再统一换算为整数帧。

### 6.3 候选落点

默认参数：

```text
speech_tail_padding_seconds = 0.12
next_speech_guard_seconds = 0.08
```

对静音区间 `[silence_start, silence_end]`，先计算偏好时间，再在帧级执行下一段声音的安全距离约束：

```text
preferred_seconds = silence_start + speech_tail_padding_seconds
first_silence_frame = ceil(silence_start * fps)
latest_safe_frame = floor((silence_end - next_speech_guard_seconds) * fps)
preferred_frame = round(preferred_seconds * fps)
candidate_frame = max(first_silence_frame, min(preferred_frame, latest_safe_frame))
```

在默认最短 `0.35s` 静音中，断点通常位于静音开始后 `0.12s`，且在帧精度允许范围内与下一段声音保留至少 `0.08s`。如果参数组合使 `latest_safe_frame < first_silence_frame`，该区间不生成候选，不得把断点推到下一段声音中。

```text
上一段语音结束       静音区                         下一段声音
5.000s                 |------------------------------| 5.600s
旧 silence_end 候选                                                 ↑
新 speech_pause 候选           ↑ 5.120s
```

候选帧仍必须夹在视频首尾帧之间。如果取整后与其他音频候选重复，先按帧去重，但保留所有原始静音区间证据。

### 6.4 与画面转场合并

沿用当前 `0.18s` 合并窗口：

- `scene_change` 与 `speech_pause` 候选的距离不超过 `0.18s` 时合并为一个机器点。
- 两类依据一致时仍优先使用画面转场帧，因为它对视频切割更稳定。
- 合并后 `reasons` 同时包含 `scene_change` 和 `speech_pause`，原始静音区间不得丢失。
- 两类依据一致时置信度沿用 `0.9`；纯画面候选沿用 `0.72`；纯语音停顿候选沿用保守的 `0.55`。

### 6.5 数据与审计

新分析记录使用 `schema_version: 2`。音频候选示例：

```json
{
  "frame_index": 128,
  "time_seconds": 5.12,
  "reasons": ["speech_pause"],
  "confidence": 0.55,
  "review_status": "machine_suggested",
  "evidence": {
    "speech_pauses": [
      {
        "silence_start_seconds": 5.0,
        "silence_end_seconds": 5.6,
        "silence_duration_seconds": 0.6,
        "speech_tail_padding_seconds": 0.12,
        "noise_threshold_db": -35
      }
    ]
  }
}
```

`settings` 至少增加：

```json
{
  "silence_duration_seconds": 0.35,
  "silence_noise_db": -35,
  "speech_tail_padding_seconds": 0.12,
  "next_speech_guard_seconds": 0.08
}
```

使用自适应回退时还需记录窗口长度、分位数、阈值余量、阈值上限和本次实际阈值，以便重现结果。

兼容规则：

- `schema_version: 1` 记录保持只读兼容，前端继续将 `silence_end` 显示为“静音结束”。
- 新前端收到缺少 `audio` 字段的旧后端响应时，必须显示“后端版本过旧，请重启后重新分析”，不得误报“此视频没有音轨”。只有 v2 明确返回 `audio.has_audio: false` 时才能显示无音轨。
- 不就地迁移或重算旧分析。用户重新分析同一视频时生成新的 v2 记录，旧的人工审核结果不被覆盖。
- v2 `analysis_id` 的计算必须包含全部断点分析参数与源文件指纹；改动最短停顿、噪声阈值或尾部余量后必须得到新分析记录。
- 前端将 `speech_pause` 显示为“语音停顿”，不显示为“句子结束”。
- 人工移动候选后沿用现有 `human_adjusted` 语义，机器原始点及 `evidence` 仍在分析记录中保留。

## 7. 后端波形数据

### 7.1 生成策略

不建议将整个视频下载到浏览器后用 Web Audio API 解码：这会增加内存占用、首屏等待和格式差异。波形应在时间线分析阶段由 FFmpeg 解码，并以可审计缓存保存。

建议流程：

```text
源视频
  ↓ FFmpeg 解码为 8 kHz / mono / signed 16-bit PCM
固定时间桶聚合 min_peak + max_peak
  ↓
生成基础级波形（建议 400 buckets/s）
  ↓ 每两桶合并
生成多分辨率层级 200 / 100 / 50 / ... buckets/s
  ↓
按当前可见时间范围和像素宽度返回合适层级
```

基础分辨率要覆盖现有最大 `240 px/s` 缩放值，保证最大缩放时每个 CSS 像素仍有至少一个可用包络样本。生成过程应流式读取 PCM，不将整段未压缩音频一次性载入内存。

### 7.2 缓存与失效

波形缓存应与分析记录绑定，建议位置：

```text
data/timelines/waveforms/<analysis-id>.wfm
```

缓存头至少记录：

```json
{
  "schema_version": 1,
  "analysis_id": "0123456789abcdef01234567",
  "source_fingerprint": {
    "size_bytes": 12345678,
    "modified_at_ns": 1789536000000000000
  },
  "duration_seconds": 32.48,
  "source_channels": 2,
  "display_channels": 1,
  "base_buckets_per_second": 400,
  "levels": [400, 200, 100, 50, 25]
}
```

源文件大小或修改时间变化时，不得复用旧波形。同一 `analysis_id` 的重复请求应复用已生成缓存。

### 7.3 接口

时间线分析结果新增轻量元数据，不直接嵌入整段峰值数组：

```json
{
  "audio": {
    "has_audio": true,
    "channels": 2,
    "waveform_status": "ready",
    "waveform_url": "/api/v1/timeline/waveforms/0123456789abcdef01234567"
  }
}
```

`waveform_status` 取值：`ready | processing | unavailable | failed`。

可见区间请求：

```http
GET /api/v1/timeline/waveforms/{analysis_id}
    ?start_frame=1200
    &end_frame=3600
    &width_px=2
```

返回：

```json
{
  "analysis_id": "0123456789abcdef01234567",
  "start_frame": 1200,
  "end_frame": 3600,
  "bucket_count": 2,
  "peaks": [[-0.12, 0.18], [-0.20, 0.24]],
  "complete": true
}
```

约束：

- `start_frame` 和 `end_frame` 以视频帧索引表达可见时间区间，后端再换算到音频采样时间。
- `width_px` 必须限制最大值，建议不超过 4096，防止单次返回过大。
- 每个横向桶返回归一化到 `[-1, 1]` 的最小/最大峰值。
- 接口只允许读取已存在的分析记录，不接受任意本地路径。
- 请求范围必须裁剪到 `[0, frame_count]`，非法 `analysis_id` 和越界参数按现有 API 规范返回 4xx。

## 8. 前端渲染

### 8.1 不使用大尺寸全量 Canvas

当视频较长且缩放到 `240 px/s` 时，整条时间线可能超过浏览器 Canvas 的安全尺寸。因此波形采用可见区虚拟化渲染：

1. Canvas 的 CSS 宽度取当前可见时间范围的实际像素宽度；视频末尾或整段时长短于视口时不得强行铺满容器。
2. Canvas 在宽时间线画布中的 `left` 跟随 `scrollLeft`。
3. 根据 `scrollLeft`、`clientWidth`、`pixelsPerSecond` 和 `fps` 计算可见首尾帧。
4. 只请求并绘制可见范围，左右各预取约一个视口的峰值数据。
5. 使用 `devicePixelRatio` 设置 Canvas 内部像素尺寸，CSS 尺寸保持不变，避免 Retina 屏模糊。

滚动和缩放时在 `requestAnimationFrame` 中重绘已缓存数据。每个峰值先由响应中的 `start_frame/end_frame` 还原为绝对帧，再通过当前 `pixelsPerSecond` 换算横坐标；不得把任意响应简单拉伸铺满 Canvas。新数据返回前先按新比例重投影缓存，随后再用当前可见范围的峰值替换。请求使用 `AbortController` 取消过期响应，防止快速缩放时旧数据覆盖新视口。

### 8.2 绘制规则

- 以 A1 轨道垂直中线为零振幅。
- `max_peak` 向上绘制，`min_peak` 向下绘制，并保留至少 4 px 的上下内边距。
- 静音区显示为中线附近的细线，不用特殊彩色块标注。
- 波形不覆盖断点、播放头或吸附引导线；覆盖层的 z-index 高于 Canvas。
- 当前播放时不做“已播放区域换色”，避免引入新颜色语义和持续大面积重绘。

## 9. 交互规则

| 操作 | A1 行为 |
|---|---|
| 播放/暂停 | 波形不移动，播放头按现有逻辑更新 |
| 水平滚动 | 与标尺和 V1 使用同一 `scrollLeft` |
| `Option + 滚轮` | 以指针下时间为锚点缩放，波形与 V1 同帧重绘 |
| 适应窗口 | 波形显示完整视频时长 |
| 单击/双击 A1 空白区 | 首期不定位播放头、不新增断点，与现有“轨道空白处不操作”规则一致 |
| A1 已锁定 | 纯音频候选只显示、不响应指针、不参与吸附或片段划分；片段选择器只依据 V1 与人工边界 |
| 点击轨道锁解锁 A1 | 语音停顿候选重新参与片段划分、选择和吸附 |
| 解锁后拖动 A1 机器候选 | 将采用断点改为人工调整点，并显示贯穿 V1/A1 的最终边界；播放头和画面不变 |
| 方向键逐帧调整 | 人工断点线在波形上逐帧移动 |
| 悬停时按空格 | A1 也属于时间线视口，沿用现有播放/暂停快捷键 |

A1 波形 Canvas 和状态文本设置 `pointer-events: none`；轨道锁始终接收点击，A1 语音候选按钮只在解锁时接收选中与拖动事件。A1 其他空白区域不打点、不定位播放头，避免横向滚动时误操作。

## 10. 前端状态

`state.timeline` 建议新增：

```js
audioLocked: true,
waveform: {
  status: "idle",       // idle | loading | ready | unavailable | failed
  request: null,         // AbortController
  analysisId: null,
  rangeStartFrame: 0,
  rangeEndFrame: 0,
  widthPx: 0,
  peaks: [],
  error: null,
}
```

切换源视频、重新分析或分析失败时，必须取消未完成的波形请求并清空旧 Canvas。响应只有在 `analysis_id` 与当前时间线一致时才能写入状态。

现有 `renderTimeline()` 仍负责布局、片段、断点和播放头；波形使用独立的 `scheduleWaveformRender()` 进行合并刷新，避免拖动播放头时重建波形数据。

## 11. 加载、错误与可访问性

| 状态 | 轨道内容 |
|---|---|
| 尚未分析 | 不显示时间线工作区，沿用现状 |
| 波形生成中 | 显示低对比度占位线和“正在生成音频波形…” |
| 可用 | 显示波形 |
| 无音轨 | 显示“此视频没有音轨” |
| 生成失败 | 显示“波形暂不可用”；时间线和切片功能仍可使用 |
| 缺少 v2 音频元数据 | 显示“后端版本过旧，请重启后重新分析” |

波形是辅助视觉，不需要逐峰值暴露给屏幕阅读器。A1 轨道容器应提供简短的可访问名称，例如“源视频音频波形，只读”。无音轨和失败状态需使用文字，不得只用颜色表示。

## 12. 性能与容错

- 时间线初始分析可并行执行画面转场、语音停顿检测和波形生成，但任何一项都必须有独立错误结果。波形失败不得使断点分析失败；音频停顿检测失败时仍可使用画面转场候选。
- 水平滚动和连续缩放只在每个动画帧执行一次波形布局/绘制。
- 同一可见范围的峰值数据应进行内存缓存，但必须设置上限，避免用户遍历长视频后无限增长。
- 如果可见区间的新数据尚未返回，保留可复用的已缓存部分，其余区域显示占位线，不拉伸旧波形伪装成新数据。
- 不将峰值数据写入审核 JSON 主体，避免记录膨胀；审核记录只保存波形状态和缓存引用。

## 13. 实施顺序

1. **后端元数据**：扩展媒体探测结果，明确 `has_audio` 和源声道数。
2. **完整停顿区间**：解析 `silence_start`/`silence_end`；零结果时用自适应 RMS 低能量区间回退，并覆盖无音轨、首部和尾部边界。
3. **语音停顿候选**：实现尾音保留、帧换算、与画面候选合并以及 v1 记录兼容。
4. **分析参数界面**：开放“最短语音停顿”，保存并展示本次分析设置。
5. **波形生成与缓存**：实现流式 PCM 聚合、多分辨率缓存和失效校验。
6. **可见范围 API**：按帧区间和像素宽度返回峰值。
7. **A1 轨道布局**：在 V1 下方新增波形轨道，分轨显示机器依据；只让播放头、吸附线和人工最终断点贯穿两轨，不改现有颜色值。
8. **虚拟化绘制**：实现可见区请求、Canvas 绘制、请求取消和缓存。
9. **联动验证**：用波形检查语音停顿候选，并覆盖播放、滚动、缩放、适应窗口、断点拖动和切换视频。

## 14. 测试矩阵

| 场景 | 预期 |
|---|---|
| 有声双声道视频 | A1 显示一条混合后的对称波形 |
| 无音轨视频 | A1 高度保留并显示明确文字，分析可继续 |
| 新前端连接旧后端 | A1 提示重启服务，不误判为无音轨 |
| 音轨解码失败 | 波形标记失败，视频断点审核和切片仍可用 |

| 视频开头静音 | 不在开头生成无意义断点 |

| 纯画面/纯语音机器候选 | 分别只显示在 V1/A1，不贯穿另一轨 |
| 两类依据合并为同一采用点 | V1/A1 各显示同帧标记；人工调整后改为贯穿式最终边界 |

| 解锁 A1 | 纯音频候选立即重新参与片段划分，已有失效选择安全清理 |
| 锁定 A1 后切片 | 审核记录只保存当前有效边界，输出视频仍保留同步音轨 |
| 加载 v1 `silence_end` 记录 | 正常显示旧候选，不原地改写 |
| 重新分析旧视频 | 新建 v2 记录并使用 `speech_pause`，旧审核记录保留 |

| 连续拖动缩放条 | 已缓存波形立即按绝对帧坐标展开/压缩，新可见区数据返回后无跳位替换 |
| 水平滚动长视频 | 无超宽 Canvas，无持续卡顿，预取区平滑替换 |
| 播放视频 | 播放头同时贯穿 V1/A1，波形本身不水平漂移 |
| 断点拖动和方向键微调 | 断点延长线和波形帧位置一致，不改写播放头 |

| 源文件被替换 | 指纹不一致，旧缓存不被复用 |
| 回归现有时间线 | 片段颜色、断点颜色、吸附、分类和切片行为不变 |

## 15. 验收标准

- A1 位于现有 V1 下方，两者共享同一宽度、时间原点、缩放比例和水平滚动位置。
- 波形与音频内容在可感知范围内对齐，静音区、句尾和下一段声音可清楚区分。
- 新的纯音频机器候选使用 `speech_pause`，位于静音区前部，不再使用 `silence_end` 作为新分析的直接切点。
- 默认参数下，候选尽量保留 0.12s 句尾余量，并在帧精度允许范围内与下一段声音保留至少 0.08s 距离。
- 用户可在分析前调整最短语音停顿，分析记录可完整还原本次参数与原始静音区间。
- v1 旧记录可正常查看，不被自动迁移；新的 v2 分析不覆盖任何旧人工审核。
- 播放头、人工最终断点和吸附引导线在 V1/A1 间不出现水平偏移；机器候选按 V1/A1 来源分轨显示。
- A1 默认锁定且可切换；锁定时片段选择器只使用 V1/人工有效边界，输出仍保留同步音频。
- 现有时间线背景、片段分类色、断点、选中态和播放头配色全部保持不变；不出现参考图的蓝/青色复制。
- 波形失败、无音轨或数据还在加载时，用户仍能完成视频断点审核与切片。
- 除 A1 轨道锁外，不增加静音、独奏、录音或独立音频编辑控件，不对用户造成“可独立编辑音频”的误导。
