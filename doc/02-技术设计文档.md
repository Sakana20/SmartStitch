# SmartStitch 技术设计文档

## 1. 总体架构

建议采用本地 Web 架构：

```text
浏览器前端
  │ HTTP + WebSocket/SSE
  ▼
Python API 服务
  ├── 配置服务
  ├── 视频库与路径服务
  ├── 素材扫描与 ffprobe 服务
  ├── 组合计划器
  ├── 任务队列
  ├── FFmpeg 渲染器
  └── 清单与日志服务
       │
       ├── YAML 配置文件
       ├── SQLite 任务数据库
       └── 本地/外接硬盘素材与输出文件
```

推荐技术选型：

- 后端：Python 3.11+、FastAPI、Pydantic、SQLAlchemy 或 sqlite3。
- 前端：Vue 3 + TypeScript + Vite，或在控制复杂度优先时使用服务端模板 + 少量 JavaScript。
- 任务执行：第一版使用进程内任务队列和受控的 `asyncio`/线程调度；无需引入 Redis。
- 配置：YAML；任务状态和历史：SQLite；批次结果：JSON/CSV 清单。
- 媒体：FFmpeg 和 ffprobe 子进程。

### 1.1 受管视频库

视频库服务负责目录选择、建库预检、标准目录创建、库元数据校验和利益点文件夹联动。它不提供任意路径的通用写文件接口；写入只能发生在用户本次选择的父目录，或经 `.smartstitch/library.json` 确认的受管库边界中。

标准库仍使用 schema 2：`source_root` 指向库根，素材组使用相对路径，输出目录使用库内绝对路径。库布局版本和利益点递增编号存在库内元数据，不混入生成算法配置。

## 2. 处理管线

### 2.0 建库和路径确认

1. 前端要求用户选择保存位置，并预览最终库路径和目录树。
2. 后端在不创建文件的情况下检查父目录、同名冲突、可写性、路径越界和外接卷状态。
3. 在同卷临时目录中建立完整布局和库标记，校验通过后再原子重命名。
4. 生成指向新库的配置并原子写入；任一阶段失败都返回可识别的恢复状态。

目录选择属于本地 UI 适配层。macOS 第一版使用系统目录选择器，前端只接收用户确认后的绝对路径；取消时不产生任何写操作。

### 2.1 启动预检

1. 加载 YAML 并进行结构校验。
2. 检查 FFmpeg、ffprobe 是否可执行并记录版本。
3. 扫描所有素材目录，过滤无效文件。
4. 对每个候选素材运行 ffprobe，建立指纹：路径、大小、修改时间、时长、流信息。
5. 校验必需素材组非空、权重总和大于 0。
6. 校验图片和尾帧模式。
7. 检查输出目录可写和剩余空间是否达到安全阈值。

ffprobe 结果可按“绝对路径 + 文件大小 + 修改时间”缓存，未变化的文件无需重复探测。

### 2.2 组合计划

先生成完整批次计划，再启动 FFmpeg。这样可以：

- 在渲染前预览分布。
- 固定随机种子后复现组合。
- 避免任务中途素材权重变更影响剩余条目。
- 为每条任务提前分配唯一文件名。

每条计划至少包含：前贴、引子、按 `timeline` 展开的动态利益点段列表、结尾、尾帧、利益点图片、输出文件名、随机种子派生值。

计划器不应写死 `benefit_1/2/3`，而应识别所有匹配 `benefit_<n>` 且在当次时间线启用的素材组。每组独立生成权重序列，再按批次序号组合。

### 2.3 媒体标准化

虽然现有抽样素材一致，仍需处理潜在差异。建议统一输出参数：

- 画布：720×1280。
- 帧率：30fps。
- 像素格式：`yuv420p`。
- 视频编码：H.264。
- 音频编码：AAC，48kHz，双声道。
- 时间戳从零开始，避免 concat 后音画不同步。

第一版优先使用一次 `filter_complex` 完成片段标准化、拼接和叠图。只有在全部输入参数完全一致且无需叠图时才考虑 concat demuxer 的无重编码快速模式。为保证稳定性，默认仍采用重编码路径。

### 2.4 时间线与叠图

视频输入先分别执行：

- 视频：缩放/补边或裁剪、设置 SAR、帧率、像素格式、时间戳归零。
- 音频：重采样、声道布局统一、时间戳归零。
- 无音频素材：生成等时长静音轨。
- 尾帧图片：按配置循环成指定时长，并生成静音轨。

随后按配置顺序 concat。配置指定的唯一利益点图片最后执行 overlay，因此天然处于最高图层，并固定用于该配置的全部成片。

叠图时间范围转换为最终时间线上的 `enable` 条件。若范围为“全部利益点段”，开始时间应等于第一个实际选中利益点段之前的累计时长，结束时间是最后一个实际选中利益点段的结束点，不能使用写死秒数。

### 2.5 输出提交

1. 输出到同目录的唯一 `.part.mp4`。
2. 检查 FFmpeg 退出码。
3. 对结果运行轻量 ffprobe，确认存在视频流、时长大于零并与预计时长在容差内。
4. 成功后将临时文件原子改名为正式文件。
5. 写入条目清单和任务数据库。

### 2.6 时间线审核交互

时间线审核页采用类似 Adobe Premiere Pro 的编辑结构。视频播放器进度条是辅助定位入口；独立的时间线编辑区由上方时间标尺栏和下方片段/断点轨道组成。三者不得分别维护浮点秒数，而应共享一个权威的 `playhead_frame`。

轨道下方的明细列表以派生片段而不是断点为数据源。每行类型按钮只修改前端入库草稿中的 `category`，并将条目实时移入下方批量切片区的对应分组。选择和分组不调用 FFmpeg；只有点击“切割并入库”才提交已保存断点版本和全部 assignments，后端完成全批预检和任务快照后再启动 FFmpeg。详见[《片段审核与分类切片设计》](./09-片段审核与分类切片设计.md)。

#### 2.6.1 时间标尺与轨道

- 权威编辑单位是整数帧；换算公式为 `time_seconds = frame_index / fps`。
- 时间标尺与片段轨道必须位于同一可滚动时间线坐标系，共享 `pixels_per_second` 和 `viewport_start_seconds`；二者不得分别计算宽度或滚动偏移。
- 标尺主刻度、次刻度和时间码间隔根据当前缩放级别选择，避免标签重叠。主刻度间距建议至少 80 CSS px，次刻度间距建议至少 8 CSS px。
- 播放头由标尺栏中的手柄和贯穿全部轨道的竖线组成，两部分使用同一个横坐标。
- 视频正常播放时，以实际呈现帧为主源更新 `playhead_frame`；实现时优先使用逐帧呈现回调，普通 `timeupdate` 只作为兼容回退。
- 逐帧呈现回调提供的帧 PTS 可按最近整数帧映射；`timeupdate`、`pause`、`seeked` 等仅提供连续 `currentTime` 的回退事件必须使用 `floor(currentTime * fps + epsilon)`，不能使用 `round`。`epsilon` 只用于抵消浮点表示误差，不得大到跨越可见帧区间。
- 断点和时间码的权威时间仍为 `frame_index / fps`。但 HTML 视频手动预览不能停在帧边界，应 seek 到目标帧中点 `(frame_index + 0.5) / fps`，避免部分编码在边界点仍呈现前一帧；只允许纳秒级数值去重，不得使用 `0.25 帧`等会保留旧画面的 seek 容差。最后一帧的预览时间需限制在媒体 duration 以内。
- 用户操作播放器进度条或时间标尺后，视频画面、标尺播放头、贯穿竖线、帧号和时间码都必须同步。片段轨道空白区域不注册播放定位事件，仅断点元素注册拖动事件。
- 使用 `sync_source` 或等价状态区分 `video_playback / player_seek / timeline_scrub / breakpoint_drag`，防止状态更新形成反馈循环。

#### 2.6.2 跟手拖动与帧定位

拖动采用当前时间线视口的绝对坐标映射，不再使用固定像素换一帧的相对减速算法：

```text
pointer_timeline_x = pointer_viewport_x - timeline_left + scroll_left
raw_time_seconds = pointer_timeline_x / pixels_per_second
target_frame = round(raw_time_seconds * fps)
```

- 鼠标移动到哪里，播放头就显示在哪里；除整数帧量化造成的亚像素差异外，不允许播放头与指针持续分离。
- 帧级精度通过放大时间线获得；当缩放达到单帧宽度至少 4 CSS px 时，应能稳定选中相邻帧。
- 拖动时用 `requestAnimationFrame` 或等价机制合并高频指针事件，每次可见刷新都使用最新指针位置，避免队列堆积造成滞后。
- 拖动时间标尺时，视频画面、帧号和时间码连续预览。拖动断点时只更新断点元素和选中断点帧值，不写入 `playhead_frame`，不驱动视频 seek；所有拖动在松开鼠标前均不写审核文件。
- 时间标尺 `pointerdown` 时暂停视频；`pointerup`、`pointercancel` 或失焦清理后均保持暂停，不根据拖动前的 `wasPlaying` 恢复。断点拖动仍可按其操作前状态恢复播放。
- 目标帧限制在 `[0, frame_count - 1]`；断点还需位于首尾帧之间，并禁止重复。
- 时间线视口通过 `pointerenter` / `pointerleave` 维护悬停状态；仅在时间线页面激活且视口悬停时拦截 `Space` 的 `keydown`，忽略按键自动重复并切换视频播放状态。
- 时间线视口监听非被动 `wheel` 事件；只有 `altKey === true` 时阻止默认滚动并执行缩放。缩放前记录鼠标横坐标对应的时间，缩放后反算 `scrollLeft`，保证鼠标下方时间点保持不动。

#### 2.6.3 断点吸附

- 默认完全关闭吸附，普通拖动即使经过断点也保持鼠标跟手。
- 仅当 `Shift` 处于按下状态时启用吸附；拖动中松开 `Shift` 应立即解除当前吸附并回到指针对应的原始帧。
- Shift 吸附范围按屏幕距离判断，进入阈值建议为 `8 CSS px`；缩放或水平滚动变化后重新换算候选位置。
- 时间标尺拖动的吸附目标包括机器候选断点和人工确认断点；断点拖动额外加入当前 `playhead_frame`，但不得因吸附反向修改播放头或驱动视频 seek。若新增点落到已有点，应选中已有点，不创建重复记录。
- 多个目标同时位于阈值内时，先选择屏幕距离最近者；距离相同时优先播放头，其次人工确认点、机器候选点；仍相同时选择帧序号较小者，保证结果可复现。
- 按住 `Shift` 时，吸附后可保持目标锁定，直到指针离目标超过建议的 `12 CSS px` 退出阈值；该迟滞只在 Shift 持续按下期间有效。
- 吸附生效时高亮目标断点，并显示目标帧与时间码；松开后以目标的整数帧保存。

更完整的交互状态与验收规则见《时间线审核交互规范》。

### 2.7 利益点目录联动

受管库中的“添加利益点”不能由前端单独修改数组完成。后端业务操作必须在单库串行化边界内：

1. 校验配置内容哈希和库标记。
2. 根据 `next_benefit_number` 分配稳定标识和相对目录。
3. 创建目录，不覆盖已有内容。
4. 原子写入配置和更新后的库元数据。
5. 通过客户端请求 ID 保证重试幂等。

删除利益点仅修改配置，不对文件系统执行删除。完整事务与恢复规则见[《标准视频库设计》](./08-标准视频库设计.md)。

## 3. 权重算法

### 3.1 基本定义

同一类别中素材 `i` 的理论概率为：

```text
p_i = weight_i / sum(all enabled weights)
```

权重为 0 或禁用的素材不参与抽取。不同类别分别计算。

### 3.2 推荐默认：配额分配后洗牌

纯粹对每条独立随机会让小批次波动较大，不利于“每天出现得比较多”的运营目标。默认采用配额方案：

1. 计算每个素材的理论次数 `count × p_i`。
2. 先分配整数部分。
3. 剩余名额按最大余数法分配。
4. 使用批次随机数生成器打乱序列。

例如生成 10 条，权重为 `6、3、1`，最终分配恰为 `6、3、1`，但出现顺序随机。

配置可提供第二种模式 `independent_random`，用于真正的逐条独立加权随机。无论何种模式，清单都要记录算法和实际次数。

### 3.3 组合去重

单个类别按配额生成序列后，各类别独立洗牌再按索引合并，可能产生相同组合。建议支持：

- `allow`：允许完全重复组合。
- `best_effort`：在组合空间足够时尽量避免重复，无法满足时允许重复并记录原因。
- `strict`：不允许重复；请求数量超过可用组合数时拒绝任务。

第一版默认 `best_effort`。组合空间是引子、所有实际启用的利益点段和结尾的可用项数量乘积，并需要考虑固定素材与相容性规则。

### 3.4 随机种子

- 未填写时由后端生成并保存。
- 批次计划只使用局部随机数生成器，不依赖全局随机状态。
- 固定种子只保证同一程序算法版本、配置快照和素材排序下可复现。
- 候选素材必须先按稳定键排序，例如规范化绝对路径。

### 3.5 多段利益点

- 新配置使用 schema 2 的 `benefit_<n>` 素材组，数量和顺序由配置决定。
- 核心组合签名是 `hook + 全部启用的 benefit_<n> + ending`，去重计分和相邻复用计分都要动态遍历该签名。
- schema 1 的 `benefit_video` 在配置加载边界迁移为 `benefit_1`，核心计划与渲染器内部只处理新结构。
- 详细字段、删除语义和验收见[《多段利益点配置设计》](./07-多段利益点配置设计.md)。

## 4. 固定利益点图片

- 一个配置通过 `benefit_overlays.file` 指定唯一图片文件。
- 素材扫描只创建一个利益点图片 Asset，不接受文件夹或多个候选文件。
- 组合计划将同一 Asset 直接分配给该配置的全部成片，不调用权重或随机算法。
- 不同产品需要不同图片时，应复制为不同配置，并分别指定各自的固定图片。
- 图片仍在最终 concat 之后执行 overlay，因此保持最高视觉图层。

## 5. 进程与并发

- 每个成片对应一个 FFmpeg 子进程。
- 全局并发由信号量限制，默认 1 或 2。
- 记录子进程 PID，取消时先发送温和终止信号，超时后再强制结束。
- API 服务重启后，将原 `running` 任务标记为 `interrupted`；已完成文件不重复覆盖。
- SQLite 使用短事务，任务日志以文件或受控大小的数据库记录保存。

## 6. 错误分类

| 类别 | 示例 | 行为 |
|---|---|---|
| 配置错误 | 字段缺失、权重为负 | 禁止保存或启动 |
| 素材错误 | 文件不存在、无视频流 | 预检失败；非必需单项可停用 |
| 兼容错误 | 解码失败、图片损坏 | 单条失败并记录输入文件 |
| 环境错误 | FFmpeg 缺失、输出不可写 | 整批禁止启动 |
| 资源错误 | 磁盘空间不足 | 暂停/停止后续条目并明确告警 |
| 用户取消 | 点击取消 | 未开始项取消，安全清理临时文件 |

## 7. 安全与数据完整性

- 后端默认只监听回环地址，不对局域网暴露。
- API 接受路径时使用解析和白名单校验；删除操作只能触及任务创建的临时文件。
- 不使用 `shell=True`，FFmpeg 参数以数组传递。
- 正式输出默认不覆盖；冲突时自动递增或拒绝。
- 配置保存采用“写临时文件 → 校验 → 原子替换”，并保留最近若干备份。
- 配置中不保存密码或平台凭证。

## 8. 可观测性

每个批次生成：

- `manifest.json`：完整机器可读记录。
- `manifest.csv`：运营可直接打开的素材组合表。
- `task.log`：后端和 FFmpeg 摘要日志。
- `config.snapshot.yaml`：本批次实际使用配置。

日志至少包含任务 ID、条目 ID、输入素材、输出路径、开始结束时间、退出码和错误摘要。
