# SmartStitch 通用项目图片库设计

## 1. 背景与目标

通用项目目前只允许 `pool_<n>` 使用视频素材。用户可以在淘宝闪购项目的固定“尾帧”中放静态图片，却不能在通用项目中插入可排序的图片段，例如开场海报、产品价格图或收尾卡片。现有扫描器已经能识别图片，渲染器也有循环图片并补静音音轨的代码；限制主要位于通用配置校验、视频库创建接口和界面。

本期让通用项目可以新增**图片库**：每条成片从该库按现有权重规则选一张图片，按库默认时长或该图片单独设置的时长展示，并依照 `timeline` 与视频库一起排序、预览和生成。淘宝闪购 schema 2 的行为不变，已有通用 schema 3 配置无需迁移。

实现状态：仓库代码已支持图片库和两级时长；尚未打包发布，运行中的旧应用需要更新并重启后才能使用。

## 2. 范围与产品规则

1. 添加素材库时选择“视频库”或“图片库”，默认视频库。两者共用 `pool_<n>` 稳定 ID、目录、顺序、必需/可选/停用、素材权重和删除规则。
2. 图片库只接受静态 PNG、JPG/JPEG、WebP、BMP。首期不接收 GIF、HEIC、PDF、动态 WebP，也不在同一库混放视频和图片。
3. 图片库有一个**默认展示时长**，默认 1.5 秒。库内每张图片可以单独设置时长；未设置时使用库默认值。修改库默认值只影响未单独设置时长的图片。两级时长都限制为 0.1–60 秒，后端使用同一范围校验。
4. 图片库在时间线任意位置均可使用，可以作为唯一启用的库。纯图片成片输出正常视频文件，并生成与视频规格一致的静音音轨。
5. 图片库参与现有的权重、配额和组合去重。可选图片库为空时跳过；必需图片库为空或只有无效图片时阻止生成。
6. 图片库用于拼接，区别于“风险提示语图片”：前者每条随机抽一张、占据时间线时长；后者配置级固定一张、叠加在画面上方。
7. 图片素材由用户放入图片库目录。时间线审核中的“切割并入库”只产出视频片段，因此图片库不作为切片分类目标。

### 暂不纳入本期

- 视频和图片混合库、图片转场/运动效果、重复使用同一库节点。
- 把视频帧截图后直接入图片库；这需要单独的截图动作与审核流程。
- 自动将淘宝闪购尾帧迁入通用图片库。现有并行验证项目可在功能完成后手动添加尾帧图片库。

## 3. 用户流程与界面

### 3.1 新增与编辑

“添加视频库”入口改称“添加素材库”；弹窗包含类型、名称、使用方式和默认权重。选择图片时显示“默认展示时长”，初值 1.5 秒，并说明“该库每条成片抽取一张图片；每张图片也可单独设置时长”。创建后卡片展示“图片库”、默认时长和有效图片数，打开目录按钮指向 `视频库/pool_<n>`。图片库可以与视频库同样拖动、上下移动、停用和删除。

简单模式的“拼接顺序”卡片显示类型徽标和默认时长。高级模式显示类型和默认时长；图片库扩展名由类型自动确定，不提供任意扩展名编辑。视频库原有的扩展名设置维持原样，但不能通过手填图片扩展名绕过类型校验。

库类型创建后不可直接切换。用户若选错类型，应新建正确类型的库，再按需移动素材并删除旧配置；删除仍保留旧目录和素材。这样不会让已有路径、权重条目和历史任务突然改变媒体含义。

### 3.2 素材列表与预览

- 图片行显示尺寸、类型和**本张展示时长**。时长输入框默认显示库默认值及“继承默认”状态；用户输入数值后成为本张覆盖值，点“恢复默认”可清除覆盖。素材启用、权重、排序和异常状态沿用视频列表。
- 点击图片可查看静态预览，预览用与最终输出相同的适配方式和背景色，并标出本张实际展示时长。批量选择图片时可批量设置相同时长或批量恢复默认。
- 计划预览和任务详情按实际顺序显示图片文件名、库类型和时长；清单保留图片路径及任务启动时冻结的时长。
- 风险提示语、视觉去重图层和输出分辨率继续应用于图片画面。

### 3.3 切片分类

`GET /libraries/by-config/{id}/slice-targets` 只返回未归类和视频库，图片库不出现在分类菜单。后端 `resolve_slice_target` 对图片库也应拒绝切片任务提交，避免旧页面或手工请求把 `.mp4` 写进图片目录。图片库的“打开目录”不受影响。

## 4. 配置与接口

沿用通用项目 `schema_version: 3`；在每个 `sources.pool_<n>` 增加 `media_type: video | image`。缺省为 `video`，因此旧通用配置的读取和输出行为保持一致。现有库级 `image_duration_seconds` 作为图片库默认时长；每个 `items` 条目新增可选的同名字段作为单张覆盖值。字段缺失或为 `null` 表示继承库默认值。视频库保留库级旧字段以兼容旧数据，但界面不显示，也不允许设置单张图片时长。

```yaml
schema_version: 3
workflow_type: generic
timeline: [pool_1, pool_2, pool_3]
sources:
  pool_1:
    label: 开场视频
    media_type: video
    mode: required
    directory: 视频库/pool_1
    extensions: [.mp4, .mov, .mkv]
  pool_2:
    label: 价格图
    media_type: image
    mode: required
    directory: 视频库/pool_2
    extensions: [.png, .jpg, .jpeg, .webp, .bmp]
    image_duration_seconds: 2.5
    items:
      - path: /项目/视频库/pool_2/价格图-A.png
        image_duration_seconds: 4.0  # 本张覆盖默认值
      - path: /项目/视频库/pool_2/价格图-B.png
        # 未设置：继承图片库默认的 2.5 秒
  pool_3:
    label: 收尾视频
    media_type: video
    mode: optional
    directory: 视频库/pool_3
    extensions: [.mp4, .mov, .mkv]
```

- `POST /api/v1/configs/{config_id}/pools` 的请求增加 `media_type` 和 `image_duration_seconds`，默认分别为 `video`、`1.5`。服务端按类型创建扩展名列表；响应返回类型和时长。
- `PATCH /api/v1/configs/{config_id}/pools/{pool_id}` 允许修改图片库默认时长、名称、使用方式和默认权重，不允许修改已有库类型。
- 素材权重保存路径同时支持写入或清除单张图片的 `image_duration_seconds`；清除应序列化为 `null` 或移除字段，不能把当时的库默认值写死到该条目。保存时沿用现有配置哈希与编辑租约校验。
- 结构化配置和 YAML 校验必须保证图片库仅使用图片扩展名、视频库不包含图片扩展名；显式 `items` 也不能绕过类型约束引用另一类媒体。
- 目录与项目标记布局保持 `layout_version: 2`，`next_pool_number` 继续单调递增；不新增专门的图片根目录。

**兼容注意：** 现有 `SourceGroupConfig` 已有 `image_duration_seconds`，扫描器以文件扩展名判定 `Asset.media_type`。新增 `media_type` 应只定义库的允许类型；不要修改历史任务中已固化的素材类型。运行中任务继续使用启动时的配置与素材快照，包括每张图片的实际时长。

## 5. 扫描、计划与渲染

### 5.1 扫描与校验

扫描时仅发现该库类型允许的扩展名。损坏、无法解码、无有效画面或权重为 0 的图片不参与抽取；必需库无可用图片时给出库名、ID 和目录。图片宽高必须为正数。显式素材条目须检查路径仍在该库受管目录内，并与库类型匹配，防止旧条目绕开扩展名过滤。

每张图片的实际时长按“单张覆盖值 → 库默认值”解析，再传给图片探测和计划。现有图片探测缓存键包含展示时长；修改任一级时长后要重新计算受影响图片的 `probe.duration`，不把旧时长带入计划。计划估算时长按各选中视频时长和各图片实际时长求和。种子、权重和配置相同时，图片选择和拼接顺序可复现。

### 5.2 渲染与音频

现有渲染器对图片输入使用循环读取并按时长截断，对无音轨素材生成静音。实现时应把每张图片解析后的实际时长量化到输出帧率，例如 `max(1, round(seconds * fps))` 帧；计划时长、FFmpeg 输入、任务进度及成片时长校验使用同一量化结果，避免短图片段出现一帧误差。

图片沿用项目的 `fit_pad`、`fill_crop`、背景色、输出帧率和像素格式。带透明通道的 PNG/WebP 先在所选背景上合成，再进入普通视频滤镜链；预览应采用同一规则。图片库自身不带音轨，渲染器输出对应时长的静音；前后视频音频在拼接后保持原有顺序。纯图片项目也输出配置的 AAC 音轨。

风险提示语按完整成片时间轴叠加，`full` 和 `custom` 语义不变；图片段计入自定义时段的时间位置。视觉去重效果同样应用于图片段。带异常尺寸、Alpha、横竖方向和长时长图片的实际输出需用 FFmpeg 样例验证。

### 5.3 动态命名

当前通用动态命名默认 `source_metadata.categories: ["pool_*"]`，会解析参与成片的素材文件名。新图片库可能不符合视频文件名规则，不能因加入一张普通图片而让整批命名失败。建议将 `pool_*` 的默认展开限定为**视频库**；显式指定图片库 ID 时才从图片文件名解析元数据，并在配置保存时提示解析规则适用性。未启用动态命名的项目无变化。

## 6. 兼容性与失败边界

| 场景 | 处理方式 |
|---|---|
| 旧通用配置没有 `media_type` | 按视频库加载，不改写原文件。 |
| 淘宝闪购 schema 2 的图片尾帧 | 原有规则继续运行；不自动转换。 |
| 图片库为空、只有损坏图片或权重全为 0 | 必需库阻止预览/生成；可选库跳过。 |
| 图片库目录混入视频、视频库目录混入图片 | 扫描时不纳入候选，并在界面提示被忽略的数量；显式条目视为配置错误。 |
| 修改库默认时长 | 只影响未设置覆盖值的图片及新任务；已覆盖图片和运行中任务不变。 |
| 设置或清除单张覆盖时长 | 新计划使用新的实际时长；清除后重新继承库默认值。 |
| 删除图片库 | 只删除配置引用，保留目录和图片，历史清单不变。 |
| NAS 断开或目录损坏 | 按现有受管库健康检查处理，不重建到本机其他位置。 |
| 旧客户端打开新图片库配置 | 旧代码可能因图片扩展名校验拒绝加载；发布时需让所有使用共享 NAS 配置的客户端先升级，再创建图片库。 |

## 7. 实施顺序与验收

1. 模型和 API：加库类型、库默认时长、单张覆盖时长与扩展名校验；旧配置缺省视频。
2. 扫描和计划：类型过滤、显式条目校验、两级时长解析、缓存与命名规则。
3. 渲染：统一帧数、透明背景合成、静音音轨和纯图片项目。
4. 界面：新增类型选择、库默认时长、单张时长与恢复默认、素材预览与顺序卡片；从切片分类排除图片库。
5. 回归：淘宝闪购、已有通用项目、混合视频/图片项目及飞书同步任务。

验收样例至少覆盖：视频→图片→视频、图片在开头/结尾、纯图片、可选空图片库、必需坏图片、带透明通道、不同宽高比、0.1 秒及 60 秒边界、同库不同图片时长、修改库默认值但保留单张覆盖、清除覆盖后继承新默认值、时长修改后的缓存刷新、动态命名 `pool_*`、切片接口拒绝图片库、旧配置加载，以及同配置同种子可复现。输出检查画面、总帧数、音轨、叠加层、清单和预览一致性。

## 8. 需要确认的产品选择

1. **本期图片库是否只支持静态图片？** 建议是；动画图片和图片运动效果后续单独设计。
2. **透明图片的底色是否沿用输出背景色？** 建议沿用，保证预览与渲染一致。

按上述范围（含库默认时长和单张覆盖时长），初步估计为 4–6 个开发日，包含代码、样例渲染和回归；若加入动效或视频图片混合库，需要另行估算。
