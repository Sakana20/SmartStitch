# SmartStitch 异步切片任务与进度面板设计

## 1. 背景与结论

当前“切割并入库”是同步请求：前端先保存断点，再调用 `POST /api/v1/timeline/slices`，直到全部 FFmpeg 切片、ffprobe 校验和清单写入结束后才收到响应。用户虽然仍能看到页面，但本次提交没有独立任务身份，切换到下一条视频后也无法安全地确认上一批是否仍在运行、完成了多少或在哪一段失败。

当前代码的关键限制是：

- `exportTimelineSlices()` 一直 `await` 整批切片结果，按钮长期显示“正在批量切割”。
- API 直接调用 `TimelineSlicer.export()`，没有先创建任务再返回。
- `TimelineSlicer.export()` 使用批次级锁，并依次调用阻塞式 `subprocess.run()`。
- 切片清单只有 `pending/running/succeeded/failed` 结果，没有可供界面持续展示的实时进度。
- 当前完成回调直接修改时间线页面状态；若用户已切换视频，旧请求可能把提示写到新视频的工作区。

结论：切片应改为异步任务。用户只等待“保存审核版本、完成全批预检、固化任务快照并成功入队”，不等待 FFmpeg。入队后可以立即审核下一条视频，通过时间线页中的“切片队列”面板持续查看进度；完整历史同时进入“任务记录”。

异步化不代表提高切片并发。第一版仍建议按 FIFO 串行执行切片批次，优先保证电脑和 NAS 在用户继续分析、预览视频时保持可用。

## 2. 目标与非目标

### 2.1 目标

- 点击“切割并入库”后快速返回任务 ID，不等待 FFmpeg 完成。
- 用户可以立即切换到下一个源视频，继续分析、打断点和提交新任务。
- 时间线页面始终显示最近切片任务、队列状态、总进度和成功/失败数量。
- 点击任务行可以查看每个输出单元的类别、源区间、当前阶段、输出路径和错误。
- 支持取消排队中或运行中的切片任务，并安全清理 `.part.mp4`。
- 服务重启后，历史状态仍可解释，不把中断任务伪装成成功。
- 保留审核版本、配置哈希、源文件指纹、入库目录校验和请求幂等性。
- 已入队任务使用不可变快照；用户之后修改当前时间线，不影响后台任务。

### 2.2 非目标

- 第一版不追求多个切片批次同时编码。
- 第一版不自动重试所有失败条目；只提供明确的手动“重试失败项”。
- 第一版不在服务重启后静默自动恢复 FFmpeg；中断任务由用户确认后继续。
- 不把切片任务与普通成片渲染强行合并成同一种业务模型。
- 不改变现有精确重编码、ffprobe 校验、分类入库和文件命名规则。

## 3. 推荐用户流程

```text
用户完成当前视频审核与分类
        ↓
点击“加入切片队列”
        ↓
保存 review_revision
        ↓
后端全批预检并固化不可变快照
        ↓
返回 202 Accepted + slice_job_id
        ↓
前端将任务加入“切片队列”面板
        ├──────────────→ 用户继续审核下一条视频
        ↓
后台按队列执行 FFmpeg → ffprobe → 原子入库
        ↓
SSE 更新任务和条目进度
        ↓
完成、部分失败、失败或取消
```

只有“保存审核版本 + 预检 + 快照入队”属于用户必须等待的提交阶段。这个阶段不启动长时间 FFmpeg，正常情况下应在短时间内完成；NAS 异常、配置冲突或目标目录失效应在这里直接返回错误，不创建一个注定失败的任务。

## 4. 时间线页切片队列面板

### 4.1 位置与视觉

在时间线页增加可折叠的“切片队列”面板，建议放在源视频切换区域下方、当前视频工作区上方。这样切换视频时面板不会被替换，也不会挤占时间线轨道内部空间。

面板继续使用现有圆角、边框、状态标签、进度条和文字颜色，不参考 Premiere Pro 的颜色。

```text
┌ 切片队列                              2 个处理中  [收起] ┐
│ 00132…重生了.mp4   正在切片  3 / 8      █████░  61%  › │
│ 00133…春日宴.mp4   等待执行  0 / 5      ░░░░░   0%  › │
│ 00131…归途.mp4     部分失败  6 / 7      ██████  100% › │
└──────────────────────────────────────────────────────┘
```

面板规则：

- 没有任务时显示轻量空状态，不占用大块高度。
- 存在 `queued/running/cancelling` 任务时默认展开。
- 最多直接显示最近 3～5 条，更多任务在面板内滚动或进入“任务记录”。
- 每行显示源视频名、短任务号、状态、总体进度、成功/失败数和详情入口。
- 任务完成后保留在列表，不因用户正在审核其他视频而消失。
- `partial_failed/failed/interrupted` 必须保持显眼，不能自动折叠后只显示“已完成”。
- 面板刷新不得重建视频元素、修改播放头、切换当前源视频或覆盖当前片段草稿。

### 4.2 提交后的页面行为

按钮文案由“切割并入库”调整为“加入切片队列”。点击后：

1. 按钮短暂显示“正在保存并入队…”。
2. 保存当前断点审核版本。
3. 使用本次草稿固定的 `client_request_id` 创建切片任务。
4. 收到 `202 Accepted` 后立即恢复时间线操作。
5. 显示“已加入队列 #abcd1234”，并将新行插入队列面板顶部。
6. 清空本次已提交的片段清单和合并选择，但保留断点、播放位置和审核结果。
7. 不自动切换视频；提供明确的“下一个视频”操作，由用户决定何时切换。

只有后端确认任务快照已经持久化后才能清空前端清单。网络断开或入队失败时必须保留原草稿，允许使用同一个 `client_request_id` 重试，不能生成重复任务。

### 4.3 任务详情

点击队列行打开现有风格的右侧抽屉。切片任务详情包含：

- 源视频名、源路径和任务短 ID。
- 目标视频库、审核版本、创建/开始/结束时间。
- 总体进度与当前阶段。
- 输出单元总数、源区间数、成功、失败、跳过和取消数量。
- 每个输出单元的类别、组合成员、预计时长、进度、输出路径和错误摘要。
- 运行中显示“取消任务”；失败或中断后显示“重试失败项”或“继续未完成项”。
- 终态任务提供“打开入库目录”和“查看切片清单”。

“任务记录”页面增加“成片渲染 / 切片入库”筛选。两类任务可以共享列表样式和详情抽屉框架，但字段和操作由 `job_type` 分支渲染。

## 5. 状态模型

### 5.1 批次状态

切片任务使用与渲染任务一致的主状态词：

```text
queued → running → completed
                 ↘ partial_failed
                 ↘ failed

queued/running → cancelling → cancelled
queued/running/cancelling --服务退出→ interrupted
```

含义：

- `queued`：快照已持久化，等待后台执行。
- `running`：至少一个条目正在 FFmpeg、ffprobe 或提交正式文件。
- `cancelling`：已收到取消请求，等待当前子进程退出和临时文件清理。
- `completed`：所有非跳过条目成功。
- `partial_failed`：至少一个成功且至少一个失败。
- `failed`：没有任何非跳过条目成功。
- `cancelled`：用户取消；已经成功提交的正式文件保留。
- `interrupted`：服务异常退出或重启时任务尚未到终态。

### 5.2 条目状态与阶段

条目状态：

```text
pending / running / succeeded / failed / cancelled / skipped
```

运行阶段 `phase`：

```text
waiting / probing_audio / encoding / verifying / committing / done
```

`status` 用于业务判断，`phase` 只用于给用户解释当前正在做什么。不能因为 ffprobe 阶段没有编码进度就让进度条倒退或突然归零。

## 6. 数据模型

### 6.1 SliceJob

切片任务确定在现有 `data/smartstitch.db` 中新增独立的 `slice_jobs` 表，不复用普通成片任务的 `jobs` 表，也不创建第二个 SQLite 数据库文件。这样可以保持两类任务的字段、状态流转和清理逻辑彼此独立，同时复用现有数据库的连接、备份和运维方式：

```sql
CREATE TABLE slice_jobs (
  id TEXT PRIMARY KEY,
  request_key TEXT NOT NULL UNIQUE,
  payload TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

第一版可继续用 JSON payload，字段至少包含：

```json
{
  "id": "8d21...",
  "short_id": "8d21a934",
  "job_type": "timeline_slice",
  "request_key": "现有 manifest_key",
  "client_request_id": "客户端稳定请求 ID",
  "status": "queued",
  "progress": 0.0,
  "analysis_id": "...",
  "review_revision": "...",
  "config_id": "product-library",
  "config_hash": "...",
  "library_id": "...",
  "source": {
    "path": "/.../source.mp4",
    "name": "source.mp4",
    "size_bytes": 123,
    "modified_at_ns": 456,
    "fps": 30.0
  },
  "output_unit_count": 8,
  "source_segment_count": 10,
  "success_count": 0,
  "failure_count": 0,
  "cancelled_count": 0,
  "skipped_count": 0,
  "created_at": "...",
  "started_at": null,
  "finished_at": null,
  "manifest_path": "/.../工作记录/切片清单/slice-xxxx.json",
  "items": []
}
```

每个 item 在现有切片清单字段基础上增加：

- `progress`：`0.0～1.0`。
- `phase`。
- `started_at`、`finished_at`。
- `attempts`。
- `ffmpeg_exit_code`、`ffprobe_result`。
- `temporary_path`。
- `error`。

### 6.2 SQLite 与库内清单的职责

- SQLite 是本机任务队列和界面查询的权威状态。
- `<视频库>/工作记录/切片清单/slice-<request_key>.json` 是随视频库移动的业务追溯记录。
- 每次状态更新先在内存中形成完整新状态，先提交 SQLite，再原子替换库内 JSON 清单。
- 清单写入失败时不得回滚已成功的正式输出或伪造任务状态；应在 SQLite 中记录 `manifest_sync_error`，后续重试同步。
- 正式文件成功提交后，清单必须立即记录该条目成功，不能只等整批结束再写。
- 删除本机任务记录不删除库内清单和已经入库的视频。

### 6.3 数据库访问与并发约束

- 普通成片任务和切片任务共用一个数据库访问层和同一把进程内写锁；不得由 `JobDatabase` 和 `SliceJobDatabase` 各自持有互不知情的写锁。
- 数据库启用 WAL 模式和 `busy_timeout`，连接仍按操作短时持有，不在 FFmpeg 执行期间保持事务。
- 进度保存必须节流，避免 FFmpeg 高频回调与普通成片任务争抢 SQLite 写锁。
- 建表使用 `CREATE TABLE IF NOT EXISTS`；应用启动时只创建缺失表，不重写、不迁移现有 `jobs` 记录。
- `request_key` 保持唯一约束，并作为网络超时重试和重复点击时的幂等边界。

## 7. API 设计

### 7.1 创建异步切片任务

```http
POST /api/v1/timeline/slice-jobs
```

请求继续使用现有 `TimelineSliceRequest`：

```json
{
  "analysis_id": "0123456789abcdef01234567",
  "config_id": "product-library",
  "review_revision": "64位审核版本",
  "current_config_hash": "64位配置哈希",
  "assignments": [
    {
      "client_unit_id": "unit-1",
      "segment_indexes": [2],
      "category": "benefit_1"
    },
    {
      "client_unit_id": "unit-2",
      "segment_indexes": [4, 7],
      "category": "ending"
    }
  ],
  "client_request_id": "稳定且可重试的请求 ID"
}
```

成功返回 `202 Accepted`：

```json
{
  "id": "8d21a934...",
  "short_id": "8d21a934",
  "job_type": "timeline_slice",
  "status": "queued",
  "progress": 0.0,
  "source_name": "source.mp4",
  "output_unit_count": 8,
  "success_count": 0,
  "failure_count": 0,
  "idempotent": false
}
```

重复的 `client_request_id + analysis_id + review_revision + config_id` 返回同一任务，仍可使用 `200` 或 `202`，但必须设置 `idempotent: true`。不得因为前端超时重试而生成第二批相同文件。

### 7.2 查询与控制

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/timeline/slice-jobs?limit=20&status=active` | 查询切片任务摘要 |
| GET | `/timeline/slice-jobs/{id}` | 查询任务及所有条目 |
| GET | `/timeline/slice-jobs/events` | 推送队列摘要变化，供常驻面板使用 |
| GET | `/timeline/slice-jobs/{id}/manifest` | 读取或下载库内切片清单 |
| POST | `/timeline/slice-jobs/{id}/cancel` | 取消排队中或运行中任务 |
| POST | `/timeline/slice-jobs/{id}/retry-failed` | 基于原快照重试失败项 |
| POST | `/timeline/slice-jobs/{id}/resume` | 重新校验并继续中断任务 |
| DELETE | `/timeline/slice-jobs/{id}` | 只删除终态的本机任务记录 |

常驻面板只建立一个队列级 SSE 连接，不为每一行分别建立 EventSource。SSE 断线后自动重连，并立即调用列表接口恢复权威状态。

迁移期间保留旧 `POST /timeline/slices` 供回归测试或兼容调用；新前端只调用 `/timeline/slice-jobs`。稳定后再删除同步端点。

## 8. 后端拆分

现有 `TimelineSlicer.export()` 应拆为两个职责：

### 8.1 `prepare(request)`：同步、快速、不可执行 FFmpeg

负责：

- 校验 `review_revision`。
- 根据审核记录重新解析 `segment_indexes`，生成权威帧区间。
- 校验同一源片段没有被多个输出单元重复使用。
- 校验配置哈希、受管库健康、类别和目标目录。
- 校验源文件存在且指纹未变化。
- 分配不会与已有文件或排队任务冲突的输出路径。
- 构造不可变 SliceJob 和 item 快照。
- 先持久化初始 `queued` SQLite 记录，再原子写入库内清单；两者均成功后才将任务交给工作线程。

任何一步失败都不入队、不启动 FFmpeg，并返回当前已有的 `409/422` 语义。

### 8.2 `run(job_id)`：后台消费不可变快照

负责：

- 从 SQLite 读取已持久化快照，不读取前端当前状态。
- 将任务从 `queued` 改为 `running`。
- 按条目执行 FFmpeg、ffprobe、原子改名。
- 节流写入进度、计数和清单。
- 捕获单条错误后继续其他条目。
- 汇总终态并发送事件。

新增 `SliceJobManager`，结构可参考现有 `JobManager`，但使用单独的 `slice_jobs` 表、队列、取消事件和子进程登记表。两个 Manager 必须共用底层 SQLite 访问层和写锁，不能因为业务表独立就建立两套数据库并发控制。第一版使用一个常驻工作线程消费 FIFO 队列，避免每次请求各自创建一个不受控后台线程。

## 9. FFmpeg 实时进度

当前 `subprocess.run(capture_output=True)` 只能在 FFmpeg 退出后返回。异步任务应改用 `subprocess.Popen`：

```text
ffmpeg ... -progress pipe:1 -nostats <temporary.part.mp4>
```

解析字段：

- `out_time_us` 或 `out_time_ms`：当前输出媒体时间。
- `speed`：可选展示，不参与完成判断。
- `progress=continue/end`：本轮进度状态。

单条进度：

```text
item_progress = clamp(out_time / expected_output_duration, 0, 0.99)
```

进入 ffprobe 时固定为 `0.99` 且 `phase=verifying`；只有校验通过并原子改名后才设为 `1.0/succeeded`。

这里的 progress 表示“处理工作完成度”，不是成功率。条目一旦进入 `failed/cancelled/skipped` 等终态，也将 progress 固定为 `1.0`，使已经结束的部分失败任务最终显示 100%；成功与失败由独立计数和状态表达。重试失败项时，对应条目的新 attempt 再从 0 开始。

总体进度按预计输出时长加权，避免 2 秒片段和 2 分钟片段各占相同百分比：

```text
overall_progress =
  Σ(item.expected_duration × item.progress)
  / Σ(non_skipped_item.expected_duration)
```

进度持久化应节流，例如满足任一条件才写入：

- 距上次写入至少 500 ms；
- 百分比增加至少 1%；
- 状态或阶段发生变化；
- 条目进入终态。

stderr 必须持续消费并只保留尾部若干行，避免管道写满导致 FFmpeg 假死。

## 10. 队列、并发与继续审核

- 切片批次默认 FIFO，同一时刻只运行一个切片 FFmpeg。
- 一个批次内部第一版仍串行处理输出单元；这样取消、清单恢复和 NAS 写入压力最可控。
- 异步只解除用户等待，不等于无限并发。
- FFmpeg 在独立子进程执行，Python 主服务仍可处理切换视频、分析、波形和保存审核请求。
- 后台切片 FFmpeg 必须尝试以略低的操作系统 CPU 调度优先级运行：POSIX 系统设置 `nice +5`。用户发起的片段识别保持正常优先级；不对后台切片设置 macOS `taskpolicy -b`，避免 NAS 或本地磁盘 I/O 被过度限速。如果受限运行环境拒绝优先级调整，也不得因此中断切片。
- 优先级下调只用于异步队列中的切片编码；同步切片接口仍保持正常优先级。
- 后续若同时运行大量普通渲染任务，应引入跨 `JobManager` 与 `SliceJobManager` 的共享 FFmpeg 容量限制；这不是异步切片首版的阻塞项。

后台任务绝不能持有整个 `TimelineSlicer` 的批次级 `RLock` 等待 FFmpeg。锁只保护任务创建、输出路径预留和状态更新等短临界区。

### 10.1 Apple Silicon 硬件加速策略

当前实现状态：Apple Silicon 异步后台切片已接入 VideoToolbox 硬件编码与 `libx264` 自动回退；普通成片仍默认使用 `libx264`，时间线识别仍未传入 `-hwaccel videotoolbox`。硬件编码与硬件解码分开控制，不做全局无条件切换。

#### 后台切片

- Apple Silicon 上优先尝试 `h264_videotoolbox` 进行硬件编码，这是第一优先级加速项。
- 首个后台切片任务创建时通过 FFmpeg encoder capability 检查确认 `h264_videotoolbox` 可用，并在进程生命周期内缓存结果；不得只根据 macOS 或 CPU 型号推断。
- VideoToolbox 不沿用 `libx264` 的 `-crf 18 -preset fast` 语义。当前硬件路径使用 `-q:v 65 -profile:v high -pix_fmt yuv420p`，并保留 `+faststart`；该质量参数还需用真实业务素材继续标定。
- 硬件 encoder 不可用、启动失败或输出校验失败时，清理本次 `.part.mp4`，对同一条目自动回退到 `libx264`；回退不得生成两个正式文件。
- 任务快照和库内切片清单必须记录计划 encoder、实际 encoder、硬件加速是否成功以及回退原因，保持可审计。
- 现有 `nice +5` 仅用于软件 CPU 调度，不应被当作 VideoToolbox 媒体引擎的流控手段。切片队列仍保持单 FFmpeg 串行，避免多个硬件编码任务同时抢占媒体引擎和 NAS 带宽。

#### 普通成片

- 普通成片渲染可增加“自动 / VideoToolbox / libx264”编码选项，但不静默改写已有配置的 `video_codec`，避免历史任务在不知情时发生画质、码率和文件大小变化。
- “自动”在 Apple Silicon 上可优先 VideoToolbox，其他平台或能力检查失败时使用 `libx264`。实际 encoder 和回退信息必须写入成片任务记录。

#### 时间线识别

- 转场识别依赖 `select='gt(scene,...)',showinfo` 软件滤镜读取像素；VideoToolbox 解码得到的硬件帧可能仍需回传系统内存，不能只以解码阶段的 CPU 下降判定加速有效。
- 语音停顿和波形生成是音频处理，不会因视频硬件解码直接加速。
- 识别阶段的 `-hwaccel videotoolbox` 只作为实验性优化：必须对同一组 H.264、HEVC、不同分辨率和帧率素材做端到端基准，确认总分析耗时下降且候选断点完全一致后才能默认启用。
- 硬件解码出现不支持编码、像素格式、滤镜交接或 FFmpeg 错误时，必须自动回退到当前软件识别路径，不向用户暴露一个只能手工处理的失败。

## 11. 输出路径预留与幂等

异步队列引入一个新问题：任务 A 的正式文件尚未生成时，任务 B 可能选择到相同输出路径。

创建任务时必须在管理器锁内同时检查：

- 磁盘上已经存在的正式文件。
- 所有 `queued/running/cancelling/interrupted` 任务已预留的 `output_path`。
- 本次任务内已经分配的路径。

冲突时继续使用现有 `-v2/-v3` 规则。输出路径一旦写入快照不得在执行阶段重新选择，否则清单、界面和实际文件会不一致。

同一请求重试时直接查 `request_key` 唯一索引并返回已有任务。已经成功的正式文件不重新编码；“重试失败项”创建新的 attempt，但继续引用原任务快照和原定输出路径。

## 12. 取消、失败与恢复

### 12.1 取消

- `queued`：直接将所有 pending 条目标为 cancelled，工作线程取到时跳过。
- `running`：设置取消事件，对登记的 FFmpeg 子进程先 `terminate()`，超时后 `kill()`。
- 当前 `.part.mp4` 清理后，未开始条目标为 cancelled。
- 已经 `succeeded` 的正式文件保留，不因取消整批而删除。
- 最终状态为 `cancelled`，详情中仍显示已成功数量。

### 12.2 单条失败

- 清理该条目的 `.part.mp4`。
- 保存 FFmpeg/ffprobe 错误摘要。
- 继续后续条目。
- 整批根据成功和失败数量进入 `partial_failed` 或 `failed`。

### 12.3 服务重启

启动时把遗留的 `queued/running/cancelling` 任务标为 `interrupted`，清理能够确认属于该任务的 `.part.mp4`。不静默恢复，原因是源文件、NAS 挂载和配置可能已变化。

用户点击“继续未完成项”时重新校验：

- 源路径和指纹。
- 视频库身份与布局。
- 配置类别仍存在。
- 已成功输出仍存在且可通过 ffprobe。
- 待执行输出路径仍未被其他任务占用。

校验通过后只执行未成功条目。

## 13. 前端状态隔离

每个异步提交必须捕获自己的不可变上下文：

- `analysis_id`、源视频名。
- `review_revision`。
- `config_id/config_hash`。
- assignments 和稳定 `client_request_id`。

任务事件只更新 `state.sliceJobs` 和队列面板，不能直接写入当前 `state.timeline.analysis`、`sliceUnits`、`selectedSegmentId` 或当前视频的结果文案。

任务完成后的素材刷新规则：

- 当前仍选中相同 `config_id` 时，可以静默刷新素材计数。
- 当前已切到其他配置时，只显示完成通知，不切换配置、不覆盖素材表。
- 多个任务连续完成时合并刷新，避免重复扫描 NAS。

## 14. 兼容与迁移

推荐分三步实施：

1. 抽离 `prepare/run`，保持同步端点行为不变，补齐进度回调和取消能力。
2. 抽离共享 SQLite 访问层，启用 WAL 和 `busy_timeout`，新增 `slice_jobs` 表、`SliceJobManager`、异步 API 和回归测试；同步端点继续可用。
3. 接入队列面板和任务记录筛选，新前端切换到 `202` 异步接口，稳定后移除同步端点。

已有库内切片清单继续可读。旧清单没有 `job_id/progress/phase` 时按历史终态展示，不要求批量迁移。

普通渲染任务旧记录没有 `job_type` 时，前端按 `render` 处理。

## 15. 测试矩阵

| 场景 | 期望结果 |
|---|---|
| 提交 10 个输出单元 | 快速返回 `202 queued`，FFmpeg 在后台执行 |
| 入队后立即切换下一视频 | 新视频可正常分析和编辑，旧任务进度继续更新 |
| 旧任务完成时正在编辑新视频 | 只更新队列面板，不覆盖新视频状态或片段清单 |
| 连续提交多个视频 | 任务按 FIFO 排队，面板分别显示来源和进度 |
| 同一请求因网络超时重试 | 返回同一 job，不重复切片 |
| 两个排队任务目标文件名相同 | 第二个任务在入队时得到稳定的 `-v2` 路径 |
| FFmpeg 正常输出进度 | 单条与总体进度单调递增，完成前不显示 100% |
| ffprobe 校验较慢 | 显示“正在校验”，进度保持 99% |
| 单条 FFmpeg 失败 | 其他条目继续，批次为 partial_failed 或 failed |
| 取消 queued 任务 | 不启动 FFmpeg，pending 项变为 cancelled |
| 取消 running 任务 | 子进程退出、`.part` 清理、成功文件保留 |
| SSE 断线重连 | 通过列表/详情接口恢复权威状态 |
| 成片任务与切片任务同时高频更新 | 不出现未处理的 `database is locked`，两类任务状态均可持续查询 |
| SQLite 成功但库内清单写入失败 | 任务状态不回退，记录同步错误并可重试修复清单 |
| 服务在切片中退出 | 重启后任务显示 interrupted，不伪装完成 |
| 中断后继续 | 重新预检，仅执行未成功条目 |
| NAS 中途断开 | 当前项失败并保留错误，服务不崩溃 |
| 用户删除或修改当前断点 | 已入队快照不变，后台结果可追溯到旧 review_revision |
| 面板存在大量历史任务 | 只渲染有限摘要，滚动和时间线操作保持流畅 |
| Apple Silicon 硬件切片 | 使用 `h264_videotoolbox`，正式文件可通过 ffprobe，任务清单记录实际 encoder |
| VideoToolbox 不可用或编码失败 | 清理本轮临时文件，自动回退 `libx264`，不产生重复正式输出 |
| 软件与硬件切片对比 | 时长、音轨、帧率、分辨率和可播放性一致，画质和文件大小在确定的验收阈值内 |
| 时间线硬件解码基准 | 候选断点与软件路径完全一致，且端到端分析耗时有明确收益；否则不默认启用 |

## 16. 验收标准

1. 点击“加入切片队列”后不等待 FFmpeg，收到任务 ID 即恢复操作。
2. 用户可在上一批运行期间切换、分析、审核并提交其他视频。
3. 时间线页常驻队列面板显示 queued/running/终态任务和实时总体进度。
4. 详情抽屉显示每个输出单元的进度、阶段、类别、源区间、路径和错误。
5. 前端刷新或 SSE 重连后能从 SQLite 恢复真实任务状态。
6. 同一客户端请求不会创建重复任务或重复输出。
7. 排队任务之间不会预留相同正式输出路径。
8. 取消任务会终止 FFmpeg、清理临时文件并保留已成功文件。
9. 服务重启后运行中任务标为 interrupted，并可经重新预检继续未完成项。
10. 后台任务完成时不会修改用户当前正在审核的视频状态。
11. 库内切片清单持续记录审核版本、源指纹、条目状态和最终输出，视频库移动后仍可追溯。
12. 普通成片渲染任务的现有创建、进度、取消和历史记录不发生回归。
13. `jobs` 与 `slice_jobs` 使用同一 `smartstitch.db` 和共享写入协调，高频进度更新下不出现未处理的数据库锁冲突。
14. Apple Silicon 后台切片优先使用 VideoToolbox，且能在不丢失任务快照、进度、取消、校验和幂等性的前提下回退到 `libx264`。
15. 硬件与软件编码的实际路径、失败与回退原因可从 SQLite 任务记录和库内清单中追溯。
16. 时间线硬件解码在断点一致性和端到端耗时未通过真实素材基准前，不作为默认路径。

## 17. 推荐实现顺序

1. 将 `TimelineSlicer` 拆为预检快照和单条执行函数。
2. 将 FFmpeg 改为 `Popen + -progress pipe:1`，实现进度回调和安全取消。
3. 抽离共享 SQLite 访问层，新增 `slice_jobs` 表和 `SliceJobManager`、FIFO 工作线程及恢复标记。
4. 新增异步创建、列表、详情、SSE、取消和重试接口。
5. 接入时间线常驻“切片队列”面板，并隔离任务状态与当前视频状态。
6. 扩展“任务记录”页面，区分成片渲染与切片入库。
7. 用真实 NAS 素材验证边切边审、取消、断网、重启和多任务排队。
8. 增加 encoder capability 检查和切片级 `h264_videotoolbox → libx264` 回退，用同一组真实素材标定硬件质量/码率参数。
9. 在断点一致性前提下基准测试时间线 VideoToolbox 硬件解码，有明确端到端收益再设为默认。
10. 稳定后移除旧同步切片端点。
