# 视觉去重边框与高斯模糊背景设计

## 1. 文档状态

- 状态：全局边框库核心链路已实现（2026-09-20）；模糊背景与透明边框独立启停的交互、配置迁移、计划和渲染链路已实现（2026-09-22）；旧项目边框批量导入工具仍待补充。
- 后续扩展：边框与烟花等多特效的可排序图层、多全局库和百分比透明度见[21-视觉去重多特效图层与全局素材库设计](./21-视觉去重多特效图层与全局素材库设计.md)。
- 范围：保留现有模糊、缩放、透明叠加和顶层风险提示语链路，将边框来源从“每项目一个文件”升级为“所有项目共用一个全局边框库”。
- 基线：保留当前素材组合去重、时间线拼接、音频、VideoToolbox 回退和风险提示语图片逻辑。

本功能在产品和代码中统一称为“视觉去重”，用于和现有 `randomization.duplicate_policy` “素材组合去重”区分。它通过模糊背景、缩小前景和透明边框改变输出画面结构，但不承诺任何第三方平台的“去重通过率”。

## 2. 需求摘要

“视觉去重”包含一个控制整体是否生效的总开关，以及两个可以独立选择的子功能。关闭总开关时两个子功能都不执行，但各自的选择和参数必须保留：

1. **模糊背景**：缩小清晰主画面，并用同一画面的高斯模糊版本补满四周。
2. **透明边框**：在当前主画面之上叠加从全局边框库选择的透明素材。

总开关开启后必须支持以下四种组合，功能 2 不得依赖功能 1：

| 模糊背景 | 透明边框 | 输出行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 保持现有基础画面，不增加视觉去重图层 |
| 开启 | 关闭 | 只缩小主画面并生成模糊背景 |
| 关闭 | 开启 | 不缩小、不模糊，直接在基础画面上叠加透明边框 |
| 开启 | 开启 | 先生成模糊背景和缩小前景，再叠加透明边框 |

当两个功能同时开启时，每条成片执行以下处理：

1. 将已完成时间线拼接和画布归一化的画面拆成两路。
2. 底路保持满幅，执行高斯模糊，作为背景。
3. 上路按比例缩小原画面并居中，四周露出模糊背景。
4. 在上述画面上叠加一个透明边框，素材可为 QuickTime Animation/RLE 透明视频或透明图片。
5. 最后才叠加现有风险提示语图片，确保其始终是最高视觉图层。

默认效果参考用户提供的图 1：720×1280 成片中，前景按 `0.90` 缩放后居中，底层为同一时刻的模糊原画面，透明边框覆盖全幅。

## 3. 范围与非目标

### 3.1 首版范围

- 模糊背景和透明边框分别按配置开启或关闭，旧配置迁移后保持原有输出不变。
- 支持单独使用“模糊背景 + 缩小原画面”、单独使用透明边框，或同时使用两者。
- 在 SmartStitch 共享根目录维护一个全局边框库，所有项目直接复用，不在每个项目中重复上传。
- 每条成片可从全局库的兼容素材中随机选择一个边框，也可由项目固定指定一个边框。
- 支持 `.mov` 容器中的 `qtrle` 透明视频，以及含 Alpha 的 PNG/WebP 图片。
- 动态边框从第 0 帧开始，循环播放到成片结束。
- 边框作用于全片；风险提示语继续使用现有 `full/main/benefits/custom` 时段协议。
- 输出分辨率、帧率、时长和音轨行为不变。

### 3.2 首版非目标

- 不随机修改速度、音调、色相、噪点或局部像素。
- 不在同一条成片中途切换多个边框。
- 不在同一条成片的中途切换多个边框；随机选择只在生成计划时执行一次。
- 不把全局边框复制到每个项目的受管视频库中。
- 不改变风险提示语图片的扫描、选择、时段和位置逻辑。
- 不将普通无 Alpha 的 MOV/MP4/JPG 当作透明边框。

## 4. RLE 素材定义与预检

### 4.1 “RLE 视频”的精确定义

“RLE”在不同软件中可能指不同格式。本项目首版将它明确定义为：

```text
容器：QuickTime MOV
视频编码：QuickTime Animation / qtrle
像素格式：含 Alpha，当前标准样例为 argb
```

本机 FFmpeg 7.1 已实测可解码 `qtrle`，其编码器也列出 `argb` 为支持的像素格式。最小实验已验证：0.5 秒、12 fps 的 ARGB/qtrle 透明边框可循环叠加到 1 秒、24 fps 的 H.264 主画面，输出音频和时长正常。

### 4.2 允许的素材

| 类型 | 扩展名 | 预检要求 | 播放方式 |
| --- | --- | --- | --- |
| RLE 动态边框 | `.mov` | `codec_name=qtrle`，视频流含 Alpha，时长大于 0 | 从 0 开始循环 |
| 静态边框 | `.png` / `.webp` | 解码后像素格式含 Alpha | 单帧延长到全片 |

不仅检查扩展名。扫描器必须用 `ffprobe` 至少读取：

- `codec_name`、`pix_fmt`、`width`、`height`、`r_frame_rate`、`duration`。
- 是否存在视频流。
- 是否存在 Alpha 通道。

只检查 `pix_fmt=argb` 仍不足以证明素材实际有透明区域。预检应抽取首帧、中帧和尾帧的 Alpha 平面；若所有抽样像素均为完全不透明，`required` 模式直接阻止生成，避免黑底素材覆盖整个视频。

### 4.3 Alpha 模式

默认按直通 Alpha（`straight`）处理。高级配置允许改为 `premultiplied`，用于解决特定软件导出的预乘 Alpha 边缘黑边。该字段必须显式传给 FFmpeg `overlay` 滤镜，不依赖不同 FFmpeg 版本的默认行为。

## 5. 图层协议

最终图层顺序从下到上固定为：

```text
④ 风险提示语图片（现有 benefit_overlay，始终最高）
③ 透明 RLE/图片边框（visual_border）
② 缩小后的原视频前景（居中）
① 高斯模糊原视频背景（满幅）
```

这个顺序是渲染器协议，不由配置改动。即使边框素材和风险提示语的位置重叠，重叠区域也必须显示风险提示语。

### 5.1 时序与音频

- 模糊背景和前景来自同一个 `[basev]` 并共享 PTS，不得各自重新解码原素材。
- 边框循环只影响边框输入，不改变主时间线。
- 音频继续使用现有 `[outa]`，不从边框 MOV 映射任何音轨。
- 视频结束由主时间线决定，不得因边框过短而提前结束，也不得因无限循环而无法结束。

## 6. 配置设计

新增顶层 `visual_dedup` 字段，不复用 `benefit_overlays`：

```yaml
visual_dedup:
  # 总开关；关闭时保留两个子功能的配置，但二者都不执行。
  enabled: false

  foreground:
    # 按输出画布宽高同比缩放，并居中叠加。
    scale: 0.90

  background:
    # 功能 1 的独立开关，不控制透明边框。
    enabled: true
    mode: gaussian_blur
    # FFmpeg gblur 参数；默认以 720×1280 为视觉基准。
    sigma: 20.0
    steps: 2
    # 首版默认不改亮度，保留为高级设置。
    brightness: 0.0

  border_overlay:
    # 功能 2 的独立开关和必需性语义，不受 background.enabled 控制。
    # disabled / optional / required；required 在没有兼容边框时阻止生成。
    mode: disabled
    source: global_library
    # random 从兼容素材中按权重选择；fixed 固定使用一个素材。
    selection_mode: random
    fixed_asset_id: ""
    # 空列表表示使用全局库中全部启用且与当前输出兼容的素材。
    enabled_asset_ids: []
    # 项目级权重覆盖；未列出的素材使用全局默认权重。
    weights: {}
    # auto 根据 ffprobe 判断 image 或 qtrle_video。
    media_kind: auto
    # exact 要求素材与输出画布同尺寸；stretch 允许拉伸。
    scale_mode: exact
    playback: loop
    opacity: 1.0
    # auto 使用边框库记录的素材 Alpha 模式；也可由高级模式覆盖。
    alpha_mode: auto
```

### 6.1 取值和默认值

| 字段 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `true/false` | `false` | 视觉去重总开关；关闭时保留子功能配置但不执行 |
| `background.enabled` | `true/false` | `true` | 是否选择模糊背景和缩小主画面；不控制透明边框，总开关关闭时不执行 |
| `foreground.scale` | `0.70～1.00` | `0.90` | 过小会显著损失主画面可见面积 |
| `background.sigma` | `0～100` | `20` | `0` 等于不模糊 |
| `background.steps` | `1～6` | `2` | 越大速度越慢 |
| `background.brightness` | `-1～1` | `0` | 使用 `eq=brightness` |
| `border_overlay.opacity` | `0～1` | `1` | 边框整体透明度 |
| `border_overlay.selection_mode` | `random/fixed` | `random` | 随机或固定选择全局边框 |
| `border_overlay.fixed_asset_id` | 全局素材 ID | 空 | 仅固定模式使用 |
| `border_overlay.enabled_asset_ids` | 素材 ID 列表 | 空 | 空表示全部兼容素材 |
| `border_overlay.weights` | `{asset_id: weight}` | 空 | 项目级权重覆盖 |
| `border_overlay.alpha_mode` | `auto/straight/premultiplied` | `auto` | `auto` 使用素材库元数据 |

为了满足 H.264/yuv420p 的偶数尺寸要求，前景计算结果必须向下取最近偶数：

```text
foreground_width  = trunc(output_width  * scale / 2) * 2
foreground_height = trunc(output_height * scale / 2) * 2
```

`border_overlay.scale_mode=exact` 是推荐模式。若输出是 720×1280，边框也应按 720×1280 导出；`stretch` 只用于已知纵横比一致的素材。

### 6.2 独立启停与兼容性

- `visual_dedup` 整体有默认值，不强制提升现有 schema 2/3 版本。
- 新配置以 `visual_dedup.enabled` 控制视觉去重整体是否生效，以 `background.enabled` 控制功能 1，以 `border_overlay.mode` 控制功能 2。总开关只门控运行结果，不得改写两个子功能的选择或参数。
- 旧 YAML 没有 `visual_dedup` 时，两个功能都默认关闭。
- 旧 YAML 只有 `visual_dedup.enabled` 时，兼容读取设置 `background.enabled = true`，同时原样保留 `visual_dedup.enabled` 和 `border_overlay.mode`。这是因为旧总开关开启时必然执行模糊背景；迁移后即使总开关当前关闭，再次开启也应保持原行为。
- 迁移后写回显式的总开关、`background.enabled` 和 `border_overlay.mode`；边框的随机/固定策略、素材 ID、权重及其他高级参数继续保留。
- 用户主动保存配置时才写入新字段，不对共享 NAS 配置做启动时批量改写。

### 6.3 全局边框库

全局库位于 SmartStitch 共享配置根目录，而不是某个项目的 `source_root`：

```text
<SmartStitch 共享根>/
├── 全局素材库/
│   └── 视觉特效/
│       └── effect_1/
│           ├── <content-id>.mov
│           ├── <content-id>.png
│           └── <content-id>.webp
└── .smartstitch/
    └── visual-border-library.json
```

- NAS 配置根为权威位置，多台电脑挂载同一 SmartStitch 根目录后看到同一批边框；`effect_1` 是稳定目录，库显示名可在系统中独立修改。
- `asset_id` 由文件内容哈希生成，文件改名不改变身份；相同内容重复上传时去重。
- 注册表记录显示名称、内容哈希、大小、修改时间、编码、像素格式、尺寸、帧率、时长、透明度检查结果、默认权重、启用状态和 Alpha 模式。
- 上传使用流式写入、大小上限、临时文件预检和同卷原子提交，不把大型 MOV 整体读入内存。
- “替换”实际创建新内容版本，不原地覆盖已有内容寻址文件，避免已创建任务在执行前读到不同内容。
- 删除首期采用软停用；已进入任务计划的素材路径保持可读。物理垃圾回收不属于首期范围。
- 全局库写操作使用独立的库版本号/内容哈希和跨进程锁，不复用某个项目的配置租约。

## 7. 扫描、计划与追溯

### 7.1 扫描器

新增独立类别 `visual_border`，不改造现有只支持图片的 `benefit_overlay`。扫描来源是全局边框库注册表，而不是当前项目目录。

- `disabled`：不选择边框；无论模糊背景是否开启都不叠加边框。
- `optional`：没有兼容素材时允许继续，不叠加边框；模糊背景是否生成由 `background.enabled` 独立决定。
- `required`：全局库不可用或没有兼容素材时阻止创建任务。
- `selection_mode=fixed`：指定素材不存在、已停用或不兼容时阻止创建任务。
- `selection_mode=random`：从全局启用、项目允许且尺寸兼容的交集中按权重生成整批选择序列。

动态边框可以携带音轨，但系统必须忽略它并给出预检警告，不得将其混入成片。

### 7.2 计划和清单

当总开关开启且 `border_overlay.mode != disabled` 时，扫描器和计划器必须处理边框，但不得以 `background.enabled` 作为前置条件。总开关关闭时跳过两个子功能的运行期扫描和计划，同时保留其配置。计划器必须在渲染前为每条成片确定唯一 `visual_border` 并保存到 `PlanItem`。固定模式的全部条目使用同一素材；随机模式使用现有批次权重分配与种子机制，不能在 FFmpeg 启动时临时抽取。全局库后续被停用或新增素材都不得改变已经冻结的计划。

`manifest.json` 每条输出至少记录：

- 模糊背景是否开启、透明边框是否开启，分别记录，不合并成一个总状态。
- 前景缩放、模糊和亮度参数。
- 边框文件路径、文件名、大小、修改时间、编码、像素格式、尺寸、帧率和时长。
- 全局 `asset_id`、内容哈希、选择模式、最终权重和随机种子。
- 边框播放方式、Alpha 模式和透明度。
- 固定的最终图层顺序。

## 8. FFmpeg 渲染设计

### 8.1 接入位置

当前渲染器先将每段规整到目标尺寸和帧率，然后 concat 为 `[basev]`，最后叠加风险提示语。新链路应插入在 concat 与风险提示语之间：

```text
各段视频归一化
  → concat [basev]
  → 模糊背景 + 缩小前景 [dedupv]
  → 透明边框 [framedv]
  → 风险提示语 [outv]
  → H.264 编码
```

不应对每个拼接片段分别做模糊和边框，否则会重复搭建过滤链，增加性能开销和转场处的不一致风险。

总开关关闭时，渲染器必须直接使用 `[basev] → risk overlay`。总开关开启时，再按两个子功能的独立开关组装过滤链：

- 两者关闭：`[basev] → risk overlay`。
- 仅模糊背景开启：`[basev] → dedup → risk overlay`。
- 仅透明边框开启：`[basev] → border → risk overlay`，不得隐式缩小或模糊主画面。
- 两者同时开启：`[basev] → dedup → border → risk overlay`。

### 8.2 概念过滤图

```text
[basev]split=2[bgsrc][fgsrc];
[bgsrc]gblur=sigma=20:steps=2[bg];
[fgsrc]scale=648:1152[fg];
[bg][fg]overlay=(W-w)/2:(H-h)/2[dedupv];

[border_input]
  fps=30,
  scale=720:1280,
  format=rgba,
  setpts=PTS-STARTPTS[border];

[dedupv][border]
  overlay=x=0:y=0:shortest=1:format=auto:alpha=straight[framedv];

[framedv][risk_overlay]
  overlay=<现有位置和时段表达式>[outv]
```

实际实现不得写死 720×1280 和 30 fps，必须使用 `config.output`。若模糊背景关闭但边框开启，边框必须直接叠加到 `[basev]`；若边框关闭但模糊背景开启，`[dedupv]` 直接进入风险提示语叠加；两者都关闭时，现有 `[basev]` 链路必须原样保留。

### 8.3 输入和循环

- 静态图片：使用 `-loop 1 -i <image>`。
- RLE 视频：使用输入级 `-stream_loop -1 -i <border.mov>`。
- 边框输入不启用 `-hwaccel videotoolbox`；`qtrle` 交给软件解码。
- 通过 `fps=<output fps>` 统一帧率，通过 `setpts=PTS-STARTPTS` 保证每条成片从边框第 0 帧开始。
- 边框与主画面叠加时以主画面为最短输入结束，并继续保留现有输出时长校验。

### 8.4 硬件编解码

高斯模糊、缩放和 Alpha overlay 属于软件滤镜链。主素材仍可以按现有逻辑使用 VideoToolbox 解码，最终仍优先使用 `h264_videotoolbox` 编码。任一硬件路径启动或输出校验失败时，必须继续使用现有 `libx264` 整条重跑回退，不只重跑局部图层。

## 9. 界面设计

### 9.1 简单模式

新增“视觉去重”卡片，不改名现有“组合重复规则”。卡片头部保留“视觉去重”总开关，卡片内的两个子功能必须并列呈现。总开关只控制整体是否生效，不清空或联动修改子功能。简单模式只提供用户可直接理解的业务操作：

- “视觉去重”总开关。
- 功能 1“模糊背景”独立开关；其下提供“效果强度”三个大选项：轻度、标准、强化，默认标准。
- 功能 2“使用透明边框”独立开关。
- 显示全局边框库可用数量，例如“全局边框库：8 个可用”。
- 提供“随机使用”和“固定使用”两个业务选项；固定模式再选择一个缩略项。
- 提供“管理全局边框库”入口，用于统一上传、停用和查看检查结果，不要求每个项目重新上传。
- 只读状态：检查中、可用数量、无兼容边框或全局库不可用。

简单模式不显示百分比滑块、模糊数值、文件路径、编码、Alpha、循环、拉伸和透明度等技术参数。

三个预设映射为稳定的内部数值：

| 简单模式预设 | `foreground.scale` | `background.sigma` | `background.steps` | `background.brightness` |
| --- | ---: | ---: | ---: | ---: |
| 轻度 | `0.94` | `12` | `2` | `0` |
| 标准 | `0.90` | `20` | `2` | `0` |
| 强化 | `0.86` | `28` | `2` | `0` |

开启“使用边框”后没有兼容的全局素材时，卡片立即显示错误，“生成成片”不可提交。关闭边框时仍可以只使用模糊背景和缩小前景；关闭模糊背景时仍可以单独使用透明边框。两个开关互不自动开启、互不自动关闭。

### 9.2 高级模式

高级模式承载所有需要理解视频格式或可能破坏画面的参数：

- 前景精确缩放比例。
- 高斯模糊 `sigma`、`steps` 和背景亮度。
- 边框的 `disabled/optional/required` 模式、随机/固定策略、固定素材、允许素材集合和项目级权重覆盖。
- `exact/stretch` 缩放策略、循环策略、整体透明度和 `straight/premultiplied` Alpha 模式。
- 预检读到的容器、编码、像素格式、Alpha、分辨率、帧率、时长、音轨警告和失败详情。

`premultiplied` 附带“仅在边缘出现黑边时使用”的说明。项目配置不再填写服务器文件路径；上传、删除、默认权重和素材级 Alpha 模式属于全局库管理。大型 RLE MOV 必须使用流式上传、可配置大小上限和原子提交。

### 9.3 字段归属

| 能力 | 简单模式 | 高级模式 |
| --- | --- | --- |
| 开启/关闭模糊背景 | 可编辑 | 可编辑 |
| 轻度/标准/强化效果 | 可编辑 | 显示当前匹配的预设 |
| 前景精确比例 | 不显示 | 可编辑 |
| 模糊和亮度精确数值 | 不显示 | 可编辑 |
| 使用/不使用边框 | 可编辑 | 可编辑完整模式 |
| 随机/固定使用边框 | 可编辑 | 可编辑 |
| 管理全局边框库 | 提供入口 | 提供完整管理和诊断 |
| 项目允许素材与权重覆盖 | 不显示 | 可编辑 |
| 边框是否可用 | 显示简短状态 | 显示完整诊断 |
| 编码、Alpha、尺寸、帧率、时长 | 不显示 | 只读详情 |
| 边框缩放、循环、透明度和 Alpha 模式 | 不显示 | 可编辑 |
| 文件大小上限和原子替换诊断 | 不显示 | 显示 |

### 9.4 模式切换与保存

- 两种模式始终绑定同一份结构化草稿，不分别保存两份配置。
- 简单模式只有在用户主动选择“轻度/标准/强化”时，才改写表中对应的四个预设字段。
- 如果高级模式的数值不匹配任一预设，简单模式显示“自定义（高级设置）”，不自动就近或覆盖。
- 在简单模式切换总开关时，只改写 `visual_dedup.enabled`，必须保留两个子功能的开关、选择策略和全部参数。
- 在简单模式切换模糊背景开关时，只改写 `background.enabled`，必须保留全部效果参数和边框状态。
- 在简单模式关闭边框时，只将边框模式改为 `disabled`，保留选择策略和高级参数；再次开启时设为 `required`。`optional` 是高级语义。
- 切换任一功能不得联动修改另一功能；尤其不得因为 `background.enabled=false` 而隐藏、禁用或跳过边框配置。
- 简单模式普通保存不得重建 `visual_dedup` 对象，不得将未显示的高级字段重置为默认值。

### 9.5 现有前端架构约束

本功能必须在现有前端架构中增量实现，不得为视觉去重另建一套界面或状态架构。

#### 9.5.1 必须复用的现有边界

- 继续使用 `frontend/index.html` + `frontend/styles.css` + `frontend/app.js` 的原生 HTML/CSS/JavaScript 架构。
- 视觉去重配置必须存在现有 `state.configDraft` 中；不创建第二份草稿、独立 store 或全局单例。
- 简单卡片由现有 `renderSimpleConfig()` 渲染，交互在 `bindSimpleConfigControls()` 中绑定，预设选择复用 `simpleChoiceButtons()` 的 `data-simple-choice` 机制。
- 高级字段由现有 `renderVisualConfig()` 渲染，优先复用 `configInput()`、`configSelect()`、`configSwitch()` 和 `data-config-path` 协议，继续由 `collectVisualConfig()` 收集。
- 默认值可以在 `ensureOutputNaming()` 和 `ensureFeishuBaseSync()` 的同层添加 `ensureVisualDedup(config)`，但该函数只能补齐缺失字段，不得覆盖已存在的高级值。
- 简单/高级/YAML 切换继续走 `setConfigMode()`、`currentStructuredDraft()` 和现有保存流程，不单独建立视觉去重保存按钮或配置接口。
- 项目兼容扫描结果仍写入 `state.scan.assets.visual_border` 并由现有 `scanAssets()` 刷新；全局管理列表挂在现有 `state` 对象下，不创建第二套 store。
- 全局边框管理继续使用统一 `api()`、toast 和当前卡片/折叠区组件；库写入使用全局库版本校验，不冒充项目配置写入。
- 继续保留当前的懒渲染行为：打开配置弹窗时只渲染当前模式，不提前构建被隐藏的高级编辑器。
- 样式复用现有 `simple-config-card`、`simple-choice`、`config-section`、`config-field`、`switch-input`、状态提示和移动端断点，不引入第二套配色、栅格或弹窗系统。
- 前端设计必须以当前配置页面为视觉基线做增量扩展，沿用现有字体层级、颜色变量、边框、圆角、阴影、间距、卡片结构、按钮、开关、选项状态、信息提示和响应式行为；新增的两个独立功能应表现为现有卡片内部的同级设置区，不得设计新的视觉语言。

#### 9.5.2 禁止的实现方式

- 不引入 React、Vue、Svelte、TypeScript 迁移、新打包器、新状态库或组件库。
- 不创建独立 SPA、iframe、新路由页面、新配置弹窗或只服务于本功能的前端启动入口。
- 不绕过 `state.configDraft` 直接从 DOM 拼接一份新配置，不在模式切换时用服务器数据重置未保存草稿。
- 不将边框预检复制成纯前端媒体解析器；前端只展示后端统一扫描结果。
- 不为简单模式创建一套与高级模式不同的后端配置模型。
- 不得为视觉去重新增一套配色、图标体系、排版比例、卡片造型、按钮造型、动效语言或交互范式；不得仅为追求“新版效果”重绘现有配置页面。若现有样式无法直接满足，应优先组合或小幅扩展现有组件，并保持其他配置卡片的一致性。

#### 9.5.3 前端回归约束

`tests/frontend_layout_test.js` 必须增加静态架构回归，至少锁定：

1. 视觉去重简单卡片位于 `renderSimpleConfig()`，高级区域位于 `renderVisualConfig()`。
2. 高级字段使用 `data-config-path="visual_dedup..."` 并由 `collectVisualConfig()` 收集。
3. 简单模式保存仍经由 `currentStructuredDraft()` 保留未展示的高级字段。
4. 打开弹窗不同时渲染隐藏编辑器。
5. 页面不出现新的独立视觉去重应用容器、iframe 或额外前端入口。
6. 桌面端和移动端视觉回归必须确认新增设置区与相邻配置卡片的字体、颜色、边框、圆角、间距、控件尺寸和断点行为一致，不出现独立的新风格。

## 10. 异常处理

| 场景 | 处理 |
| --- | --- |
| 总开关关闭 | 两个子功能都不执行，但完整保留其选择和参数 |
| 模糊背景开启、边框关闭 | 只生成模糊背景和缩小前景 |
| 模糊背景关闭、边框开启 | 保持基础画面尺寸和清晰度，只叠加透明边框 |
| 模糊背景和边框都开启 | 按“模糊背景与缩小前景 → 透明边框 → 风险提示语”生成 |
| 模糊背景和边框都关闭 | 不增加视觉去重过滤链 |
| `optional` 且全局库无兼容素材 | 不叠加边框，继续生成 |
| `required` 且全局库无兼容素材 | 预检失败，不静默降级 |
| 固定素材被停用或不兼容 | 预检失败并提示具体素材 |
| 全局库并发写入版本冲突 | 返回冲突并刷新列表，不覆盖其他电脑的修改 |
| MOV 不是 `qtrle` | 首版拒绝并提示重新导出 QuickTime Animation/RLE |
| 素材无 Alpha 或抽样全不透明 | 拒绝，避免覆盖主画面 |
| `exact` 模式尺寸不符 | 拒绝并同时显示素材尺寸和目标尺寸 |
| 边框比成片短 | 从第 0 帧无缝循环，不冻结末帧 |
| 边框有音轨 | 忽略边框音轨并显示警告 |
| Alpha 边缘有黑边 | 提示尝试 `premultiplied`，不自动猜测 |
| 硬件编码失败 | 清理临时文件，使用 `libx264` 整条重跑 |

## 11. 性能与并发

新链路会将同一画面拆分为两路，其中一路执行高斯模糊，并额外解码一路 qtrle。预期 CPU 和内存带宽显著高于现有纯拼接链路。

- 不为视觉去重单独绕过现有任务并发上限。
- 实现后在 Apple Silicon 上用 720×1280/30 fps 的 15 秒、60 秒和 180 秒样本记录实时倍率、峰值内存和多任务稳定性。
- 若并发 2 条已经明显导致系统换页或单条速度大幅下降，应在开启模糊背景或透明动态边框时将推荐并发设为 1，但不静默覆盖用户的显式设置。

## 12. 测试与验收

### 12.1 单元测试

1. 没有视觉去重配置的旧项目加载后总开关和两个子功能都关闭，现有 FFmpeg 过滤图字符不变；已有旧 `enabled` 配置迁移前后输出一致。
2. 字段边界验证覆盖 `scale/sigma/steps/brightness/opacity`。
3. 720×1280 且 `scale=0.90` 得到 648×1152；任意奇数画布亦输出偶数前景尺寸。
4. qtrle+argb 通过；qtrle+rgb24、H.264 MOV、无 Alpha PNG 和 JPG 被拒绝。
5. 边框输入不出现 `-hwaccel videotoolbox`，主视频输入仍保留。
6. 过滤图顺序必须是 `concat → dedup → border → risk overlay`。
7. 关闭边框但开启模糊背景时，只产生背景和前景过滤链。
8. 关闭模糊背景但开启边框时，从 `[basev]` 直接叠加边框，不出现 `split/gblur/foreground scale`。
9. 总开关关闭及总开关开启后的四种子功能组合均有计划器和过滤图断言；切换总开关不得改变子功能配置，切换任一子功能也不得改变另一功能。

### 12.2 集成测试

固定生成三类小素材：带运动图形的主视频、红色四边且中间透明的 qtrle/argb MOV、和一张与红边重叠的绿色风险提示语测试图。

验收：

- 画布保持配置分辨率和帧率。
- 四周可见高斯模糊背景，中间可见清晰的缩小前景。
- 透明中心不出现黑底，红色边框可见。
- 红色边框和绿色风险提示语重叠的像素最终为绿色，证明风险提示语在最上层。
- 使用时长为边框 3 倍以上的主视频，边框动画持续循环而非冻结末帧。
- 输出时长符合现有误差阈值，且音轨只来自主时间线。
- VideoToolbox 成功路径和强制失败后的 `libx264` 回退路径都可产生有效成片。
- 另以“仅边框”组合生成样片，确认主画面不缩小、不模糊且透明边框正常显示。

### 12.3 回归测试

- 总开关关闭或两项子功能都关闭时，现有三段/多段拼接、风险提示语时段、响度均衡、硬件回退、任务取消和清单测试全部通过。
- `--no-audio` 若未来接入 SmartStitch 普通成片，视觉去重链不得隐式创建音轨。
- 多个时间线片段转场处不出现背景和前景错帧。

## 14. 已确认业务规则

全局边框库按下列规则实现：

1. 前景缩放为 90%；若图 1 对应的实际比例不同，可在样片验收时调整。
2. RLE 边框短于成片时从头循环，不冻结尾帧。
3. 边框来自 NAS 共享的全局库，项目默认从全部兼容素材中随机选择，也可固定指定。
4. 边框覆盖全片，不增加自定义时段。
5. 风险提示语继续完全沿用当前配置，且无条件位于最高图层。
6. 模糊背景与透明边框是视觉去重分组下的两个并列功能，可分别开启，也可同时开启；透明边框不依赖模糊背景。
